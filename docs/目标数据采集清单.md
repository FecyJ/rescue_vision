# P0 目标数据采集清单

本清单只负责现场操作与关闭证据；记录 schema 和命令语义以[数据集与评测](数据集与评测.md)为准。必须使用规则允许的实物或尺寸、材质、颜色高度一致的打印件；现有棋盘和蓝色测试块不能代替四类目标数据。

## 采集前准备

- [ ] 绿色 40 mm 普通物资正方体。
- [ ] 黑色 40 mm 核心物资正三棱锥；若最终实物定义更新，以组委会图纸为准。
- [ ] 橘色 80×40×40 mm 伤员长方体。
- [ ] 浅蓝 40 mm 危险目标正方体。
- [ ] 与正式场地接近的底色、安全区材料和常见干扰物。
- [ ] 相机使用 2304×1296、固定焦点；记录实际 `LensPosition`。
- [ ] 每次改变光照、布置或运动方式时创建新的 `recording_id`，禁止把同一连续录像拆到不同数据集集合。

## 建议会话矩阵

每种目标至少覆盖下列独立记录组；多个目标接触和跨类别遮挡必须单独成组：

| 维度 | 建议取值 |
| --- | --- |
| 光照 | 明亮、偏暗、局部阴影、反光 |
| 距离 | 近、中、远及图像边缘 |
| 姿态 | 正立、倾倒、各主要旋转方向 |
| 遮挡 | 无、轻度、明显但仍可辨认 |
| 运动 | 静止、手持慢速横移、快速横移/转动模糊 |
| 接触 | 孤立、同类相邻、跨类别接触、危险目标靠近普通目标 |
| 背景 | 场地材料、边界附近、安全区附近、非目标彩色干扰物 |

优先采集危险目标与蓝色安全区/反光材料同时出现、黑色核心目标处于阴影、橘色伤员发生部分遮挡的困难场景。

## 录制

为每个会话使用一个全新目录：

```bash
rescue-vision-record \
  --config configs/runtime.example.yaml \
  --output recordings/目标类别_场景_时间戳 \
  --duration-seconds 20 \
  --tag lighting=indoor_bright \
  --tag distance=near \
  --tag occlusion=none \
  --tag motion_blur=low \
  --tag background=official_mat \
  --tag target_pose=upright \
  --tag contact_state=isolated
```

录制结束必须检查 `session.json`：

- [ ] `completed` 为 `true`。
- [ ] `written_frames` 大于 0。
- [ ] `dropped_frames` 已记录；若比例明显偏高，降低录制频率或检查存储性能。
- [ ] `config`、`versions`、分辨率和焦点信息正确。
- [ ] 用 `RecordingSource` 抽查首、中、末帧可通过哈希读取。

## 标注与清单

- 保留原始记录目录不变，在外部标注工具中引用图像，不覆盖原图。
- 按 [Pose 视觉模型约定](Pose视觉模型约定.md) 标注四类水平框和单个 K0；当前不标掩码或额外姿态关键点。类别无法确认时不标该实例，K0 无法确认时写 `0 0 0`。
- 数据集 JSONL 必须填写[数据集与评测](数据集与评测.md)规定的七个分层标签。
- 所有来自同一记录目录的样本使用同一个 `recording_id`。
- 用 `rescue-vision-manifest` 从记录目录生成带哈希验证的数据集 JSONL，不手工复制帧路径。
- 运行 `rescue-vision-split` 后检查标签分布；关键困难场景不能只存在于训练集。

## P0 关闭证据

- [ ] 至少四类规则目标均有可回放实拍记录，而不是合成图片或格式示例。
- [ ] 静态与手持运动场景均已覆盖。
- [ ] 清单通过严格 schema 和防泄漏划分工具。
- [ ] 数据版本、存储位置和校验和已记录。

底盘完成后的真实振动、减速带和碰撞数据属于后续补充域，不阻塞当前 P0 实物数据基线关闭。
