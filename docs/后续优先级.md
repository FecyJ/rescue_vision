# 后续优先级

本页只列开放目标。实现状态见项目 [README](../README.md)。排序原则是先做不依赖机械尺寸、最终安装位姿、底盘参数和串口协议的工作。

## P0：补齐现场数据资产

依赖四类目标实物或高一致性打印件和近似场地背景，不依赖底盘。

- [ ] 按[数据采集手册](数据采集工具使用.md#正式采集覆盖)录制绿色普通物资、黑色核心物资、橘色伤员和浅蓝危险目标。
- [ ] 同时覆盖静态、手持运动、阴影、遮挡、接触、蓝色安全区干扰和图像边缘。
- [ ] 生成带哈希的数据清单和按录像整组划分报告，记录数据版本与存储位置。

完成标准：四类目标均有可哈希验证的实拍记录；静态与运动会话可由 `RecordingSource` 回放；清单和划分命令严格通过。合成示例、棋盘图片和单个测试块不能作为关闭证据。

## P1：受监督车载运动采集

依赖现有相机录制链路和可用底盘，不依赖正式目标模型、地面映射、定位、
建图、世界模型或任务规划。协议无关 UART、直接 TCP 远程消息、调试运动/录制
命令、会话/视频/地图/车辆/采集状态 schema 和 schema v7 运行配置已实现，
开放工作按以下顺序推进：

1. 实现 Rescue Car 协议适配器，统一解复用 `OK`、`ERR`、轮速遥测和未知
   前缀；树莓派接收时间与 STM32 控制器时间分别保留。未来 IMU 遥测复用
   同一入口或显式新增消息类型，不修改 UART 传输层。
2. 先与 STM32 冻结失联看门狗、急停锁存/恢复和遥测格式；没有固件侧失联
   停车时，只允许架空轮或有物理急停、人员全程监督的低速测试。
3. 电脑端在独立项目中按[通信协议交接](电脑端通信协议.md)实现 PyQt6
   调试界面和可配置手柄输入，不安装或导入本仓库 Python 包；本仓库只实现
   车端适配。操作者使用死手使能控制前后速度、转向角速度和拍摄；目标朝向
   只有在显式 `field`/`session_start` 参考系及可用 IMU/定位证据下才执行。
   松开使能、手柄断开、远程/UART/相机异常和应用退出必须进入停车流程。
4. 接入有界实时图传、地图和车辆/录制状态观察流；比赛运行配置固定为
   `observe_only`，正式运行不得接受电脑控制。
5. 实现版本化运动脚本：支持限速的静止、直行、原地转向、弧线和制动动作，
   同时记录指令、实测轮速、动作段、停止原因和后续 IMU 数据。
6. 把运动日志及动作计划身份纳入记录 schema、完整性检查和数据版本，不用
   整会话静态标签冒充逐时变化的运动状态。

完成标准：手动与脚本模式复用同一电控协议和安全停车路径；不依赖定位即可
完成短距离受监督采集；断串口、杀进程、相机/写盘失败和接收队列溢出均经
真机验证由固件看门狗停车；图像与轮速/IMU（固件提供后）可按树莓派单调
时间对齐并通过记录完整性检查。

## P2：目标感知基线与 Hailo 适配

依赖：P0 数据和现有感知契约；不依赖底盘通信。

- 训练开发机可复现的四类基线，颜色只作为辅助证据；低置信度由运行时降级为 `unknown`。
- 使用现有 Hailo 后端完成正式单 K0 模型和目标硬件部署验证。
- 单独校准危险类别，支持疑似危险区域膨胀和保守绕行。
- 在静态集、手持运动集和目标硬件上分别评测。

完成标准：报告分类别指标与失败样例，危险类单列；树莓派 + Hailo 持续运行无延迟累积，并报告端到端 P50/P95 观测年龄。

## P3：区域、场界与对手感知

依赖近似场地材料样本，不依赖底盘控制。

- 红/蓝安全区通过 `team_color` 映射己方/对方，区分物资区、伤员区、入口和隔板。
- 输出场界、对方安全区和安全裕量地面多边形。
- 建立不依赖对手固定图案的对手机器人/未知障碍基线。
- 颜色、线段、几何和学习模型保持可替换，围栏只作为低精度观测。

完成标准：红蓝切换只改配置；离线回放报告区域类别、边界误差和保守占据区域。

## P4：定位和规划接口

依赖场地几何；精确运动学和报文编码后置。

- 冻结场地坐标、红蓝方变换和静态地图。
- 从固定场地特征产生视觉位姿观测，并用离线数据评估误差。
- 定义里程计/IMU mock；轮距、噪声和控制周期全部从配置注入。
- 规划器只消费世界模型和可配置机器人足迹，输出抽象速度意图或路径点。

完成标准：合成轨迹可完整运行；替换底盘参数不修改感知、世界模型或规则状态机。

## P5：机械和电控冻结后

- 固定相机高度、俯仰、保护罩和焦点后的内参复核、地面外参和保留点误差验收；
- 真实轮距、轮径、编码器、IMU、速度范围和控制周期下的定位融合；
- 物理链路、报文编码、看门狗、急停和失控保护联调；
- 推送机构、机器人足迹、载荷变化和接触条件下的轨迹验证；
- 减速带、碰撞、翻倒、热降频、供电波动和 3 分钟对抗压力测试。

## 当前推荐顺序

1. 有实物时立即完成 P0 静态与手持运动数据。
2. 在不等待定位的前提下完成 P1 小车协议、安全闭环、手动和脚本采集，补充真实车载运动数据；电控延期时不阻塞 P2 基线训练。
3. 数据到位后做 P2；场地材料到位后并行做 P3。
4. 再做 P4 离线定位和规划接口，并接入现有世界模型与抽象动作。
5. 机械、电控参数冻结后集中完成 P5，补齐接触/交付证据提供者并完成整车规则验收。
