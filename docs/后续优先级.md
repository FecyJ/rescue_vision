# 后续优先级

本页只列开放目标。实现状态见项目 [README](../README.md)。排序原则是先做不依赖机械尺寸、最终安装位姿、底盘参数和串口协议的工作。

正式流程的软件状态机、解团门禁、绿色机会抓取、近场宽度抓取、安全区 d1 视觉纠偏和
末端张爪推送—运输联调入口已经装配；本页继续只列开放的真车门禁、现场数据和验收工作，
不把计划能力写成已完成的比赛能力。

## P0：补齐现场数据资产

依赖四类目标实物或高一致性打印件和近似场地背景，不依赖底盘。

- [ ] 按[数据采集手册](数据采集工具使用.md#正式采集覆盖)录制绿色普通物资、黑色核心物资、橘色伤员和浅蓝危险目标。
- [ ] 同时覆盖静态、手持运动、阴影、遮挡、接触、蓝色安全区干扰和图像边缘。
- [ ] 生成数据清单和按录像整组划分报告，记录存储位置与已知缺口。

完成标准：四类目标均有可回放并目视抽查的实拍记录；静态与运动会话可由
`RecordingSource` 回放；清单和划分命令通过。合成示例、棋盘图片和单个
测试块不能作为关闭证据。

## P1：受监督手动车载运动采集

依赖现有相机录制链路和可用底盘，不依赖正式目标模型、地面映射、定位、
建图、世界模型或任务规划。协议无关 UART、直接 TCP 远程消息、调试运动/
夹爪/录制命令、STM32 二进制协议树莓派端、差速运动函数、远程调试执行、会话/视频/
地图/车辆/采集状态契约、持续扳机双舵机夹爪控制和带机械端点的运行配置
已实现；ROI HSV、目标地面几何也已接入同一运行配置，
v3 六类推理与视觉定位链路已接入，正式模型资产、实测地标和远场标定尚未完成。当前状态与开放工作：

1. [ ] 树莓派端已按[树莓派与单片机通信协议 v3](树莓派与单片机通信协议v3.md)
   实现 COBS、CRC16、固定布局、统一命令序号、回复、状态健康位、序号安全同步
   及编码器/IMU 遥测并删除旧文本兼容；融合入口也已实现温度零偏、三轴
   比例/交叉轴和安装旋转校正。仍需完成 STM32/树莓派真机联调、IMU 参数标定、
   失联看门狗、急停锁存和真实传感器输出验收。没有固件侧失联停车时，只允许架空轮或
   有物理急停、人员全程监督的低速测试。
2. [ ] 电脑端在独立项目中按[通信协议交接](电脑端通信协议.md)实现 PyQt6
   调试界面、可配置手柄输入和持续夹爪扳机控制，不安装或导入本仓库 Python
   包；左扳机映射张开按压状态、右扳机映射闭合按压状态，并在按住期间持续刷新
   `DebugGripperCommand`；本仓库只实现
   车端适配。操作者使用切换式死手使能控制前后速度和转向角速度；拍摄使用
   独立采集命令。目标朝向只有在显式 `field`/`session_start` 参考系及可用
   IMU/定位证据下才执行。
   切换为 OFF、手柄断开、远程/UART/相机异常和应用退出必须进入停车流程，
   并禁止在恢复或重连后自动恢复使能。
3. [x] 本仓库提供 `rescue-vision-manual-capture`，把
   `motion.run_remote_motion()` 装配到同一车端会话，并接入有界实时图传、
   车辆/录制状态、独立采集命令和统一 recording 格式。手动记录额外
   保存运动命令、编码器/IMU、系统状态、命令回复和停车原因，并使用与图像一致的树莓派单调
   时间。录像队列溢出、
   写盘、相机、远程、UART 或非法控制异常均退出统一停车路径。该入口只允许
   `debug_control`，不会被比赛 `observe_only` 配置启用；没有可验证固件
   看门狗时还必须显式确认物理急停和全程监督，并通过车辆状态发布
   `supervised_physical_stop`，不伪装为固件保护。
4. [ ] 在新协议和固件看门狗完成后真机验收断串口、杀进程、相机/写盘失败、
   损坏帧和接收队列溢出；按 STM32 采样时间及树莓派接收单调时间核对图像与
   编码器/IMU 对齐。

手动模式的软件完成标准：不依赖定位即可接收切换式死手的限速 twist，并用
独立命令开始/停止车载记录；OFF、过期、断线、故障和应用退出均复用
`RemoteMotionExecutor` 停车路径；重连不会自动恢复使能。以上已有无硬件
pytest，固件级失控保护和真车停车证据仍以第 1、4 项为门禁。

## P2：目标感知基线与 Hailo 适配

依赖：P0 数据和现有感知契约；不依赖底盘通信。

- 训练开发机可复现的四类 Pose 基线，由模型提供检测框与 K0；运行时模型标签是任务类别权威，ROI HSV 只提供对应类别的几何掩码。颜色覆盖不足或歧义时保留 `candidate_class=null` 与质量诊断，不制造运行时任务 `unknown`。
- 使用四类现场实物和实际相机参数校准 HSV 范围、覆盖率、dominance 与去噪参数；命题示意图启动值不能作为完成证据。
- 使用现有 Hailo 后端完成正式六类 `[3,3]` 模型和目标硬件部署验证。
- [x] 已实现基于 ROI 颜色掩码、K0 和完整相机外参的传统视觉地面几何估计：
  40 mm 方块、80×40×40 mm 长方体和正三角形面接地的正四面体均使用配置化
  尺寸，输出可选机器人系中心、足迹、对称朝向、拟合分数和不确定度。
- [ ] 使用四类实物标注地面中心和足迹，按距离、视角、阴影与遮挡校准拟合
  门限并报告分类别毫米误差；合成投影测试不能关闭此项。
- 单独校准危险类别，支持疑似危险区域膨胀和保守绕行。
- 在静态集、手持运动集和目标硬件上分别评测。

完成标准：报告分类别指标与失败样例，危险类单列；树莓派 + Hailo 持续运行无延迟累积，并报告端到端 P50/P95 观测年龄。

## 当前推荐顺序

1. 有实物时立即完成 P0 静态与手持运动数据。
2. 在不等待定位的前提下完成 P1 固件安全闭环、电脑端手柄和手动采集真机验收，补充真实车载运动数据；电控延期时不阻塞 P2 基线训练。
3. 数据到位后做 P2；场地材料到位后并行做 P3。
4. 再做 P4 离线定位和规划接口，并接入现有世界模型与抽象动作。
5. 机械、电控参数冻结后完成 P5，其中再实现脚本运动采集；把正式流程的几何门禁和
   d1 视觉证据替换或融合为真实接触/交付传感器证据，并完成整车规则验收。
