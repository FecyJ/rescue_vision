# 正式流程设计

`rescue-vision-match` 是当前唯一的正式比赛流程，领域实现位于
`src/rescue_vision/app/match.py`，硬件生命周期位于
`src/rescue_vision/app/match_runtime.py`。未来正式流程的改进都直接基于
`MatchSequence`；仓库不再维护另一套 15 分或 20 分应用编排。

## 抓取任务与动作顺序

`MatchSequence.grasp_task` 持有一次物理抓取意图，涵盖搜索接管、对准接近、停稳规划、
解团恢复及再抓取。它保存入口类别/位置、动作核心、恢复次数、场景修订、失败归属和总截止时间。
局部 tracker ID 和 `near_field_session_id` 是关联线索与场景版本，不是新物理任务。
成功抓取并交接运输，或明确记录失败并退出目标，才结束任务。任务总预算由
`match.grasp_task_timeout_ms` 配置（默认 20000 ms），跨转向、停稳和解团不重置；已经冻结的
前推/退离/合爪先完成其受控退出，不因总预算到期停在接触区。

搜索优先尝试合法近场目标，其次按规则分值与距离选择远场入口；单绿或单橙不需要先成团。
启动动作结束即进入该正常流程，首趟存在可执行单绿方案时直接夹取，解团不是开场必经步骤。
正式 `match` 的启动动作来自 `match.opening_actions`，按配置顺序执行 `turn` / `straight`，
每项独立给出角度/距离、速度和可选停稳切换时间；它与 `match_nb` 的
`nb_opening_actions` 不共享动作列表或开场状态机。
黑、绿、橙候选统一检查目标 K0 周围 10 mm 内是否有其它已定位物块；不再用夹爪实体外接半径
或更大扫掠邻域扩大这条独立性门禁。路径仍独立检查前进走廊、场界和双方安全区，不能因为邻物
距离超过 10 mm 就放行一条不安全路径。10 mm 内的目标记录 `target_not_isolated:<id>:<class>`。
没有当前橙色证据时直接按黑绿候选继续；后续新帧再次看到橙色时恢复橙色优先，非独立橙色进入
短距离橙色瞄准轻撞解团。首趟完成后关闭单绿专用策略，后续补夹和解团参数保持原样。
日志证据及验证边界见[开局单绿净空诊断](match开局单绿净空诊断.md)。
接近使用现有主 tracker 与采集位姿历史，物理位置唯一可关联时允许换号而保持任务。
短时漏检保留任务并有界重新观察；关键几何仍不可用时记录失败后换目标或执行已检查的换位。
机器人原地转向、局部重新编号和重新开启场景不会解除物理失败记录。

### 稳定场景的一次决策

生产入口持续注入真实 `OdometryImu`，`motion/stationary.py` 是唯一静止证据权威。
两轮计数连续不变、设备采样递增、IMU有效且角速度低于进入阈值，才积累稳定场景请求；
退出静止使用更宽角速度阈值，并要求编码器/角速度运动连续达到确认时长，吸收单次量化抖动。
pending 期间不提交图像，但不改写此前的静止起点；数据无效、重复/倒退样本和遥测断档仍立即失效。
固定 settle 到期或零速命令不能代替静止。跨阶段始终静止时复用已有静止起点；
真实转向、前推或退离后重新取得相应的新稳定场景。

`GraspPreparationSession` 在同一个场景中完成跟踪关联、包络、选组、机械角度及危险扫掠。
首次合法选组即持有动作核心并累计当前帧，不等消费者返回锁组再追要第二张图。
`confirmation_frames=1` 可由一张可靠静止帧完成；多帧只累计不同有效采集，外围排名变化不重选核心。
同一停车视野中新出现且与已有目标 bbox IoU 不超过配置阈值的检测，首帧即冻结为独立目标，
不等待 tracker 二次确认；高重叠检测不按该规则提升。
确认过的核心遇到漏检可保留计数，但缺少当前几何时不能提交缓存动作。

`GraspPreparation.action` 明确表达下一步：

| 结果 | 任务动作 |
| --- | --- |
| `grasp` | 当前朝向可执行，静态场界与安全区检查通过后冻结开爪、编码器定距、合爪 |
| `motion` | 冻结最小必要转角，按 IMU 进度执行，停稳后复核同一核心 |
| `recovery` | 抓取存在具体阻挡，同一后台请求产生独立验证的解团计划 |
| `observe` | 缺少可补充证据，保持当前任务并进行短时重观测 |
| `exit` | 当前场景已证明没有安全抓取或恢复方案，记录失败后换目标或换位 |

当前朝向机械可达时不要求包络中心进入 ±5 mm。绿黑组合按 K0 扫掠、实际开度和剩余容量选择；
已存在合法方案时不再为了未确认同伴等待。低重叠新目标由上述停车视野规则直接冻结并参加当前选组。
首趟只允许单绿；伤员始终单独转运；一般物资最多三个。已交付与已携带观测只失去候选资格，
仍保留为障碍、危险和推移净空证据。HSV 不改变模型任务类别，颜色不足或歧义不产生质量门禁；
掩码不可用时横向包络使用 bbox 底边。四类目标缺失模型 K0 时使用 bbox 底边中点地面锚点。

近场交接使用当前 K0 距离，远场目标先通过路径检查继续接近，不能直接停车等近场计划。
局部任务退出记录失败后，优先检查当前视野中的合法替代目标，再决定扫描或换位。
普通 `match` 不会因看见蓝色危险目标而转入蓝色重观测或接近；蓝色只作为危险和路径障碍参与检查。
显式蓝色优先策略仍由独立的 `match_strategy` 入口运行。

转向完成时间只记录一次。异步规划尚未返回时，已有 IMU 航向继续用于冻结转角进度，
不因缺图退回定时器。开爪提交时冻结前进航向，编码器控制行程、IMU 纠正启动偏转；
减速时同比减小纠偏。前进日志为 `forward_encoder_heading_hold`，不重新瞄准新图中的目标。

### 解团恢复与重新抓取

正式近场受阻由 `GraspPreparationSession` 在同一场景中调用 `breakup_planner.py`，
共享采集位姿、物理尺寸和候选排除索引。`BreakupSceneContext` 只传不可变的场地/位姿/任务输入；
规划器不切换状态，不打开相机，不修改任务。恢复必须服务于入口目标或其物理邻域，
不能仅因别处看见一个团而推移。缺少危险 K0 或可靠接触几何时不盲推。

解团使用实际 K0、夹爪前伸及物块实体，独立检查完整路径、场界、双方安全区与推移净空。
解团计划发布后不再用后续整幅画面的目标数量、类别和 10 mm 位置匹配做二次一致性复核；
执行仍受计划年龄、连续静止证据、控制状态和冻结计划自身的安全检查约束。
`breakup_confirmation_frames` 管理同一物理接触核心的不同帧确认。需要转向时先冻结实际转角，
按 IMU 执行；近场已经确认过「抓不了、必须推开」的接触计划不因这次对准失效，对准到位即冻结
计划并前推，不再回到近场重新观察——否则会在「近场判定必须解团 → 对准 → 弃团 → 近场再判定
必须解团」之间死循环，且每次循环都把车转离已对准的朝向并丢掉交接目标。
确认完成前先把团内绿/黑/橙得分物块保存为 `GraspTask.marked_targets`，没有得分目标时不提交恢复。
随后对准接触射线，全程闭爪按 `breakup_forward_distance_m` 前进，真实停稳后保持闭爪
按 `breakup_backward_distance_m` 后退，再次停稳。正式配置分别为 0.4 m 和 0.10 m。
两个行程都按编码器定距，1 mm 行程容差；
刹车余量只用于扫掠外扩，不能从后退行程扣除。整段定距路径不安全即淘汰，不缩短成另一种动作。
旧 `breakup_penetration_mm` / `breakup_retry_penetration_mm` 配置已移除，外部配置需删除这两个键。

每段第一次达到终点即锁存制动阶段及开始时间，反弹、回滚或外力导致里程回落不会重新前进/后退。
运行时按连续制动意图去重 `SOFT_BRAKE`，不按状态名称或动态诊断字符串去重；等待期间继续
处理 UART 应答和 `MotionController.update()` 的零轮速心跳。`commanded_wheel_speeds=(0,0)`
只代表上位机指令缓存，实际静止仍由编码器/IMU确认。停稳预算冻结为本段最大速度除以
有效减速度，加轮速停稳确认时间、两倍遥测最大间隔；不是新的感知等待窗口。
到期仍未确认控制状态时继续保持软制动并报告 `breakup_stop_unconfirmed`，禁止在持续运动或
控制状态不可用时倒车或重新搜索；它不再进入永久停车态。有效编码器/IMU重新给出连续静止
证据后，原状态机自动继续后退或完成退离，无需重启流程。诊断包含该段的
`segment_stop_started_ns` 和 `segment_stop_deadline_ns`。

正式流程中的普通动作超时不再升级为 `terminal_stop`。点到点运输从当前绝对位姿重建动作；
非接触动作不再执行目标、场界或安全区的通用扫掠碰撞门禁，D1、D2、重定位、转向和显式倒车
直接采用运动控制器输出。近场编码器方向不符、无进展或本次里程计不可用时退出本次抓取并
重选。赛前检查失败、明确急停、事故、失控等直接安全终止仍锁存停车，完成规定运输次数仍
进入正常 `finish_stop`。抓取候选、解团动作等各自的实体扫掠规则不受此项修改影响。

对准、前推和后退期间持续用采集时刻位姿把新观测转为 `FieldPoint`，按类别与物理位置一对一
关联标记。允许沿已测得的前推位移关联滑动物块；不把预测推移写成实测位置。短暂漏检保留
最后实测坐标与原采集时间，同类关联有歧义时不冒认，新 ID 不清空标记；同帧已关联目标继续高亮。
退离后使受推移影响的旧抓取几何失效，增加场景修订，保持标记、任务身份与总截止时间。
取得退离停稳后标记目标的新观测，以 `breakup_complete_replan_grasp_task` 和明确的
`NearFieldHandoffPrior` 接回对准/稳定抓取规划，计划必须包含交接目标；首趟仍只选单绿。
新几何不可用时只等约两帧加正常处理延迟，窗口在首次等待时冻结；若已锁定目标但只是停稳证据
超时，先原地重观测一次，不写物理失败记忆；再次失败才记录并重选。
没有默认整圈扫描，也不以旧标记直接开爪。
恢复次数累计受 `breakup_max_attempts` 限制；后续恢复仍需独立验证不同的可行推移，
无安全恢复、无有效改善或预算耗尽时必须带物理失败证据退出，不能新建 session 重试相同动作。

### 延迟、预算和旁路

运行时使用 `latest_snapshot()` 保留真实感知结果，任务自行区分流的新鲜度和静止场景有效性。
采集时间、感知发布时间、准备发布时间与遥测时间独立保存。静止计划采集年龄可超过通用
800 ms 流门限，但必须在连续静止区间内，受近场总提交预算限制，且结果发布后失联年龄仍
受通用观测上限约束。新场景出现核心缺失或危险侵入时，迟到计划不能覆盖新风险。
异步结果返回即可被消费，不要求同周期再到一张图，也不改写旧结果采集时间。

`no_plan_wait_ms` 用于真实停稳后的无计划短观察；有连续帧时依据实测帧间隔与感知发布时间
冻结约两帧加处理延迟的观察窗口，并为提交截止时间保留遥测周期余量，不逐轮扩大窗口。
已提交且仍在计算的场景请求可在独立的
`alignment_timeout_ms` 提交窗口内完成。任务总截止时间约束所有子阶段。
窗口不会因重复帧、状态跳转或结果迟到重新计时。失败在释放局部计划前一次记录入口、实际核心、
位姿、原因与下一步；预览方案不能替换失败归属。

无计划短窗口只覆盖「完全没有方案」。会话一旦定下路由或锁定成员即进入提交阶段，改用
`alignment_timeout_ms` 提交窗口，否则一次瞬时丢帧就会在提交前把整个会话判死；对准转向期间
不判定该超时，转向有自己的预算，不能算成「没有方案」。提交超时的原因若表示本次没有发出过
任何运动指令，同一片区域只允许一次原地重观测：保留交接目标与抓取任务、只更换会话号、不写
物理失败记忆，因此不需要靠整圈扫描加换位解锁同一目标；第二次仍失败才按普通失败退出并记录。

`GraspPreparationWorker` 使用一个待处理槽和一个最新结果槽，串行计算、按场景会话隔离结果；
取消任务不等待旧计算完成。正式受阻场景的组合、机械角搜索和解团边界搜索在后台完成。
诊断使用独立有界槽，结果先发布；运动命令先于预览叠加和日志下发。旁路异常报告并隔离，
不单独导致控制循环停车。Python 线程仍共享 GIL，是否需要进程隔离由目标设备时延实测决定，
不能以后台线程或 pytest 通过宣称满足 5–10 ms 真机控制周期。

日志包含 `grasp_task`、阶段、入口位置、核心、恢复次数、场景修订、阻挡、最近进展、
任务/阶段截止时间、确认进度、采集/准备年龄和 `stationary_reason`。
静止失效区分编码器运动、旋转、传感器无效、设备重复/倒退、采样断档和遥测过期。
远场入口另有 `approach_seed`，逐个列出新鲜目标被淘汰的第一个门禁（`stale`、
`attempt_blocked`、`class_not_in_policy`、`behind_robot`、`path_blocked`、`side_neighbor`、
`corridor_blocked` 等）或 `accepted`；它与 `_find_approach_seed` 共用同一判据，用于区分
「没看见」与「看见了但被否决」——在它之前，远场入口没有等价于近场 `grasp_candidate` 的淘汰日志。

### 补夹和运输边界

完成一般物资抓取后，允许补夹时创建下一抓取任务；本趟已携带类别、剩余容量、
原扫描预算和未解除的物理失败记录继续保留。补夹候选为全场绿黑，近场半径只控制接近交接，
不截断发现范围；候选保持到明确失败或失观。成功补夹后累计成员并交接运输。
每个完成的夹取会话只累计一次计划成员，控制循环重复读结果不重复加数；2 个后最多补 1 个，
3 个直接运输。首次只允许单绿，单橙不补夹。`carried_target_count` 在交付退出或误夹开爪释放后清零。
带载状态不提供解团恢复能力；无直接抓取方案则在剩余扫描预算内换目标，耗尽后返程。
首趟、单橙、CC 与单绿运输联调保持各自禁用能力。

安全区运输仍由比赛层管理：绿黑使用 `safe_zone_fallback_target_field_mm`，单橙使用
`safe_zone_injured_target_field_mm`，后续 d1 纠偏、d2 与交付路线不归抓取规划器管理。
`capture_confirmed=False` 仍表示仅完成软件动作，不能作为现场抓获或有效交付证据。

到达 D1 且两帧安全区关键点视觉校准成功、D2 直线尚未启动时，已启用的 `gate_clearance`
按己方两个安全区门前当前 K0 场地证据截获运输：物资区前的橙色、伤员区前的绿/黑以及任一区
前的蓝色触发路线。校准失败或 D2 已开始后不触发。触发条带以静态地图安全区前沿为基准：
`front_edge_inset_mm` 将基准线向场地中心移动，`front_depth_mm` 控制纵深，
`lateral_inset_mm` 同时内缩左右边界。

触发后先等待编码器/IMU证明真实停稳。红方绿/黑前往 `(-450, 1022.5) mm`，橙色前往
`(450, 1022.5) mm`；蓝方绕场地原点中心对称。绿/黑转到绝对航向 `0°`，橙色转到 `180°`，
闭爪前进 900 mm、倒退 600 mm，再转到己方安全区方向（红方 `90°`，蓝方 `-90°`）。
随后交给正式 D2 投递状态机张爪、对准并闭爪，以 D2→安全区末段对应的类别速度推进 200 mm；
推入完成后张爪并复用正常 `safe_zone_exit_distance_m` / `return_backup_speed_m_s` 倒车与停稳
状态机，完成并累计一次运输。
横移期间持续检查新鲜危险目标，并在移交正式 D2 投递前检查 200 mm 推入线段；推移实体包络
可能进入任一安全区或场界外时，放弃该路线，保持载荷并从当前位置恢复普通安全区运输。
`attempt_timeout_s` 从首次触发起限制门前横移，
至 600 mm 倒车结束并移交正式 D2 投递；后续推入和退出沿用正式状态机。
动作诊断包含采集时间、触发类别、目标点、航向和截止时间。该路线已接入配置，但尚未真机验收。

### 抓取提交与证据失败（1932 回归）

已提交 `active_plan` 后，选组/恢复准备结果不再接管执行；迟到的 RECOVERY/EXIT、

## 运行配置与入口

正式流程配置为 `configs/runtime.match.yaml`，配置节为 `match`。车端入口需要物理
急停和全程监督确认：

```bash
rescue-vision-match \
  --config configs/runtime.match.yaml \
  --start-area 2 \
  --supervised-physical-stop-ready \
  --local-preview \
  --log-dir logs
```

正式流程以区域 2 的运行配置为基准。`--start-area 2`（默认值）表示地图右上角、
己方为红方；`--start-area 3` 表示地图左下角、己方为蓝方。选择 3 时，初始
`FieldPose2D`、物资区/伤员区运输终点和带符号的场地刹车过冲均相对中心十字
`(0,0)` 做 180° 中心对称；固定物理静态地图不复制或翻转。

开场变体 `rescue-vision-match-nb` 使用 `configs/runtime.match_nb.yaml`，直接继承当前正式
流程，只把开场换成从当前起点执行 `match.nb_opening_actions`：每项是一个相对 `turn`
或 `straight` 动作，分别配置角度/距离和该动作速度。当前配置恢复为历史的
`turn → straight → turn → straight → reverse`；普通 `turn` 使用 IMU 相对航向进度；
可选 `wheel_turn` 使用左右轮累计编码器里程差除以轮距计算角度，直行使用编码器累计路程；
转向未完成时不允许线速度，动作之间只保留配置的短暂停稳，不做
场地点重算或额外横向校准。最后一个动作完成后清理 NB 控制器并直接进入
正式流程的 `SEARCH_CLUSTER` 入口；后续解团、抓取、运输和返回不再走 NB 分支。
`nb_opening_turn_tolerance_rad`、`nb_opening_heading_tolerance_rad` 和
`nb_opening_distance_tolerance_m` 只作用于开场，正式流程分别使用
`cluster_align_tolerance_rad`、`noncontact_heading_tolerance_rad` 等字段。
字段含义和 `nb_opening=action=...` 诊断行以
[app README](../src/rescue_vision/app/README.md) 为权威，真机核对项见
[manual_tests/README.md](../manual_tests/README.md)：

```bash
rescue-vision-match-nb \
  --config configs/runtime.match_nb.yaml \
  --supervised-physical-stop-ready \
  --log-dir logs
```

该变体只支持启动区域 2；动作序列相对于实际起点和起始航向执行，不做区域 3 中心对称。

蓝色优先策略变体 `python -m rescue_vision.app.match_strategy` 使用
`configs/runtime.strategy.yaml`。它在策略阶段（`_strategy_formal_phase is False`）
只搜蓝色危险物块：开场两段反向冲刺后，能直接夹取单个蓝块则单块转运，否则对全蓝目标团
执行动态解团；`required_transports: 2`，两趟分别在对面安全区左右 D2 点释放，终点不
推进到安全区深处（`safe_zone_d2_to_final_braking_overrun_mm` / `..._x_mm` 均为 0）。
第二趟返回结束后翻转入正式阶段，恢复己方 y 方向的端点与首轮单绿机会，其后完全复用
正式绿块流程。该变体是 `app/match.py` 的子类，正式阶段显式委托回基类；策略阶段的
失败记忆、旋转预算与安全区排除沿用的是同一套 2047 语义，不再保留按区域的旧实现。
入口、诊断和继承边界以 [app README](../src/rescue_vision/app/README.md) 为权威：

```bash
python -m rescue_vision.app.match_strategy \
  --config configs/runtime.strategy.yaml \
  [--start-area 3] \
  --supervised-physical-stop-ready \
  --log-dir logs
```

`--start-area 3` 同样做中心对称并切换到蓝方。策略阶段只处理蓝色危险物块：走廊被
绿/黑/橙目标占住时不会改抓这些类别，而是继续搜索。

夹取—运输联调入口复用同一配置，从 `FieldPoint(0,0)`、场地航向 `+90°` 直接搜索
绿色单物块，不进入解团。当前联调实现沿用正式流程的夹取和运输，仅在安全区末端不再
重复闭合夹爪，保持张开推入物块并保持张开退出：

```bash
rescue-vision-grab-transport \
  --config configs/runtime.match.yaml \
  --supervised-physical-stop-ready \
  --local-preview \
  --log-dir logs
```

两个入口都会在正常退出、信号、相机、通信或控制异常时进入统一停车和资源清理路径。
观察图传和地图发布是旁路，不参与运动决策。

## 明确未接入的能力

`app/scan_target_memory.py` 和 `app/field_target_cluster.py` 保留为可复用的纯逻辑模块，
并由独立测试覆盖；它们当前不属于正式流程的控制链。正式流程暂不使用跨帧视野外目标
记忆、记忆目标接管或 20 分流程的视觉纠偏设计。正式 match 已接入有限的采集时刻编码器/IMU
位姿历史，用于把选中目标转换到当前机器人坐标；它不等同于跨帧目标记忆。

## 验收边界

当前自动测试覆盖状态转移、解团/近场抓取门禁、近场会话隔离、d1 视觉纠偏、d2 和末段
航位积分、联调入口不解团、配置校验、日志/预览旁路及异常停车。正式比赛使用前仍需
完成正式 v3 模型、现场安全区地标、远场地面标定、底盘参数、固件看门狗、接触/交付
证据和真车压力测试；真机控制响应时间、夹持成功率、解团效果、危险类表现和目标硬件
端到端时延均未验证。

搜索入口先通过采集位姿历史把 K0 补偿到当前机器人系，再检查场界与接近路径、比较距离；原始采集时间不变。
`RELOCATE_FORWARD` 中发现合法候选即交给正常对准/接近链。一般阶段锁组前，未确认绿黑成员能否共同收拢
按当前朝向的实际开度、行程、容量与危险目标 K0 扫掠判断；不可行增组不能扣住合法单块。
