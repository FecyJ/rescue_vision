# 正式流程设计

`rescue-vision-match` 是当前唯一的正式比赛流程，领域实现位于
`src/rescue_vision/app/match.py`，硬件生命周期位于
`src/rescue_vision/app/match_runtime.py`。未来正式流程的改进都直接基于
`MatchSequence`；仓库不再维护另一套 15 分或 20 分应用编排。

## 动作顺序

流程使用机器人相对 `GroundPoint`、陀螺仪累计航向和编码器累计路程完成启动、目标团搜索、
解团和绿色物资运输。搜索阶段允许配置开启的单个绿色物资机会抓取；机会目标必须通过
新鲜度、单物块净空、前进走廊和安全区路径门禁。否则选择完整目标团，优先包含绿色普通
物资的团，再按成员数排序；候选失败时保留完整目标团并继续寻找下一候选。

绿色目标先停车采集不同感知帧并取平均。远目标先接近到配置的二次对准距离，再停车
重新对准；最终按 `green_grab_offset_mm` 编码器定距接近。到达该偏移后保持局部张爪
并停车复核 `green_preclose_recheck_hold_ms`，以车体原点为中心，在
`green_preclose_recheck_range_mm` 范围内寻找新鲜、已确认且可重新对准的绿色物块，
不要求候选位于车前；复核本身不原地转向搜索，只使用当前视野。候选仍必须通过按当前
观测计算的接近走廊和双方安全区路径门禁；若发现候选，就切回绿色对准并再次定距接近，
不闭合夹爪。重复动作直到没有候选，或达到
`green_preclose_max_carried_blocks`，然后才闭爪进入运输。停车复核窗口让刚从当前
物块旁露出的目标有时间完成 tracker 确认，避免只在一个控制周期内检查而漏触发。
动作切换按 `action_settle_time_s` 保持零速，并由陀螺仪保持直线航向。

## 安全区视觉纠偏

夹取后沿补偿后的场地直线到达 d1。d1 停稳后只消费新鲜安全区 K0/K1/K2 观测，收集
配置数量的样本并取均值；安全区角点定位器结合红/蓝静态地标和完整地面外参拟合车辆
`FieldPose2D`，成功后直接覆盖当前受限航位。拟合失败会清空样本、重新寻找关键点并
保持零速等待新的完整观测。

校正后的位姿作为 d1→d2 和 d2→安全区末段的起点。两段继续使用编码器定距和陀螺仪
航向保持，不使用固定终点位姿；每一段都应用配置的刹车过冲补偿。推进完成后停稳、
张爪释放，再沿退出距离倒车并转向，等待新鲜帧后重新进入搜索。

## 运行配置与入口

正式流程配置为 `configs/runtime.match.yaml`，配置节为 `match`。车端入口需要物理
急停和全程监督确认：

```bash
rescue-vision-match \
  --config configs/runtime.match.yaml \
  --supervised-physical-stop-ready \
  --local-preview \
  --log-dir logs
```

夹取—运输联调入口复用同一配置，从 `FieldPoint(0,0)`、场地航向 `+90°` 直接搜索
绿色单物块，不进入解团：

```bash
rescue-vision-grab-transport \
  --config configs/runtime.match.yaml \
  --supervised-physical-stop-ready \
  --local-preview \
  --log-dir logs
```

两个入口都会在正常退出、信号、相机、通信或控制异常时进入统一停车和资源清理路径。
观察图传和地图发布是旁路，不参与运动决策。

## 明确未接入的能力

`app/scan_target_memory.py` 和 `app/field_target_cluster.py` 保留为可复用的纯逻辑模块，
并由独立测试覆盖；它们当前不属于正式流程的控制链。正式流程暂不使用跨帧视野外目标
记忆、采集时刻位姿对齐、记忆目标接管或 20 分流程的视觉纠偏设计。

## 验收边界

当前自动测试覆盖状态转移、解团/抓取门禁、d1 视觉纠偏、d2 和末段航位积分、联调入口
不解团、配置校验、日志/预览旁路及异常停车。正式比赛使用前仍需完成正式 v3 模型、
现场安全区地标、远场地面标定、底盘参数、固件看门狗、接触/交付证据和真车压力测试。
