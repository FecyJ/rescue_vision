# 正式流程设计

`rescue-vision-match` 是当前唯一的正式比赛流程，领域实现位于
`src/rescue_vision/app/match.py`，硬件生命周期位于
`src/rescue_vision/app/match_runtime.py`。未来正式流程的改进都直接基于
`MatchSequence`；仓库不再维护另一套 15 分或 20 分应用编排。

## 动作顺序

流程使用机器人相对 `GroundPoint`、陀螺仪累计航向和编码器累计路程完成启动、目标团搜索、
解团和绿色物资运输。搜索阶段允许配置开启机会抓取：仍以固定
`motion.gripper.transport_*` 包络评估前向扫掠走廊，但正式近场流程在远场对准/接近期间保持
`CLOSED`。首轮按距离优先尝试单个绿色 K0；一般阶段
接受绿/黑物资组或单个橙色伤员快速入口。一般阶段统一比较固定走廊内外候选：
先选近场范围内目标，同层按配置类别分值降序、距离升序选择；最终物资组合仍由近场
选择器确定。搜索种子和近场候选共用目标方向的路径检查，不先锁定一条已知会被蓝块
阻挡的路线。局部解团单独在真实停稳后使用当前帧寻找一个可靠接触核心，完成安全检查，
再用配置数量的连续有效帧确认并冻结计划，不接入近场抓取准备器。
橙色附近默认执行配置隔离半径，禁止伤员混运；普通物资的侧后方例外必须由近场完整
包络证明不侵入夹爪扫掠且与橙块有配置净空。蓝色危险与缺几何目标不使用例外，缺包络时仍拒绝。
其它目标缺少 K0 时不无条件推定其位于禁区。固定走廊未覆盖到的合法目标会在解团前先生成近场
停车路由窗口统一评估近场组、远距重接近和解团；橙色只形成单目标候选，绿/黑只彼此组合。
近场交接把远场已对准目标唯一关联到最近的局部目标：首轮单绿优先规划该物块，但它当前帧
无法生成合法计划（失去颜色包络、越过近场半径或被走廊硬门禁阻挡）时由下一个合法绿色接管，
交接只是排序偏好而不是独占锁；一般阶段先按
规则总分和单橙优先级排序，再在同一规则层内优先选择包含该物块的合法组合；同为 15 分时单橙严格优先于三绿或一绿一黑。
停车后只开启一个有界确认窗口，动作核心按物理成员固定；tracker ID 短暂变化时由 K0 连续性
别名保持锁定，后续有效帧只更新同一物理成员的几何。
一般阶段在锁组前等待并排相邻绿/黑物资完成局部轨迹确认，避免交接种子先获得确认而
过早锁成单件；等待沿用当前尝试预算。场界或安全区造成的静态路径拒绝返回路线重选，
不会作为目标团阻挡触发解团，搜索入口同步检查近场静态边界。
机会检查仍保留安全区、
场界、缺几何地面点和危险目标的保守门禁。

侧邻门禁只约束单橙计划：在预测抓取方向的 `x′/y′` 轴上，只有邻居与计划成员的纵向中心差
不超过 `near_field_grasp.side_neighbor_longitudinal_margin_mm`、横向中心差
不超过 `near_field_grasp.side_neighbor_lateral_margin_mm`，且横向确实存在分离时，才判为侧邻；
明显前后错开的目标（例如伤员在前、蓝块在后）不触发。绿/黑候选不因蓝色或橙色侧邻被直接
淘汰：蓝块只按实际扫掠走廊判定——K0 加内切半径是否进入夹爪开口将要扫过的矩形，
确认窗口没有其它安全方案时才进入解团。单橙色仍由
`orange_isolation_radius_mm` 执行独立性门禁。单纯绿黑分布密集时，
仍允许最多三个绿黑成员的多目标抓取；橙色始终只形成一个成员的独立候选。

远目标先接近到 `near_field_grasp.max_range_mm`（当前 match 为 450 mm）再交给近场宽度抓取会话。
近场先在当前朝向计算左右包络边界、独立舵机开度、真实前进行程和危险扫掠；包络中心不再是
±5 mm 的提交门槛。只要左右末端可达且路径合法，直接停车进入唯一确认/开爪；只有当前朝向
确实无法夹取时，才选择进入机械可夹范围的最小转角。多成员组的开口超过最大行程仍淘汰，
不通过收窄开口伪造可夹取；单目标的边界也必须服从真实舵机行程。
必要转角由 IMU 闭环执行有界粗转，进入物理可夹范围立即制动；同一物理目标最多一次粗转和
一次必要修正。没有覆盖采集时刻的运动历史时只允许有界动作后复核，不伪造时间补偿；没有新
视觉结果时不会持续按旧视觉角旋转数秒。
锁定目标的身份已由 tracker 确认，单帧颜色证据不足只算缺几何证据，不作废确认窗口；
明确蓝色危险与颜色冲突仍立即失效。候选通过后立即制动，真实停稳后的一个
当前新帧再次通过相同门禁即冻结计划，按该帧左右边界分别计算动态舵机角，再执行编码器
定距前进和闭爪。`confirmation_frames=1` 表示这一个停稳后当前帧，不再叠加三帧中心确认；
`alignment_timeout_ms` 只保留为停稳、当前帧和异步准备结果的总提交预算。
开爪前检查当前几何的真实采集年龄、准备结果年龄和实际底盘静止区间；停车后采集的
当前计划允许正常处理延迟超过150 ms，仍受 processing 观测失联上限及尝试总预算限制。
静止必须来自连续有效的轮编码器/IMU，而非零速指令；完整门禁与日志语义见
[app README](../src/rescue_vision/app/README.md)。不能用控制时刻改写旧几何的采集时刻。
数据短缺、结果延迟和提交超时返回带原因的搜索/重选；只有实际走廊被明确危险或不合法几何阻挡时才进入解团。
一般阶段最多远距重接近一次。当前方向的直接抓取走廊检查所有已知危险目标，不能用动态开爪绕过安全门禁。
每次近场失败记录具体目标/物理区域、原因、确认进度、观测/准备年龄和截止时间；跨会话仍按
物理区域抑制同一尝试，只有相对几何、路径或机器人位置发生明确变化才重新允许。
本地预览和观察图传在同一采集帧上显示对准预览、复核、可执行或被阻挡的走廊区域。
首次运输的策略是恰好一个绿色普通物资；若候选的前进走廊存在蓝色、橙色或黑色目标，
先尝试其它安全绿色候选，只有没有合法抓取方案时才进入局部解团。候选方向的走廊横向门限
按两块实体的内切半径之和加实际夹爪余量（`near_field_grasp.clearance_mm` 的一半和
`near_field_grasp.corridor_lateral_margin_mm`）逐目标计算，不再使用固定半宽或蓝块外接
半径：只是近旁、并不在夹取路径上的异类目标不否决候选，避免制造不必要的解团；
`match.green_path_half_width_mm` 只作为缺少目标物理尺寸配置时的回退值。近场扫掠中的蓝块
同样按内切半径收缩净空，蓝块实体始终参与扫掠阻挡。首次交付完成后可选择绿/黑物资 1～3 个，或单独选择 1 个橙色伤员。蓝色、
缺几何目标只有在当前帧有可靠地面点且实际进入走廊时才能精确判定；缺少 K0 的危险目标不能被当作走廊为空，近场提交会拒绝并等待当前几何。橙色隔离区内的邻居按上述包络条件复核，不允许伤员混运。缺少 K0 的无关合法目标不参与橙色禁区的距离推定。计划提交前检查双方安全区、
场界和车体余量；缺少定位时停车等待，路径阻挡时按现有解团/重选路由处理。开爪前目标失效时只在本次预算内重新观察，
之后转远距接近或返回搜索，不再回到同一近场旋转循环；开爪后的关键运动故障才进入动作中止。锁定成员单帧
颜色证据不足只保留身份和确认预算、暂停当前清洁几何提交，不升级为 `class_changed`/明确危险；缺几何仍
不能作为安全物资或安全路径证据，明确危险历史在轨迹存续期内保持。
动作切换按 `action_settle_time_s` 保持零速，并由陀螺仪保持直线航向。

正式流程的局部解团使用实际成员 K0 作为候选接触点，按扫掠可接触成员数、局部密度、
距离和转角排序；整团算术均值只保留为诊断信息。已经放入安全区的物资不再进入成团和
瞄准点候选——它们仍留在目标集合里继续参加推移净空检查，不能被碰撞也不能被忽略——
因此交付堆积不会把车反复拉回安全区。含蓝色成员的混合团可以在其
阻碍合法抓取时解团，全蓝团跳过。发现需要解团后先保持零速，等待真实编码器/IMU停稳；
停稳后的当前帧选择一个可靠接触核心，并一次完成危险目标、场界、安全区和机器人包络
检查。随后只用 `match.breakup_confirmation_frames` 个不同有效帧确认同一物理核心；确认
成功立即冻结当前计划，不再执行单独旋转、接近或接触后的第二轮参考采集，也不等待近场
抓取准备器。冻结后按闭爪前推、停稳张爪、后退、停稳闭爪执行；前推距离由首次接触、
局部穿入量和配置上限共同限制，后退保留退出净空并在刹车余量前减速。前推深度取
`min(breakup_penetration_mm 或 retry, 局部团自身纵向跨度, 行程上限)`，因此单纯调大
`breakup_penetration_mm` 只对深团有效，浅团仍按自身跨度停。最小可行推进深度门槛取
`breakup_min_penetration_mm` 与 `breakup_braking_margin_mm` 之和同局部接触集自身跨度
的较小值：浅团只要能整段推穿就成立。固定取两者之和会永久淘汰比门槛浅的合法团，
40 mm 正四面体黑核的内切接触盘只有 2r≈23 mm，现场日志里 129 次逐候选淘汰有 127 次
正是这个 23.1 mm；刹车余量已由行程上限和扫掠外延各扣一次，不该再当成物料深度要求。
行程不足以推穿接触跨度时仍按当时门槛淘汰。
计划、实际行程、碰撞成员和尝试编号写入诊断；确认超时或当前核心失效则退出本次区域并恢复搜索。
失败记忆按**物理瞄准点**记：一次确认超时只封锁它真正瞄准的那一个点，历史尝试也只和
同一瞄准点比对（容差 `cluster_group_ground_mm`）。旧实现把失败计划的整组成员足迹当
区域、并用 `cluster_group_ground_mm + breakup_retry_penetration_mm`（460 mm）邻域认
"同一个团"，一次超时就让 100 mm 内所有团连续 20 秒无法解团、一次别处推挤就把附近
几百毫米的团判成尝试用尽。
搜索、对准、近场和重选之间共用同一份**旋转预算**：按绝对累计转角计算，只有真正执行
完一次抓取或一次解团推挤、或确认场上不再有蓝块以外的可收集信息时才重新计时；状态
切换不清零。**一圈用完仍未执行任何动作且场上仍有可收集目标时，必须推进到有效动作**：先
在失败记忆有效的前提下选择其它合法接触计划并正常确认（`rotation_budget_commit`），不把
失败瞄准点直接强制提交。若没有其它合法计划，则执行经过完整场界/安全区路径检查的有界
`RELOCATE_FORWARD` 换位；失败记忆不清除，只有真实编码器位移改变几何后才重新评估。只有
确实只剩蓝块时才允许继续扫描。停稳后仍选不出任何合法接触计划时，
`match.breakup_no_plan_reobserve_ms` 只给一个有界的重观测窗口（现场按约两帧取值）就
退出本次区域：重复观测只有在新一帧检出新的可接触成员时才可能改变结果，不再占满按
确认帧数计的完整确认预算。入口时冻结的待确认计划不算数：执行计划必须由停稳后的当前帧
重新生成，重算失败时同样按"无计划"窗口退出。
近场路由宣告几何阻挡但当前帧已经选不出合法接触计划时不停车：不为不可能的动作进入
停稳、重观测和放弃的循环，直接按失败记忆带原因重选，把该物理瞄准点记入失败记录，
由搜索换目标或换区域；同一输入帧最多求一次接触计划。已交付物资按**图像上目标框与
安全区框重叠**排除候选和成团：交付线（场地 y=1115）、静态地图多边形（y≥1200）和实测
地标（y=1137）三个数值并不一致，靠场地位姿反推会把刚推进安全区的物块重新当候选，
图像重叠不依赖位姿推算。逐候选的淘汰原因写入 `rejected_candidates=[...]` 诊断，避免
现场只能看到"选不出计划"这一个结论。

2026-09-10 的日志暴露出旧版“对齐—接近—二次复核—近场准备”链路会在零速阶段反复
等待和清零。当前正式流程已收缩为停稳后的当前帧安全规划、少量连续核心确认和一次
冻结，再进入前推/张爪/后退；`match.breakup_confirmation_frames` 控制确认帧数。真实
编码器/IMU 静止证据、危险类表现、接触效果及 Pi/Hailo 端到端性能仍需真机复测。具体
接口见 [app README](../src/rescue_vision/app/README.md)，通用开发约束见 [AGENTS.md](../AGENTS.md)。
一般阶段绿/黑近场收拢完成且本趟未满 `near_field_grasp.max_targets`（上限 3）时，
进入 `TRANSPORT_GREEDY_SCAN`，闭爪按 `spin_angle_rad`（正式配置 270°）扫描，
只寻找可直接进入近场走廊的绿/黑物资。当前帧没有可补夹的绿/黑信息（只有蓝色、
已收拢或已交付物资）时按 `cluster_search_empty_angular_velocity_rad_s` 快速转动，
出现可补夹信息后回到 `close_gripper_spin_angular_velocity_rad_s`；两条速度共用同一个
旋转预算和扫描方向。只消费收拢完成后的新观测；另有“扫描角度/角速度 + 近场确认预算”的
单调时间上限，按两条速度中较慢的一个计算，避免快速段被上限截断、也避免扫视无法完成。
发现候选后进入与搜索阶段相同的全局夹取前置链（`TRANSPORT_ALIGN_GREEN` → 接近 →
近场唯一确认窗口），扫描找到的目标同时成为近场交接先验，对准转角由实际几何决定，
需要反向时反向；不再重开一次自由选组会话。每命中一次即累计类别和数量并直接携已有物资
返程，不再重复整圈扫描，剩余容量由下一趟搜索决定；无候选、确认超时或路径受阻时同样
携已有物资返程，不带载解团或追逐远处目标。首次单绿和单橙运输，以及独立 CC/单绿运输
联调入口不启用补夹。CLI 和配置格式不变。

补夹仅接收 K0 前向距离大于 `target_final_x_mm + range_hysteresis_mm` 的新成员，
避免把已收拢区的目标当作新增物资。送入近场准备线程的观测在扫视开始时按同一条
前向界限通过 `grasp_excluded_observation_indices` 传给近场 worker，过滤爪内已携带成员，使
它们不会进入选组或重复计数；索引在同帧去重和锁定身份映射后仍指向同一物理观测。蓝色危险
证据始终保留，近处观测继续参与障碍检查，不因带载就删除危险证据。消费层再用当前位姿复核一次返回
计划，已放入安全区的物资不能冻结成执行计划。若过滤后仍出现已收拢区成员，才放弃
本次补夹并返程。扫描命中一次就返程，因此剩余容量只能由下一趟搜索补齐；当前数量仍是
动作完成后的估计，尚无真实接触确认；带载转向、二次开爪的留存效果和实际三块容量未验证。

抓取完成后保存本趟成员类别：绿/黑路线使用
`match.safe_zone_fallback_target_field_mm`，单橙色路线使用
`match.safe_zone_injured_target_field_mm`，避免把伤员送入物资区。

## 安全区视觉纠偏

夹取后若当前场地 y 已沿己方安全区方向越过 d1，则不再回到 d1，直接原地进入视觉纠偏；
否则沿补偿后的场地直线到达 d1。车辆停稳后先旋转到安全区 bbox 的水平中心；
有 bbox 时按归一化水平误差比例限速，中心死区和恢复阈值提供滞回，换向先复用轮速停稳确认，
只接受停稳确认后的新帧。若中心处三个关键点暂缺，先进入
`safe_zone_keypoint_reobserve_timeout_s` 静止重观测；框仍居中且缺点时最多按原方向低速扫视一次，
随后再次停车观察，再消费新鲜 K0/K1/K2 观测。重复旧帧不会延长窗口或混入五点标定样本，
收集配置数量的样本并取均值；安全区角点定位器结合红/蓝静态地标和完整地面外参拟合车辆
`FieldPose2D`，成功后直接覆盖当前受限航位。拟合失败会清空样本、重新寻找关键点并
保持零速等待新的完整观测。

校正后的位姿作为 d1→d2 和 d2→安全区末段的起点。两段继续使用编码器定距和陀螺仪
航向保持，不使用固定终点位姿；每一段都应用配置的刹车过冲补偿。绿/黑物资末段使用
`safe_zone_d2_to_final_speed_m_s` 和 `safe_zone_d2_to_final_braking_overrun_mm`，单个橙色
伤员改用 `safe_zone_orange_d2_to_final_speed_m_s` 和
`safe_zone_orange_d2_to_final_braking_overrun_mm`。解团动作可用
`breakup_max_wheel_acceleration_m_s2` 单独限制轮速变化率。旋转搜索在当前帧没有绿/黑/橙
有效信息（包括只有蓝色或无检测），或所有有效非蓝目标的 bbox 中心都落在安全区 bbox 内时，
使用 `cluster_search_empty_angular_velocity_rad_s` 快速扫描；出现安全区 bbox 外的可转运类别信息后
恢复普通搜索角速度。全蓝色危险目标团不进入解团，继续
搜索其它候选。搜索不再为绿色单独执行优先整圈扫描；首轮单绿仅作为候选合法性约束，一般阶段统一比较绿/黑物资组和单橙方案。推进完成后停稳、张爪释放，再沿
退出距离直线倒车；退出停稳后复用同一套安全区 bbox/K0/K1/K2 视觉纠偏，等待新鲜帧后
直接重新搜索，不再执行固定退出转向。若搜索决策进入解团，停稳后的接触计划和前推
线段仍必须通过红蓝双方安全区膨胀相交检查。

安全区 bbox 追踪使用归一化水平误差的比例控制，并由
`safe_zone_bbox_turn_deadband_ratio` 和 `safe_zone_bbox_turn_resume_ratio` 提供中心滞回；
换向先复用轮速停稳确认，只消费停稳确认后的新帧。bbox 居中后关键点仍缺失时使用
`safe_zone_keypoint_reobserve_timeout_s` 有界静止重观测；bbox 居中仍缺点时最多同向低速扫视一次，
扫描后重新停车取新帧，
重复旧帧不会延长窗口或混入五点标定样本。

## 运行配置与入口

正式流程配置为 `configs/runtime.match.yaml`，配置节为 `match`。车端入口需要物理
急停和全程监督确认：

```bash
rescue-vision-match \
  --config configs/runtime.match.yaml \
  --start-area 2 \
  --supervised-physical-stop-ready \
  --local-preview \
  --log-dir logs
```

正式流程以区域 2 的运行配置为基准。`--start-area 2`（默认值）表示地图右上角、
己方为红方；`--start-area 3` 表示地图左下角、己方为蓝方。选择 3 时，初始
`FieldPose2D`、物资区/伤员区运输终点和带符号的场地刹车过冲均相对中心十字
`(0,0)` 做 180° 中心对称；固定物理静态地图不复制或翻转。

无解团开场变体 `rescue-vision-match-nb` 使用 `configs/runtime.match_nb.yaml`，只把固定
启动转向+定距直行换成 `match.nb_opening_*` 的绝对场地坐标直线航点；其余解团、转运和
安全区运输完全复用正式流程。每段先原地对准航向再平移，每个航点到位后零速停稳再起算
下一段。字段含义、默认值和 `nb_opening=phase=...` 诊断行以
[app README](../src/rescue_vision/app/README.md) 为权威，真机核对项见
[manual_tests/README.md](../manual_tests/README.md)：

```bash
rescue-vision-match-nb \
  --config configs/runtime.match_nb.yaml \
  --supervised-physical-stop-ready \
  --log-dir logs
```

该变体只支持启动区域 2，开场航点按区域 2 坐标书写，不做中心对称。

夹取—运输联调入口复用同一配置，从 `FieldPoint(0,0)`、场地航向 `+90°` 直接搜索
绿色单物块，不进入解团。当前联调实现沿用正式流程的夹取和运输，仅在安全区末端不再
重复闭合夹爪，保持张开推入物块并保持张开退出：

```bash
rescue-vision-grab-transport \
  --config configs/runtime.match.yaml \
  --supervised-physical-stop-ready \
  --local-preview \
  --log-dir logs
```

两个入口都会在正常退出、信号、相机、通信或控制异常时进入统一停车和资源清理路径。
观察图传和地图发布是旁路，不参与运动决策。

## 明确未接入的能力

`app/scan_target_memory.py` 和 `app/field_target_cluster.py` 保留为可复用的纯逻辑模块，
并由独立测试覆盖；它们当前不属于正式流程的控制链。正式流程暂不使用跨帧视野外目标
记忆、记忆目标接管或 20 分流程的视觉纠偏设计。正式 match 已接入有限的采集时刻编码器/IMU
位姿历史，用于把选中目标转换到当前机器人坐标；它不等同于跨帧目标记忆。

## 验收边界

当前自动测试覆盖状态转移、解团/近场抓取门禁、近场会话隔离、d1 视觉纠偏、d2 和末段
航位积分、联调入口不解团、配置校验、日志/预览旁路及异常停车。正式比赛使用前仍需
完成正式 v3 模型、现场安全区地标、远场地面标定、底盘参数、固件看门狗、接触/交付
证据和真车压力测试；真机控制响应时间、夹持成功率、解团效果、危险类表现和目标硬件
端到端时延均未验证。
