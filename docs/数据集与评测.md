# 数据集、记录与评测规范

本页是记录目录、数据清单和评测输入输出的唯一 schema 说明。模块位置见[项目结构](项目结构.md)，命令的完整操作流程见[数据采集工具使用手册](数据采集工具使用.md)，现场覆盖项见[目标数据采集清单](目标数据采集清单.md)。

## 记录目录

`camera/recording.py` 中的 `FrameRecorder` 产生 schema v1 记录：

```text
recording_id/
├── session.json       # 尺寸、配置快照、版本、场景标签、丢帧统计
├── frames.jsonl       # 序号、单调时间、相机元数据、图像哈希
├── annotations.json   # 空标注清单模板或后续人工标注索引
└── frames/
```

实时线程调用 `record(frame)` 时只进行有界队列提交；图像编码与写盘位于旁路线程。队列满会返回 `False` 并累计 `dropped_frames`，不会阻塞视觉主链路。

`camera/replay.py` 中的 `RecordingSource` 严格按 `frames.jsonl` 回放原序号和原 `timestamp_ns`，读取时重新验证图像 SHA-256，用于可重复回归。`ImageDirectorySource` 和 `VideoFileSource` 使用帧序与指定/标称 FPS 生成确定性时间戳。

数据采集建议在运行配置中选择 `camera.backend: picamera2`，这样每帧会保存传感器时间、曝光时间、模拟/数字增益、色温、红蓝增益、焦点位置和帧周期。`rpicam_vid` 后端只保证配置值与应用接收时间，适合作为低开销运行备选，不应声称拥有逐帧曝光元数据。

录制时用重复的 `--tag name=value` 记录整个会话的场景标签；未提供的必需标签会显式写为 `unknown`，不会静默省略：

```bash
rescue-vision-record \
  --config configs/runtime.example.yaml \
  --output recordings/normal_bright_near_001 \
  --duration-seconds 20 \
  --tag lighting=indoor_bright \
  --tag distance=near \
  --tag occlusion=none \
  --tag motion_blur=low \
  --tag background=official_mat \
  --tag target_pose=upright \
  --tag contact_state=isolated
```

单会话结束后使用 `rescue-vision-check-recording` 完整回放图像、核对哈希与统计，并检查帧率、丢帧率及 Picamera2 元数据覆盖。参数和报告字段见[数据采集工具使用手册](数据采集工具使用.md)。

## 数据清单与分层标签

参与训练/验证/测试划分的 JSONL 每行至少包含：

```json
{
  "schema_version": 1,
  "dataset_version": "rescue-targets-v1",
  "sample_id": "recording_001/frame_000001",
  "recording_id": "recording_001",
  "image_path": "recording_001/frames/00000001.png",
  "tags": {
    "lighting": "indoor_bright",
    "distance": "near",
    "occlusion": "none",
    "motion_blur": "low",
    "background": "official_mat",
    "target_pose": "upright",
    "contact_state": "isolated"
  }
}
```

标签值由数据负责人维护受控词表；不得用空字符串或省略字段代替“未知”，应显式使用 `unknown`。同一段录像、连拍或同一物理布置必须共享 `recording_id`。

记录完成后，从一个或多个会话直接生成数据集清单。默认逐帧核对 SHA-256，并拒绝未完成记录、缺失标签、重复 `recording_id`、越出数据集根目录的路径和损坏图像：

```bash
rescue-vision-manifest \
  --dataset-root recordings \
  --dataset-version rescue-targets-v1 \
  --output dataset.jsonl \
  recordings/normal_bright_near_001 \
  recordings/hazard_shadow_far_001
```

随后按 `recording_id` 整组进行稳定哈希划分，防止相邻帧泄漏，并输出各集合的标签分布：

```bash
rescue-vision-split dataset.jsonl \
  --output dataset.split.jsonl \
  --report split-report.json
```

版本 1 强制记录光照、距离、遮挡、运动模糊、背景、目标姿态和相互接触状态。报告若显示某一关键场景只存在于单一集合，应补采数据，而不是拆散同一录像到多个集合。

## 逐对象评测记录

评测 CLI 接受已完成匹配的逐对象 JSONL：

```json
{
  "schema_version": 1,
  "sample_id": "recording_001/frame_000001",
  "object_id": "target_03",
  "ground_truth_class": "blue_danger",
  "predicted_class": "blue_danger",
  "confidence": 0.96,
  "ground_truth_ground_mm": [820.0, -120.0],
  "predicted_ground_mm": [831.0, -116.0],
  "capture_timestamp_ns": 1000000000,
  "result_timestamp_ns": 1042000000,
  "tags": {"lighting": "indoor_bright"}
}
```

- `ground_truth_class: null` 表示误检。
- `predicted_class: null` 表示漏检。
- 二者不能同时为 `null`。
- 目标匹配属于检测器评测适配器职责；本工具不以不透明规则猜测匹配关系。

运行：

```bash
rescue-vision-evaluate evaluation.jsonl \
  --output report.json \
  --model-version model-sha256-or-name \
  --dataset-version dataset-v1
```

报告包含分类别 precision/recall/F1、含误检/漏检的混淆矩阵、地面点误差、端到端 P50/P95 时延和失败样例索引，并记录模型、数据与代码版本。危险类别必须在评审时单独查看，不能被总体平均值掩盖。

任务目标评测的类别字段统一使用 `green_supply`、`black_core`、
`orange_injured`、`blue_danger` 和运行时 `unknown`。旧的
`normal/core/injured/hazard` 值不属于当前目标契约。

## 采集顺序

整车完成前先使用规则允许的实物或高一致性打印件，采集静态相机与手持运动数据，覆盖上述分层标签。底盘完成后追加真实振动、减速带和碰撞域数据，保留原数据集作为独立回归基线。
