# 数据集、记录与评测规范

本页只定义当前记录目录、数据清单和评测输入输出格式。采集、检查、清单和划分命令统一见[数据采集手册](数据采集工具使用.md)。

## 记录目录

`camera/recording.py` 中的 `FrameRecorder` 产生统一记录：

```text
recording_id/
├── session.json       # 尺寸、配置快照、场景标签、丢帧统计
├── frames.jsonl       # 序号、单调时间、相机元数据、图像路径
├── annotations.json   # 空标注清单模板或后续人工标注索引
├── motion.jsonl       # 仅手动驾驶会话：命令、轮速、UART 扩展和停车事件
└── frames/
```

`session.json` 必须记录：

- `recording_kind`：`camera` 或 `supervised_manual_motion`；
- `image_coordinate_system`：`raw_pixel` 或 `undistorted_pixel`；
- `calibration_id`：去畸变会话使用的可读标定 ID，原图为 `null`；
- `valid_pixel_ratio`：去畸变全尺寸图中的有效像素比例，原图为 `null`。
- `undistort_fill_value`：去畸变无效边缘的灰度填充值，任务数据固定为 `114`，原图为 `null`。
- `auxiliary_streams`：辅助流名到相对文件名的映射；普通相机会话为
  `{}`，手动驾驶会话声明 `manual_motion`。

任务目标清单只接受 `undistorted_pixel` 会话；原图会话只用于标定或诊断。
工具只读取当前格式，不维护历史格式兼容分支。

实时线程调用 `record(frame)` 时只进行有界队列提交；图像编码与写盘位于旁路线程。队列满会返回 `False` 并累计 `dropped_frames`，不会阻塞视觉主链路。

`camera/replay.py` 中的 `RecordingSource` 严格按 `frames.jsonl` 回放原序号和原
`timestamp_ns`，并检查图像可以解码且尺寸正确。`ImageDirectorySource` 和
`VideoFileSource` 使用帧序与指定/标称 FPS 生成确定性时间戳。

Picamera2 会话可逐帧保存传感器时间、曝光、增益、色温、红蓝增益、焦点和帧周期；`rpicam_vid` 只保证配置值与应用接收时间。

### 手动运动辅助流

手动驾驶记录的 `session.json` 必须声明：

```json
{
  "recording_kind": "supervised_manual_motion",
  "auxiliary_streams": {
    "manual_motion": "motion.jsonl"
  }
}
```

`motion.jsonl` 每行都有连续 `log_sequence`、`event_type` 和
`timestamp_ns`。事件类型为：

- `stream_started` / `stream_finished`：辅助流生命周期；
- `motion_command`：命令 ID、车端接收时间、有效期、死手、twist 和执行结果；
- `motion_timeout`：车端有效期停车及对应命令 ID；
- `gripper_command`：命令 ID、车端接收时间、有效期、张开/闭合扳机按压
  布尔状态和 `applied` / `stopped` / `expired` 执行结果；
- `gripper_timeout`：持续夹爪命令到期停止推进及对应命令 ID；
- `odometry_imu`：UART 接收时间、STM32 微秒采样时间、累计左右编码器、
  三轴陀螺仪/加速度计、IMU 温度和传感器状态位；
- `system_status`：STM32 微秒计时、固件看门狗、锁存急停、命令年龄、停车
  原因和双舵机目标；
- `command_reply`：原命令序号、命令类型和接受/拒绝结果；
- `safety_stop`：断线、UART/相机故障或应用退出等停车原因。

COBS、CRC、类型、长度、方向、枚举或状态位非法的 UART 帧会被通信/协议层
丢弃，不写成业务事件，也不会伪造定位输入。

命令接收、UART 接收、图像帧和安全停车均记录树莓派应用单调时间 ns；STM32
计时只作为独立字段，不能替代它。完整性检查要求日志首尾事件完整、字段严格、
序号连续，且运动流时间范围覆盖全部保存图像帧。脚本动作段和计划身份不属于
该手动流，仍按后续优先级后调。

## 数据清单与分层标签

参与训练/验证/测试划分的 JSONL 每行至少包含：

```json
{
  "sample_id": "recording_001/frame_00000001",
  "recording_id": "recording_001",
  "frame_sequence": 1,
  "timestamp_ns": 1000000000,
  "image_path": "recording_001/frames/00000001_1000000000.jpg",
  "image_coordinate_system": "undistorted_pixel",
  "calibration_id": "camera-front-20260729",
  "valid_pixel_ratio": 0.96,
  "undistort_fill_value": 114,
  "annotation_manifest": "recording_001/annotations.json",
  "tags": {
    "lighting": "indoor_bright",
    "distance": "near",
    "occlusion": "none",
    "motion_blur": "low",
    "background": "official_mat",
    "target_pose": "upright",
    "contact_state": "isolated"
  }
}
```

标签值由数据负责人维护受控词表；元数据无法确定时不得用空字符串或省略字段，应显式使用 `unknown`。
这只是标注元数据值，不是当前四类任务目标类别。同一段录像、连拍或同一物理布置必须共享 `recording_id`。

数据清单强制记录光照、距离、遮挡、运动模糊、背景、目标姿态和相互接触状态。
划分必须按 `recording_id` 整组进行，禁止把同一连续会话拆到不同集合。

## 逐对象评测记录

评测 CLI 接受已完成匹配的逐对象 JSONL：

```json
{
  "sample_id": "recording_001/frame_00000001",
  "object_id": "target_03",
  "ground_truth_class": "blue_danger",
  "predicted_class": "blue_danger",
  "model_predicted_class": "green_supply",
  "hsv_candidate_class": "blue_danger",
  "hsv_status": "accepted",
  "hsv_color_fraction": 0.62,
  "hsv_dominance": 0.91,
  "confidence": 0.96,
  "ground_truth_ground_mm": [820.0, -120.0],
  "predicted_ground_mm": [831.0, -116.0],
  "capture_timestamp_ns": 1000000000,
  "result_timestamp_ns": 1042000000,
  "tags": {"lighting": "indoor_bright"}
}
```

- `ground_truth_class: null` 表示误检。
- `predicted_class: null` 表示漏检。
- 二者不能同时为 `null`。
- `confidence` 是 Pose 后端检测分；颜色分类诊断分别使用
  `model_predicted_class`、`hsv_candidate_class`、`hsv_status`、
  `hsv_color_fraction` 和 `hsv_dominance`，不能把检测分解释成颜色置信度。
- ROI 二值掩码保留在实时 `TargetObservation.color_segmentation`，逐对象评测
  JSONL 不复制像素数组；需要评测掩码时应另行定义带真值版本的分割数据格式。
- `ground_truth_ground_mm` / `predicted_ground_mm` 表示 v3 任务目标 K0，即
  接触底面的几何中心在机器人地面系中的投影。旧 `TargetGroundGeometry`
  不属于 v3 主链路，不写入当前目标评测记录。
- 类别词表默认为四类 `green_supply`、`black_core`、`orange_injured`、
  `blue_danger`；词表外取值和空评测输入会被拒绝。`unknown` 不是当前任务类别，
  颜色证据不足只记录为 `hsv_candidate_class=null`，不进入类别统计。
- 报告始终包含上述四类；危险类没有真值样本时通过 `warnings` 明确告警。
- 目标匹配属于检测器评测适配器职责；本工具不以不透明规则猜测匹配关系。

报告包含分类别 precision/recall/F1、含误检/漏检的混淆矩阵、地面点误差、
端到端 P50/P95 时延和失败样例索引。危险类别必须在评审时单独查看，不能被
总体平均值掩盖。

任务目标评测的类别字段统一使用 `green_supply`、`black_core`、
`orange_injured`、`blue_danger`。旧的
`normal/core/injured/hazard` 值不属于当前目标契约。
