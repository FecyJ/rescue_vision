# 数据集、记录与评测规范

本页只定义记录目录、数据清单和评测输入输出的 schema。采集、检查、清单和划分命令统一见[数据采集手册](数据采集工具使用.md)。

## 记录目录

`camera/recording.py` 中的 `FrameRecorder` 产生 session schema v4 记录：

```text
recording_id/
├── session.json       # 尺寸、配置快照、版本、场景标签、丢帧统计
├── frames.jsonl       # 序号、单调时间、相机元数据、图像哈希
├── annotations.json   # 空标注清单模板或后续人工标注索引
├── motion.jsonl       # 仅手动驾驶会话：命令、轮速、UART 扩展和停车事件
└── frames/
```

`session.json` 必须记录：

- `recording_kind`：`camera` 或 `supervised_manual_motion`；
- `image_coordinate_system`：`raw_pixel` 或 `undistorted_pixel`；
- `intrinsics_fingerprint_sha256`：去畸变会话使用的内参指纹，原图为 `null`；
- `valid_pixel_ratio`：去畸变全尺寸图中的有效像素比例，原图为 `null`。
- `undistort_fill_value`：去畸变无效边缘的灰度填充值，任务数据固定为 `114`，原图为 `null`。
- `auxiliary_streams`：辅助流的版本、相对文件名和时间基准；普通相机会话为
  `{}`，手动驾驶会话声明 `manual_motion`。

其中 `frames.jsonl`、`annotations.json` 和 `motion.jsonl` 各自使用 schema
v1。任务目标清单只接受 `undistorted_pixel` 会话；原图会话只用于标定或诊断。

session v3 已包含完整图像身份，当前回放、检查和清单继续兼容；它没有
`auxiliary_streams`，不能冒充含运动证据的手动会话。session v2 和数据清单
v1 没有记录边缘填充值，当前工具会拒绝它们。不要只改 schema 数字伪造迁移；
旧图若使用黑色边缘，应从原图重新去畸变为填充值 `114` 并重新计算图片哈希、
会话统计和清单，或重新采集。

实时线程调用 `record(frame)` 时只进行有界队列提交；图像编码与写盘位于旁路线程。队列满会返回 `False` 并累计 `dropped_frames`，不会阻塞视觉主链路。

`camera/replay.py` 中的 `RecordingSource` 严格按 `frames.jsonl` 回放原序号和原 `timestamp_ns`，读取时重新验证图像 SHA-256，用于可重复回归。`ImageDirectorySource` 和 `VideoFileSource` 使用帧序与指定/标称 FPS 生成确定性时间戳。

Picamera2 会话可逐帧保存传感器时间、曝光、增益、色温、红蓝增益、焦点和帧周期；`rpicam_vid` 只保证配置值与应用接收时间。

### 手动运动辅助流

手动驾驶记录的 `session.json` 必须声明：

```json
{
  "schema_version": 4,
  "recording_kind": "supervised_manual_motion",
  "auxiliary_streams": {
    "manual_motion": {
      "schema_version": 2,
      "path": "motion.jsonl",
      "time_base": "application_monotonic_ns"
    }
  }
}
```

`motion.jsonl` 每行都有 `schema_version=2`、连续 `log_sequence`、
`event_type` 和 `timestamp_ns`。事件类型为：

- `stream_started` / `stream_finished`：辅助流生命周期；
- `motion_command`：命令 ID、车端接收时间、有效期、死手、twist 和执行结果；
- `motion_timeout`：车端有效期停车及对应命令 ID；
- `wheel_telemetry`：UART 接收时间、STM32 毫秒计时、目标/实测轮速和舵机角；
- `safety_status`：版本化固件看门狗、锁存急停、命令年龄和停车原因；
- `command_reply`：STM32 命令回复；
- `unknown_uart`：以十六进制保留尚未冻结的 IMU 等扩展原始报文；
- `safety_stop`：断线、UART/相机故障或应用退出等停车原因。

命令接收、UART 接收、图像帧和安全停车均记录树莓派应用单调时间 ns；STM32
计时只作为独立字段，不能替代它。完整性检查要求日志首尾事件完整、字段严格、
序号连续，且运动流时间范围覆盖全部保存图像帧。脚本动作段和计划身份不属于
该手动流，仍按后续优先级后调。

schema v2 相比未发布的 v1 增加 `safety_status`；检查工具严格拒绝把 v1 日志
声明为 v2。已有本地试录目录如仍是 v1，应保留或归档原目录后重新采集，
不做无证据的就地转换。

## 数据清单与分层标签

参与训练/验证/测试划分的 JSONL 每行至少包含：

```json
{
  "schema_version": 2,
  "dataset_version": "rescue-targets-v1",
  "sample_id": "recording_001/frame_00000001",
  "recording_id": "recording_001",
  "frame_sequence": 1,
  "timestamp_ns": 1000000000,
  "image_path": "recording_001/frames/00000001_1000000000.jpg",
  "image_sha256": "bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb",
  "image_coordinate_system": "undistorted_pixel",
  "intrinsics_fingerprint_sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "valid_pixel_ratio": 0.96,
  "undistort_fill_value": 114,
  "annotation_manifest": "recording_001/annotations.json",
  "tags": {
    "lighting": "indoor_bright",
    "distance": "near",
    "occlusion": "none",
    "motion_blur": "low",
    "background": "official_mat",
    "target_pose": "upright",
    "contact_state": "isolated"
  }
}
```

标签值由数据负责人维护受控词表；不得用空字符串或省略字段代替“未知”，应显式使用 `unknown`。同一段录像、连拍或同一物理布置必须共享 `recording_id`。

数据清单 schema v2 强制记录光照、距离、遮挡、运动模糊、背景、目标姿态和相互接触状态。清单生成默认逐帧核对 SHA-256；划分必须按 `recording_id` 整组进行，禁止把同一连续会话拆到不同集合。

## 逐对象评测记录

评测 CLI 接受已完成匹配的逐对象 JSONL：

```json
{
  "schema_version": 1,
  "sample_id": "recording_001/frame_00000001",
  "object_id": "target_03",
  "ground_truth_class": "blue_danger",
  "predicted_class": "blue_danger",
  "confidence": 0.96,
  "ground_truth_ground_mm": [820.0, -120.0],
  "predicted_ground_mm": [831.0, -116.0],
  "capture_timestamp_ns": 1000000000,
  "result_timestamp_ns": 1042000000,
  "tags": {"lighting": "indoor_bright"}
}
```

- `ground_truth_class: null` 表示误检。
- `predicted_class: null` 表示漏检。
- 二者不能同时为 `null`。
- 类别词表默认为 `green_supply`、`black_core`、`orange_injured`、
  `blue_danger`、`unknown`；词表外取值和空评测输入会被拒绝。
- 报告始终包含上述五类；危险类没有真值样本时通过 `warnings` 明确告警。
- 目标匹配属于检测器评测适配器职责；本工具不以不透明规则猜测匹配关系。

报告包含分类别 precision/recall/F1、含误检/漏检的混淆矩阵、地面点误差、端到端 P50/P95 时延和失败样例索引，并记录模型、数据与代码版本。危险类别必须在评审时单独查看，不能被总体平均值掩盖。

任务目标评测的类别字段统一使用 `green_supply`、`black_core`、
`orange_injured`、`blue_danger` 和运行时 `unknown`。旧的
`normal/core/injured/hazard` 值不属于当前目标契约。
