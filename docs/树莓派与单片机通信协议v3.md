# 树莓派与单片机通信协议

本文是树莓派视觉计算端与 STM32 底盘控制端之间通信接口的唯一权威。它面向
长期运行、运动安全和编码器/IMU 定位，替代现有 Rescue Car 文本行协议。

当前 STM32 固件和仓库内的树莓派参考实现均已切换到本文协议。参考脚本
`raspberry_pi_imu_receiver.py` 提供编解码、统一命令序号分配和遥测接收能力。
它不是完整的自动驾驶进程。真实驾驶程序仍要实现本文第 7 节规定的周期发送、
持续接收、回复健康检查和安全重同步流程。

旧文本命令 `m...`、`g...`、`t...`、`s1...`、`OK` 和 `ERR` 已不受支持。同一
UART 不能混入调试文本。

本文不规定 IMU 模块自身的 UART/I²C 协议。STM32 负责读取、校验和时间戳 IMU
数据，再按本文统一发送；不得把 IMU 厂商的二进制帧透明转发到树莓派。

## 1. 设计边界

- 物理链路固定为 UART 115200、8N1、无硬件流控。
- 线路只有一种二进制分帧，不混用调试文本、日志或 IMU 原始协议。
- 每种消息有固定布局。修改字段时同时修改两端和本文，不维护 schema 版本、
  兼容别名或能力协商。
- CRC16 只负责发现传输损坏，不提供认证或保密；协议不使用 SHA、签名、密钥、
  JSON、时间字符串或文件校验和。
- STM32 负责电机闭环、夹爪输出、失联停车、急停锁存、编码器采样和 IMU 采样。
- 树莓派负责机械标定参数、里程计/IMU/视觉融合和场地坐标，不向 STM32 下发
  全局位置，也不把 STM32 积分位置作为定位权威。

## 2. 帧格式

一帧在线路上的格式为：

```text
COBS(message_type | payload | crc16_le) | 0x00
```

- COBS 使用标准 Consistent Overhead Byte Stuffing；`0x00` 只作为帧结束符。
- 解码后的首字节是 `message_type`，末两字节是 CRC16，二者之间是固定长度
  payload；没有 magic、长度字段或结束字符串。
- 多字节整数统一为小端。协议不传输浮点数。
- CRC 使用 CRC-16/CCITT-FALSE：`poly=0x1021`、`init=0xFFFF`、
  `refin=false`、`refout=false`、`xorout=0x0000`。
- CRC 覆盖 `message_type | payload`，结果以小端 `uint16` 附在末尾。
  标准检查输入 ASCII `123456789` 的结果为 `0x29B1`。
- 解码后帧长度上限为 64 bytes。空帧、COBS 错误、超长、长度不符、未知类型或
  CRC 错误的帧直接丢弃，不刷新运动看门狗，也不回复错误帧。

接收端必须持续消费字节流。遇到损坏帧后丢弃到下一个 `0x00`，下一帧仍可正常
解析。发送端不得在同一 UART 输出 `printf` 调试文字。

## 3. 公共类型和时间

| 名称 | 宽度 | 说明 |
| --- | ---: | --- |
| `u8` / `i8` | 1 byte | 无符号/有符号整数 |
| `u16` / `i16` | 2 bytes | 小端整数 |
| `u32` / `i32` | 4 bytes | 小端整数 |
| `u64` / `i64` | 8 bytes | 小端整数 |

命令序号和周期遥测序号均为 `u16`，到 `65535` 后回到 `0`。树莓派发出的所有
命令建议共用一个序号分配器，每发出一条新命令就取下一个序号。每种周期遥测
各自维护序号。连续性判断按模 `65536` 计算，`65535 → 0` 是正常连续帧。

STM32 对 `SET_WHEEL_SPEED` 和 `SOFT_BRAKE` 维护一条运动序号流。处于正常运动
状态时，序号差值落在 `1..32767` 才视为向前。旧的轮速序号返回
`sequence_old`，不会执行。下面几种情况有专门处理。

- 当前最新运动帧原样重发时，STM32 返回相同结果。回复队列有可用槽位时，已
  接受的重传会刷新 300 ms 运动看门狗，不会重复改变目标。
- 旧上位机若复用当前序号但改变轮速，STM32 仍接受新目标。这项行为只用于兼容，
  新上位机不得依赖它。
- `SOFT_BRAKE` 不受旧序号限制。它是树莓派启动、重连和收到
  `sequence_old` 后的安全重同步命令。停车后的第一帧轮速允许从任意序号开始。
- 运动看门狗超时后，STM32 清除运动序号历史。重启后的树莓派可以从任意序号
  建立新会话。
- `EMERGENCY_STOP` 每次收到合法帧都会执行，不参与去重。

`sample_timestamp_us` 和 `controller_timestamp_us` 是 STM32 从本次启动开始的
单调时间，类型为 `u64`。当前固件用 1 ms 系统时基换算为微秒，因此末三位固定
为零。定位帧填写新 raw 样本提交时刻，不使用 UART 开始发送的时刻。树莓派
收到完整帧时另外记录本机 `monotonic_ns`；两台设备的时间值不能直接相减。
STM32 重启表现为控制器时间倒退，树莓派必须清除连续积分状态，等待新的绝对
视觉观测或重新初始化。

## 4. 树莓派到 STM32 的命令

### 4.1 设置轮速 `SET_WHEEL_SPEED`（`0x10`）

| 偏移 | 类型 | 字段 | 说明 |
| ---: | --- | --- | --- |
| 0 | `u8` | `message_type` | 固定 `0x10` |
| 1 | `u16` | `command_sequence` | 命令序号 |
| 3 | `i16` | `left_target_mm_s` | 左轮目标速度，正值向前 |
| 5 | `i16` | `right_target_mm_s` | 右轮目标速度，正值向前 |
| 7 | `u16` | `crc16` | 帧 CRC |

STM32 只接受固件安全限值内的速度。有效命令更新左右目标并刷新运动看门狗；
越界命令拒绝执行且不刷新看门狗。树莓派在运动使能期间必须周期重发当前目标，
建议 20–50 Hz，不能只在目标改变时发送。每个发送周期使用新的命令序号。不要
等待上一周期的 `COMMAND_REPLY` 才发送下一周期轮速，否则回复丢失会拖慢控制。

连续轮速流中的旧帧不补发。新的周期目标已经发出后，缺失的旧回复只记为链路
质量问题，不能把旧速度重新插回发送队列。若连续 100 ms 没有确认任何新轮速，
上位机发送 `SOFT_BRAKE` 并退出运动状态。

左右速度必须按小端有符号 `int16` 解析，再执行固件独立限幅；不得先读成
`uint16` 再参与控制。例如 `CE FF` 表示 `-50 mm/s`，不是 `65486 mm/s`。
任何一轮绝对值超过固件安全上限时整条命令返回 `out_of_range`，两轮目标均不
更新。该项必须用前进、后退、左右原地转向四种符号组合做固件单元测试。

### 4.2 柔和停车 `SOFT_BRAKE`（`0x11`）

| 偏移 | 类型 | 字段 | 说明 |
| ---: | --- | --- | --- |
| 0 | `u8` | `message_type` | 固定 `0x11` |
| 1 | `u16` | `command_sequence` | 命令序号 |
| 3 | `u16` | `crc16` | 帧 CRC |

有效命令把双轮目标设为零，按 STM32 已标定的制动斜率减速，并刷新看门狗。
制动斜率不逐条下发，避免两端维护两套运动约束。

`SOFT_BRAKE` 也是运动序号的安全同步点。树莓派打开串口或进程重启后，先发送
一帧 `SOFT_BRAKE` 并等待 `accepted`，随后才允许发送非零轮速。收到
`sequence_old` 时执行同样流程。STM32 接受任意合法序号的柔和停车帧。
柔和停车被接受后，紧接着的第一帧合法 `SET_WHEEL_SPEED` 也允许使用任意序号，
随后恢复正常的模 `65536` 前进关系。这兼容旧程序为不同命令分别计数的行为。

### 4.3 紧急停止 `EMERGENCY_STOP`（`0x12`）

| 偏移 | 类型 | 字段 | 说明 |
| ---: | --- | --- | --- |
| 0 | `u8` | `message_type` | 固定 `0x12` |
| 1 | `u16` | `command_sequence` | 命令序号 |
| 3 | `u16` | `crc16` | 帧 CRC |

STM32 收到有效帧后立即关闭运动输出并锁存急停。本文不定义远程解除急停命令；
只能在目标为零时通过后续真机安全评审确认的现场动作解除。任何轮速命令和
树莓派重连都不得自动解除。

急停锁存后仍允许 `SOFT_BRAKE` 返回 `accepted`，用于安全重同步。该命令不会
重新打开电机输出，也不会解除急停。

### 4.4 设置夹爪目标 `SET_GRIPPER`（`0x13`）

| 偏移 | 类型 | 字段 | 说明 |
| ---: | --- | --- | --- |
| 0 | `u8` | `message_type` | 固定 `0x13` |
| 1 | `u16` | `command_sequence` | 命令序号 |
| 3 | `u16` | `left_target_cdeg` | 左舵机目标，百分之一度 |
| 5 | `u16` | `right_target_cdeg` | 右舵机目标，百分之一度 |
| 7 | `u16` | `crc16` | 帧 CRC |

角度范围固定为 `0..18000`。夹爪机械开闭端点仍由树莓派运行配置保存；STM32
只执行显式双舵机目标和自身电气安全限制。夹爪命令不刷新运动看门狗；停车或
失联时保持最近夹爪目标，不自动释放物品。

### 4.5 查询状态 `QUERY_STATUS`（`0x14`）

| 偏移 | 类型 | 字段 | 说明 |
| ---: | --- | --- | --- |
| 0 | `u8` | `message_type` | 固定 `0x14` |
| 1 | `u16` | `command_sequence` | 命令序号 |
| 3 | `u16` | `crc16` | 帧 CRC |

回复队列有可用槽位时，有效命令额外触发一帧 `SYSTEM_STATUS`，但不刷新运动
看门狗。队列已满时，该命令不执行且可能没有回复。

## 5. STM32 到树莓派的消息

### 5.1 命令回复 `COMMAND_REPLY`（`0x80`）

| 偏移 | 类型 | 字段 | 说明 |
| ---: | --- | --- | --- |
| 0 | `u8` | `message_type` | 固定 `0x80` |
| 1 | `u16` | `command_sequence` | 原命令序号 |
| 3 | `u8` | `command_type` | 原命令类型 |
| 4 | `u8` | `result` | 结果枚举 |
| 5 | `u16` | `crc16` | 帧 CRC |

`result` 固定为：

| 值 | 名称 | 含义 |
| ---: | --- | --- |
| 0 | `accepted` | 命令已接受；当前命令的原样重传也返回此值 |
| 1 | `out_of_range` | 数值超出固件安全范围 |
| 2 | `emergency_stop_latched` | 急停锁存，拒绝运动命令 |
| 3 | `device_unavailable` | 对应执行器当前不可用 |
| 4 | `sequence_old` | 轮速序号落后于当前运动序号，命令未执行 |

`accepted` 只表示 STM32 接受了目标，不表示电机或舵机已经物理到位。树莓派
不得等待回复后才发送下一周期轮速命令。

STM32 的高优先级回复队列容量为 8。普通命令只有在回复成功入队后才执行。
队列已满时，普通命令不执行，也可能没有对应回复。急停仍立即执行，但急停
回复可能因队列已满而缺失。树莓派必须持续排空串口，不能用突发方式一次灌入
大量命令。`system_flags.reply_queue_full` 可用于发现本次启动期间发生过这类
拥塞。

对没有后继新目标的低频命令，回复超时后可以原样重发一次。重发必须保留原
序号和原 payload。轮速流已经发送更新目标时，不再重发旧轮速。收到
`sequence_old` 后丢弃旧目标，执行一次 `SOFT_BRAKE` 同步流程。

`device_unavailable` 为保留结果。当前固件尚未生成该结果。

### 5.2 里程计与 IMU `ODOMETRY_IMU`（`0x81`）

该帧由 STM32 的固定 10 ms 周期释放，正常目标频率为 100 Hz。每个周期在关中断
窗口内原子锁存左右编码器累计计数、最新 IMU raw 状态和该样本的提交时间。若本周期
没有完成新的 IMU 事务，或 I²C 事务失败/周期超期，仍发送该周期编码器和最近一次
IMU 状态，但清除 `imu_valid` 并置位 `sample_overrun`；时间戳保持最近一次 raw 样本
的提交时间，不能改成 UART 发送时刻。下一周期重新计算该标志，不能永久粘住。

| 偏移 | 类型 | 字段 | 单位/说明 |
| ---: | --- | --- | --- |
| 0 | `u8` | `message_type` | 固定 `0x81` |
| 1 | `u16` | `telemetry_sequence` | 本消息独立序号 |
| 3 | `u64` | `sample_timestamp_us` | STM32 单调采样时间 |
| 11 | `i64` | `left_encoder_count` | 左轮累计计数，正值向前 |
| 19 | `i64` | `right_encoder_count` | 右轮累计计数，正值向前 |
| 27 | `i32` | `gyro_x_urad_s` | IMU 传感器 `+x` 角速度，µrad/s |
| 31 | `i32` | `gyro_y_urad_s` | IMU 传感器 `+y` 角速度，µrad/s |
| 35 | `i32` | `gyro_z_urad_s` | IMU 传感器 `+z` 角速度，µrad/s |
| 39 | `i32` | `accel_x_mm_s2` | IMU 传感器 `+x` 加速度，mm/s² |
| 43 | `i32` | `accel_y_mm_s2` | IMU 传感器 `+y` 加速度，mm/s² |
| 47 | `i32` | `accel_z_mm_s2` | IMU 传感器 `+z` 加速度，mm/s² |
| 51 | `i16` | `imu_temperature_cdeg` | IMU 温度，百分之一摄氏度 |
| 53 | `u16` | `sensor_flags` | 传感器状态位 |
| 55 | `u16` | `crc16` | 帧 CRC |

机器人坐标原点是两驱动轮接地点连线中点，`x` 向前、`y` 向左、`z` 向上。
本固件明确不把车辆安装轴旋转、零偏、温漂或噪声参数写入 STM32；上述三个
IMU 字段保持传感器坐标系，只有厂商量程和单位换算在 STM32 完成。树莓派必须
在融合前对每帧按下面的顺序应用车辆标定，而且只能应用一次：

```text
sensor_corrected = cross_axis_scale * (sensor_value - bias(temperature))
robot_value      = sensor_to_robot * sensor_corrected
```

其中 `bias`、每轴 scale/cross-axis、温度补偿和 `sensor_to_robot` 3×3 矩阵都
属于树莓派配置。若仍使用兼容字段 `motion.odometry.gyro_z_sign`，应将它并入
该矩阵或在矩阵外只应用一次，不能同时在 STM32 和树莓派翻转。当前现场看到的
传感器静止倾角会原样出现在 sensor-frame 加速度中；经过树莓派矩阵后，车辆
水平静止时机器人坐标才应近似 `(0, 0, +9807) mm/s²`。树莓派不解释厂商
四元数或欧拉角。

这是一项字段语义的明确修订，57 字节二进制布局、类型、偏移、字节序、COBS
和 CRC 均不变。任何仍把 `0x81` 三轴值直接当作机器人坐标的树莓派代码都必须
同步修改；禁止在两端同时应用同一个安装旋转或符号。

编码器累计值从 STM32 启动时的零点开始，运行中不得清零。两轮正值都表示
前进；必须包含实际采用的正交解码倍频和减速后的全部计数。每圈计数、有效
轮径和有效轮距属于树莓派机械标定，不放进每帧通信。

`sensor_flags` 位定义如下；未定义位必须为零：

| bit | 名称 | 为 1 的含义 |
| ---: | --- | --- |
| 0 | `imu_valid` | 本帧 IMU 数值可用 |
| 1 | 保留 | 当前固件固定为 0 |
| 2 | `left_encoder_valid` | 左编码器可用 |
| 3 | `right_encoder_valid` | 右编码器可用 |
| 4 | `gyro_saturated` | 本周期陀螺仪接近按配置满量程的 98% guard band |
| 5 | `accel_saturated` | 本周期加速度计接近按配置满量程的 98% guard band |
| 6 | `sample_overrun` | 自上一帧后发生采样超期或漏采 |

树莓派只有在相应 `valid` 位有效时才能消费数据。饱和或超期帧可以记录，但
必须由融合层拒绝或显著降权。参考实现对单次且双编码器有效的 `sample_overrun`
暂存一个周期，待下一帧正常遥测后对陀螺数据做线性插值；连续异常或其他连续性
错误仍清除连续位姿。饱和位即使 `imu_valid=0` 也会保留，用于区分
“样本已拒绝”的原因。协议不发送磁力计、四元数、欧拉角或 STM32
积分位姿；这些数据对当前二维视觉融合不是必要输入，且磁力计容易受到电机和
车体材料干扰。

当前 IMU 通过 I²C 中断状态机异步采样，raw 事务不在主循环同步等待。`sample_timestamp_us`
以 STM32 毫秒时基记录 raw 样本完成时间，因此分辨率为 1000 µs。加速度三轴
全零、接近满量程、物理范围异常或突变样本不会标记为有效；固件仍按 100 Hz
周期发送编码器累计值和最近状态，同时清除 `imu_valid`。陀螺静止为零是合法的，
但不能用来把全零加速度样本当作重力样本。

### 5.3 系统状态 `SYSTEM_STATUS`（`0x82`）

STM32 固定以 10 Hz 发送，并在收到 `QUERY_STATUS` 后额外立即发送一帧。

| 偏移 | 类型 | 字段 | 说明 |
| ---: | --- | --- | --- |
| 0 | `u8` | `message_type` | 固定 `0x82` |
| 1 | `u16` | `status_sequence` | 本消息独立序号 |
| 3 | `u64` | `controller_timestamp_us` | STM32 单调时间 |
| 11 | `u16` | `watchdog_timeout_ms` | 固件运动失联超时 |
| 13 | `u32` | `last_motion_command_age_ms` | 尚未收到时为 `0xFFFFFFFF` |
| 17 | `u16` | `system_flags` | 系统状态位 |
| 19 | `u8` | `stop_reason` | 当前运动状态枚举 |
| 20 | `u16` | `servo_left_target_cdeg` | 左舵机当前目标 |
| 22 | `u16` | `servo_right_target_cdeg` | 右舵机当前目标 |
| 24 | `u16` | `crc16` | 帧 CRC |

`system_flags` 位定义如下；未定义位必须为零。bit 4–6 是粘滞健康告警，只要
本次 STM32 启动期间发生过一次对应故障就保持为 1，重启后清零。

| bit | 名称 | 为 1 的含义 |
| ---: | --- | --- |
| 0 | `protocol_ready` | 二进制协议已经初始化并可收发 |
| 1 | `emergency_stop_latched` | 急停已经锁存 |
| 2 | `motor_output_enabled` | 电机驱动输出当前允许 |
| 3 | `gripper_output_available` | 双舵机输出可用 |
| 4 | `reply_queue_full` | 本次启动期间回复队列曾经满载 |
| 5 | `tx_degraded` | 本次启动期间 UART TX 启动失败或发生过 20 ms stall |
| 6 | `rx_degraded` | 本次启动期间发生过 RX 溢出、UART 错误或非法帧 |

当前固件在舵机 PWM 初始化后固定置位 bit 3，没有舵机位置或电流反馈。它只
表示输出通道已经配置，不能证明夹爪物理到位。运动看门狗是否已经收到过运动
命令可结合 `last_motion_command_age_ms` 判断。该字段为 `0xFFFFFFFF` 时尚未
接受运动命令。

`stop_reason` 固定为：

| 值 | 名称 | 含义 |
| ---: | --- | --- |
| 0 | `startup` | 启动后尚未接受运动命令 |
| 1 | `running` | 正常执行轮速目标，包括零目标 |
| 2 | `soft_brake` | 正在或已经柔和停车 |
| 3 | `watchdog_timeout` | 失联看门狗触发停车 |
| 4 | `emergency_stop` | 急停锁存停车 |

## 6. 安全行为

1. STM32 上电后轮速目标和电机输出为零。硬件 IWDG 立即运行。运动通信看门狗
   在首次接受 `SET_WHEEL_SPEED` 或 `SOFT_BRAKE` 后开始计时。
2. `watchdog_timeout_ms` 必须是固件固定安全参数，首版建议 300 ms；不得由
   树莓派逐条修改。
3. 只有通过 COBS、固定长度、CRC、类型和值域校验，并且成功预留回复位置的
   `SET_WHEEL_SPEED` 和 `SOFT_BRAKE` 刷新运动看门狗。当前最新运动帧的原样
   重传也会刷新看门狗。
4. `SET_GRIPPER`、`QUERY_STATUS`、损坏帧、未知帧和越界命令不得刷新看门狗。
5. 距最近一次有效运动心跳达到 300 ms 后，STM32 把双轮目标和输出降为零，
   清除运动序号历史，并持续报告 `watchdog_timeout`。UART 恢复后不自动恢复
   旧目标。超时后的第一帧合法轮速可从任意序号开始。新的上位机仍应先完成
   柔和停车同步，再发送非零轮速。
6. 急停优先级高于全部运动命令并保持锁存。本文不允许通过通信解除急停。
7. 树莓派退出时应先发送 `SOFT_BRAKE`，但这不能替代 STM32 看门狗。

必须在架空轮和具备物理急停的条件下分别验证：停止树莓派发送、杀死进程、
拔出 UART、发送损坏帧、接收洪泛、STM32 重启和树莓派重启。只有实测在规定
时间内停车后，软件才可宣称固件看门狗可用。

## 7. 实时调度和队列

- STM32 必须优先处理 UART 接收和电机安全，不得因发送遥测阻塞控制循环。
- `ODOMETRY_IMU` 正常目标为 100 Hz，`SYSTEM_STATUS` 固定 10 Hz；命令回复随
  命令产生。I²C 重试或主循环异常会造成定位帧漏采，上位机通过序号、时间戳和
  `sample_overrun` 识别。
- 发送拥塞时允许丢弃尚未发送的旧 `ODOMETRY_IMU`，保留最新样本；不得积累
  无界队列。`SYSTEM_STATUS` 和 `COMMAND_REPLY` 不得被普通遥测覆盖。
- 树莓派持续排空 UART。接收缓冲区溢出、连续定位遥测超期或系统状态过期均
  视为链路故障，并进入停车/定位降级路径。
- 树莓派真实串口必须独占打开，禁止驾驶与监测进程同时读取；活动运动控制
  更新间隔超过 100 ms 时先发送 `SOFT_BRAKE` 并终止控制，不能在主循环恢复后
  用累计停顿时间一步跳回旧目标。
- 固件高优先级回复队列容量为 8。树莓派持续接收并解码所有消息，不能只在
  发送命令后临时读取一次。发送线程和接收线程共享同一个串口对象与待确认表。
- 轮速发送周期建议 20–50 ms。每周期使用新序号。待确认轮速数量达到 4 或
  连续 100 ms 没有收到任何轮速 `accepted` 时，停止发送非零目标并进入
  `SOFT_BRAKE` 同步流程。
- UART TX 帧由 STM32 保留到发送完成。TX 启动失败或 20 ms stall 后重试原帧。
  `tx_degraded` 置位后，上位机记录链路故障并降低运动许可，不能假定后续回复
  延迟仍处于正常范围。
- 115200 8N1 下，本协议 57-byte 解码定位帧经 COBS 后不超过 59 wire bytes；
  100 Hz 定位遥测约占 5.9 kB/s，给命令、状态和回复保留足够余量。

### 7.1 上位机稳定控制流程

树莓派每次打开串口都执行下面的流程。

1. 启动独立接收循环，持续读取到 `0x00`，完成 COBS、固定长度和 CRC 校验。
2. 创建一个全局 `u16` 命令序号分配器。仓库参考类为
   `raspberry_pi_imu_receiver.CommandEncoder`。
3. 发送一帧 `SOFT_BRAKE`，等待相同序号和类型的 `COMMAND_REPLY accepted`。
   等待期间不发送非零轮速。
4. 进入运动状态后，每 20–50 ms 发送一次当前左右轮目标，每次取新序号。发送
   不等待上一帧回复。
5. 接收循环按 `command_sequence + command_type` 匹配回复。迟到回复只更新链路
   统计，不能让旧目标重新进入发送队列。
6. 收到 `sequence_old`、`reply_queue_full`、连续回复超时或发送循环停顿超过
   100 ms 时，立即停止非零轮速，重新执行第 3 步。
7. 进程正常退出时发送 `SOFT_BRAKE`。无法发送时依靠 STM32 的 300 ms 看门狗
   停车。

轮速循环的核心逻辑如下。

```python
commands = CommandEncoder()

# 打开串口后的安全同步
sequence, frame = commands.soft_brake()
serial.write(frame)
wait_reply(sequence, SOFT_BRAKE, REPLY_ACCEPTED)

while driving:
    sequence, frame = commands.set_wheel_speed(left_mm_s, right_mm_s)
    serial.write(frame)
    pending[(sequence, SET_WHEEL_SPEED)] = monotonic()
    sleep(0.02)  # 50 Hz

    if oldest_unacknowledged_age() >= 0.10 or len(pending) >= 4:
        enter_soft_brake_resync()
```

`wait_reply` 只适用于启动停车、夹爪和查询等低频操作。周期轮速不能逐帧同步
等待 ACK。

### 7.2 `SET_WHEEL_SPEED` 未生效时的排查顺序

先查看同序号的 `COMMAND_REPLY`，再查看最近一帧 `SYSTEM_STATUS`。

| 现象 | 含义 | 上位机动作 |
| --- | --- | --- |
| `result=accepted` | 目标或当前心跳已经接受 | 继续用新序号周期发送，检查目标值和电机故障状态 |
| `result=sequence_old` | 轮速帧属于旧运动序号流 | 丢弃旧帧，发送 `SOFT_BRAKE` 完成同步 |
| `result=emergency_stop_latched` | 急停锁存 | 停止运动发送，等待现场复位 |
| 没有回复，bit 4 为 1 | 回复队列曾满，普通命令可能未执行 | 停止突发发送，持续排空 RX，再做停车同步 |
| 没有回复，bit 6 为 1 | RX 曾溢出、出错或收到非法帧 | 检查 COBS、长度、CRC、串口独占和波特率 |
| `stop_reason=watchdog_timeout` | 300 ms 内没有有效运动心跳 | 先同步停车，再恢复 20–50 Hz 轮速流 |
| `emergency_stop_latched=1` | 固件或通信急停已经锁存 | 不再尝试轮速恢复 |

旧上位机最常见的问题是固定使用一个序号。当前固件兼容连续复用当前序号，原样
重发会刷新看门狗，同序号的新速度也会执行。新实现仍应使用
`CommandEncoder`，这样回复关联、乱序识别和重连过程更清楚。

## 8. 定位消费约定

树莓派按相邻有效帧计算编码器增量和时间差：

```text
delta_left_count  = left_count[n]  - left_count[n-1]
delta_right_count = right_count[n] - right_count[n-1]
dt                = (timestamp_us[n] - timestamp_us[n-1]) / 1_000_000
```

每圈计数、左右轮有效半径、有效轮距、IMU 原始零偏、sensor-to-robot 矩阵、
`gyro_z` 极性和噪声全部来自树莓派运行配置。融合层先按 5.2 节对 sensor-frame
三轴数据应用 bias/scale/cross-axis 和 `sensor_to_robot`，再把矩阵后的机器人
`gyro_z` 及其对应零偏转换为左转为正；`gyro_z_sign` 若保留，只能在这一处
应用一次。之后再推算短时航向；编码器负责平移，并用中心十字视觉
位姿进行低频绝对纠偏。完整三轴陀螺仪和加速度计用于静止、倾斜、碰撞、饱和
和异常运动判断，不直接对平面位置做长期二次积分。

以下任一情况必须中断连续积分，而不是跨越异常拼接轨迹：

- STM32 时间倒退或相邻时间不递增；
- 连续 `sample_overrun` 超过树莓派配置的单周期插值预算；单次异常且双编码器有效
  时可按前后有效陀螺数据插值补偿；
- 遥测序号不满足模 `65536` 的前进关系，或丢帧导致时间间隔超过融合配置上限；
- 任一编码器 `valid` 位清零；
- 左右累计计数出现不符合机械上限的跳变；
- UART 接收溢出或定位遥测过期。

IMU 无效时可按配置短时退化为纯轮式里程计；编码器无效时不得用加速度计二次
积分伪造平面位置。磁力计、四元数或欧拉角若以后经整车验证确有必要，应新增
独立消息类型，而不是改变 `ODOMETRY_IMU` 的固定布局。
