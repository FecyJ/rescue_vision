# 独立电脑端客户端通信协议交接

本文是独立电脑端客户端与树莓派上位机之间的通信协议说明。电脑端计划使用
PyQt 和手柄，但应维护在独立项目中；它**不得安装、导入或复制调用**
`rescue_vision` 的 Python 包，也不读取本仓库的 `runtime.yaml`。

本仓库只向电脑端承诺线级协议、消息 schema、方向、单位和安全语义。当前
车端参考实现位于 `src/rescue_vision/communication/remote.py` 和
`remote_messages.py`，但实现代码不是跨项目 API。若本文与代码不一致，
必须先在双方项目中显式升级协议版本并补互操作测试，不能让客户端跟随内部
Python 类型的变化。

文中的“必须”“不得”是协议要求；“建议”不构成线级兼容要求。

## 1. 范围和版本状态

当前已定义：

- TCP 连接角色、预共享密钥双向认证和会话密钥派生；
- v1 帧格式、逐帧 HMAC-SHA256 完整性校验和双向序号；
- `observe_only` / `debug_control` 权限语义；
- 调试运动命令 v1；
- 调试采集命令 v1；
- 视频、地图、车辆状态和采集状态的 topic 名称。

当前尚未冻结：

- 视频 attributes 的独立版本化 schema；
- 地图快照、车辆状态和采集状态 payload schema；
- 能力发现、权限协商、心跳、请求回执和错误响应消息；
- 车端运动意图到底盘左右轮速度的适配；
- STM32 失联看门狗契约。

因此，独立客户端可以先完成连接、认证、帧编解码和两类控制 payload 的互操作，
但不能把收到任意临时 JSON 后能显示称为地图、车辆状态或采集状态协议完成。

协议版本分三层，互不替代：

| 层 | 当前版本 | 字段 |
| --- | --- | --- |
| 远程帧头 | 1 | header 的 `schema_version` |
| 调试运动 payload | 1 | JSON 的 `schema_version` |
| 调试采集 payload | 1 | JSON 的 `schema_version` |

收到不支持的版本必须关闭当前连接或拒绝该业务消息，不得猜测兼容。

## 2. 部署与连接角色

- 树莓派是 TCP server，通常监听 `0.0.0.0:8765`；
- 电脑端是 TCP client，主动连接树莓派的局域网地址；
- 端口、连接/IO 超时、帧长上限和密钥路径由两端各自项目配置；
- 两端配置文件互相独立，不共享路径或配置类；
- 每个 TCP 连接只对应一个认证会话，断线重连必须重新握手并派生新会话密钥。

参考上限为：

| 参数 | 参考值 |
| --- | ---: |
| 握手超时 | 2000 ms |
| IO 轮询超时 | 100 ms |
| 最大 header | 4096 bytes |
| 最大 payload | 2097152 bytes |
| 控制队列容量 | 32 |
| 观察队列容量 | 2 |

这些是两端需要协调的部署参数，不在握手中交换。任一端实际限制更小时，以
更小值为准。

## 3. 密钥文件解释

两端持有内容相同的预共享密钥（PSK）。兼容当前车端的读取规则为：

1. 以二进制读取整个文件；
2. 去除文件首尾 ASCII/字节空白；
3. 若剩余内容恰好为 64 bytes，尝试按 ASCII 十六进制解码为 32 bytes；
4. 若十六进制解码失败，则把剩余内容当原始密钥；
5. 最终密钥不得少于 32 bytes。

推荐生成 32 bytes 随机密钥并以 64 位小写十六进制保存。密钥不得写入日志、
截图、URL、普通配置字段或版本库。

## 4. 双向认证握手

所有整数和字节串按本节原样处理；字符串标签是下列 ASCII bytes，末尾不含
换行。`HMAC(key, data)` 表示 HMAC-SHA256，输出 32 bytes。

### 4.1 Client Hello

电脑端为每次新连接生成 32 bytes 密码学安全随机数 `client_nonce`：

```text
client_proof = HMAC(
    PSK,
    ASCII("client") || 0x00 || client_nonce
)
```

随后一次完整写出 68 bytes：

```text
offset  size  value
0       4     ASCII "RVC1"
4       32    client_nonce
36      32    client_proof
```

nonce 不得复用或使用时间戳、计数器代替随机数。

### 4.2 Server Hello

车端验证 Client Hello 后生成新的 32 bytes `server_nonce`，返回 68 bytes：

```text
server_proof = HMAC(
    PSK,
    ASCII("server") || 0x00 || client_nonce || server_nonce
)
```

```text
offset  size  value
0       4     ASCII "RVS1"
4       32    server_nonce
36      32    server_proof
```

电脑端必须验证 magic 和 `server_proof`，比较 HMAC 时使用常量时间比较。
失败时立即关闭 TCP，不发送业务帧。

### 4.3 会话密钥派生

双方验证完成后计算：

```text
session_material = HMAC(
    PSK,
    ASCII("session") || 0x00 || client_nonce || server_nonce
)

client_to_server_key = HMAC(
    session_material,
    ASCII("client-to-server")
)

server_to_client_key = HMAC(
    session_material,
    ASCII("server-to-client")
)
```

电脑发往车端的每一帧使用 `client_to_server_key`；车端发往电脑的每一帧使用
`server_to_client_key`。不得混用方向密钥。握手没有第三个确认包。

## 5. v1 帧格式

TCP 是字节流，接收方必须处理拆包和粘包，不能假定一次 `recv()` 对应一帧。
每帧结构：

```text
┌──────────── 12-byte prefix ────────────┬──── header ────┬── payload ──┬── tag ──┐
│ magic:4 │ header_len:u32 │ payload_len:u32 │ header_len B │ payload_len B │ 32 B │
└────────────────────────────────────────┴────────────────┴─────────────┴────────┘
```

prefix 使用网络字节序（big-endian）：

- magic：ASCII `RVM1`；
- `header_len`：无符号 32 位整数；
- `payload_len`：无符号 32 位整数。

认证标签：

```text
tag = HMAC(
    direction_session_key,
    prefix || header_bytes || payload_bytes
)
```

tag 固定为 32 bytes。接收方必须先检查声明长度不超过本地上限，收齐整帧后
验证 tag，再解析 header 或业务 payload。HMAC 失败、magic 错误、长度越界
或 header 非法都必须终止当前连接。

### 5.1 Header JSON

`header_bytes` 是 UTF-8 JSON object，键必须恰好为：

```json
{
  "schema_version": 1,
  "stream": "control",
  "topic": "control/debug/motion",
  "content_type": "application/json",
  "sequence": 0,
  "sender_timestamp_ns": 123456789,
  "attributes": {}
}
```

字段约束：

| 字段 | 类型与约束 |
| --- | --- |
| `schema_version` | integer，必须为 `1` |
| `stream` | `"control"` 或 `"observation"` |
| `topic` | 去除首尾空白后非空，最多 128 UTF-8 bytes |
| `content_type` | 去除首尾空白后非空，最多 128 UTF-8 bytes |
| `sequence` | 非负 integer，bool 不算 integer |
| `sender_timestamp_ns` | 发送端单调时钟纳秒，非负 integer |
| `attributes` | JSON object；键非空且最多 64 UTF-8 bytes |

attribute 值只允许 string、integer、有限浮点数、boolean 或 null，不允许
数组、嵌套 object、NaN 或 Infinity。

发送端为了稳定互操作和测试向量，应使用：

- 键名按字典序排序；
- `,` 和 `:` 后无多余空白；
- 非 ASCII 字符使用 JSON `\uXXXX` 转义；
- 不输出 NaN/Infinity。

接收端不应依赖键顺序或空白形式，但必须要求键集合完全一致。HMAC 始终基于
线上收到的原始 header bytes，不得反序列化再序列化后验证。

### 5.2 序号

每个方向各维护一个序号：

- 新认证连接从 `0` 开始；
- 每发送一帧加 `1`；
- `control` 和 `observation` 共享该方向的同一个序号空间；
- 接收方要求严格连续，不允许重复、倒退或跳号；
- 断线重连并完成新握手后重新从 `0` 开始。

应用层观察队列可以丢旧帧，所以 GUI 最终看到的消息序号可能跳号；线级解码器
在入队前仍必须验证线路序号连续。

## 6. 权限模型

权限模式：

- `observe_only`：电脑只能接收 observation，不得发送 control；
- `debug_control`：赛外调试时允许电脑发送下述 control。

当前 v1 握手**不协商也不回传权限模式**。两端各自通过部署配置选择模式，
车端配置是最终权威：

- 车端 `observe_only` 收到任何 `stream="control"` 帧会终止连接；
- 电脑端也必须在本地 `observe_only` 时禁止构造和发送 control；
- GUI 禁用按钮不算协议保护，底层发送入口仍要检查权限；
- 正式比赛必须使用 `observe_only`，不得通过电脑遥控。

若后续需要在 GUI 显示车端实际权限，应新增版本化能力/会话状态消息，不能
把本地配置显示成已由车端确认。

## 7. Topic 表

| stream | topic | 方向 | payload 状态 |
| --- | --- | --- | --- |
| control | `control/debug/motion` | 电脑 → 车端 | v1 已定义 |
| control | `control/debug/capture` | 电脑 → 车端 | v1 已定义 |
| observation | `observation/video/frame` | 车端 → 电脑 | topic 已保留；严格 attributes 待冻结 |
| observation | `observation/map/snapshot` | 车端 → 电脑 | 仅保留，payload 待冻结 |
| observation | `observation/vehicle/state` | 车端 → 电脑 | 仅保留，payload 待冻结 |
| observation | `observation/capture/status` | 车端 → 电脑 | 仅保留，payload 待冻结 |

未知 topic 不能按已知 schema 解析。客户端可以记录非敏感元数据并忽略未知
observation；未知 control 在车端必须拒绝。

## 8. 调试运动命令 v1

帧要求：

```text
stream       = "control"
topic        = "control/debug/motion"
content_type = "application/json"
attributes   = {}
```

payload 是 UTF-8 JSON object，键必须恰好为：

```json
{
  "schema_version": 1,
  "command_id": "drive-000001",
  "issued_timestamp_ns": 123456789,
  "valid_for_ms": 250,
  "deadman_enabled": true,
  "control_mode": "twist",
  "linear_velocity_m_s": 0.2,
  "angular_velocity_rad_s": -0.4,
  "target_heading_rad": null,
  "heading_reference": null
}
```

字段约束：

| 字段 | 类型与约束 |
| --- | --- |
| `schema_version` | integer，必须为 `1` |
| `command_id` | 去除首尾空白后非空，最多 128 UTF-8 bytes |
| `issued_timestamp_ns` | 电脑单调时钟纳秒，非负 integer |
| `valid_for_ms` | integer，范围 `[1, 5000]` |
| `deadman_enabled` | boolean |
| `control_mode` | `"twist"` 或 `"target_heading"` |
| `linear_velocity_m_s` | 有限 number；正为前进，负为后退 |
| `angular_velocity_rad_s` | 有限 number；逆时针为正 |
| `target_heading_rad` | null 或 `[-π, π]` 内有限 number |
| `heading_reference` | null、`"field"` 或 `"session_start"` |

组合约束：

- `twist`：`target_heading_rad` 和 `heading_reference` 必须均为 null；
- `target_heading`：两个 heading 字段必须均非 null，且
  `angular_velocity_rad_s` 必须为 `0.0`；
- `deadman_enabled=false`：线速度、角速度必须均为 `0.0`，两个 heading
  字段必须均为 null；
- 车端从完整收到该帧的本机单调时间起算 `valid_for_ms`，不能比较电脑和
  树莓派的单调时钟；
- 过期、重复 `command_id`、死手撤销或输入链路故障必须进入停车路径。

首版客户端只能发送 `twist`。在 IMU/定位和车端朝向控制器完成前，
`target_heading` 虽有预留 schema，也不得开放给操作者。

手柄只是命令数据源，不改变协议：轴映射、死区、曲线、速度上限、死手按键
和采样新鲜度由独立客户端本地配置；最终只生成上述标准 JSON。松开死手、
手柄断开、采样过期、窗口失焦、连接异常和程序退出时，客户端必须清零本地
目标并尽力发送 `deadman_enabled=false` 的零速度命令。重连后不得恢复旧速度。

发送成功仅表示电脑写入/排队了协议帧，不表示车端或 STM32 已执行。v1 尚无
运动回执，后续车辆状态 schema 应回显最近接收和应用的 `command_id`。

## 9. 调试采集命令 v1

帧要求：

```text
stream       = "control"
topic        = "control/debug/capture"
content_type = "application/json"
attributes   = {}
```

payload 键必须恰好为：

```json
{
  "schema_version": 1,
  "request_id": "capture-000001",
  "issued_timestamp_ns": 123456789,
  "action": "start",
  "label": null,
  "session_tags": {
    "lighting": "indoor_bright",
    "surface": "competition_like"
  }
}
```

字段约束：

| 字段 | 类型与约束 |
| --- | --- |
| `schema_version` | integer，必须为 `1` |
| `request_id` | 去除首尾空白后非空，最多 128 UTF-8 bytes |
| `issued_timestamp_ns` | 电脑单调时钟纳秒，非负 integer |
| `action` | `"start"`、`"stop"`、`"snapshot"` 或 `"mark_event"` |
| `label` | null 或非空 string，最多 128 UTF-8 bytes |
| `session_tags` | string→string object；键和值均非空且最多 128 UTF-8 bytes |

组合约束：

- `start`：`label` 必须为 null，可带 `session_tags`；
- `stop`：`label` 必须为 null，`session_tags` 必须为空；
- `mark_event`：`label` 必须非 null，`session_tags` 必须为空；
- `snapshot`：`session_tags` 必须为空，`label` 可为 null 或非空标识；
- payload 不得包含电脑指定的输出路径。

车端从自己的运行配置决定记录根目录，并执行不覆盖和完整性规则。发送请求
不代表采集成功；在 `observation/capture/status` schema 冻结前，独立客户端
只能显示“请求已发送”，不能显示“录制已开始”。

## 10. 观察消息

### 10.1 视频帧

已保留：

```text
stream       = "observation"
topic        = "observation/video/frame"
content_type = "image/jpeg"（当前建议）
payload      = JPEG bytes
```

当前车端示例约定 attributes 包含：

- `frame_sequence`
- `timestamp_ns`
- `width`
- `height`
- `coordinate_system`

这些字段尚无独立 schema 版本和严格解析类，因此当前属于**预备约定**，不是
已冻结互操作协议。车端发布器实现前，双方应先冻结字段类型、尺寸上限、允许
坐标系、时间语义和 attributes 中的 schema 版本，并在两个项目各自添加
同一组 JPEG/坏帧/超限帧测试向量。

观察消费必须丢旧保新，不能因电脑显示或解码慢而反压车端相机。GUI 看到帧号
跳变应统计为丢帧，不应直接断线。

### 10.2 地图、车辆与采集状态

下列 topic 目前只有名字，没有可供独立客户端实现的 payload 合同：

- `observation/map/snapshot`
- `observation/vehicle/state`
- `observation/capture/status`

不得根据车端临时 JSON 猜字段。每个 schema 至少应先定义：

- 独立 `schema_version`；
- 精确键集合、类型、单位、枚举和 null 语义；
- 坐标系和时间基准；
- 数据新鲜度、未知/不可用和错误状态；
- 大小上限及未知版本处理；
- 双方共用的语言无关 JSON/二进制测试向量。

车辆状态还应包含控制是否就绪、急停/看门狗状态、目标与实测轮速，以及最近
接收/应用的 `command_id`。采集状态应关联 `request_id`，包含
`recording_id`、状态、帧数、丢帧、磁盘告警和失败/停止原因。

## 11. 队列与故障语义

- control 必须可靠排队；队列满是故障，不能丢旧或覆盖；
- observation 使用有界队列并丢旧保新；
- 控制始终优先于等待发送的 observation；
- TCP 断开、HMAC 失败、序号错误、非法帧或控制队列溢出后，不得继续使用
  当前会话；
- 重连必须新建 TCP、重新认证、重置双向线路序号；
- 自动重连只能恢复观察，不能自动恢复非零控制；
- 认证失败和配置错误不得高速无限重试。

当前协议没有线上错误回复。连接被车端关闭时，电脑端只能把它视为会话失败，
记录本地非敏感诊断并重新建立连接；不能从断开本身推断具体错误原因。

## 12. 与底盘 UART 的隔离

电脑端永远不发送 Rescue Car UART 字符串，也不计算左右轮速度。链路边界为：

```text
独立 PyQt/手柄客户端
    └─ 本文协议：车体线速度/角速度意图
          └─ 树莓派车端适配（待实现）
                └─ UART：m<L>,<R> / b<L>,<R> / e / v
                      └─ STM32
```

根据《Rescue Car v2.0 — 电控代码使用说明书》，UART 为 115200、8N1、CRLF
结尾，包含设置双轮速度、柔刹、急停、查询、约 10 Hz 遥测及 `OK`/`ERR`
回复。这些均属于树莓派车端内部协议，不得泄漏为电脑端依赖。

说明书目前没有明确“超过多久未收到命令即停车”的固件契约。在 STM32 增加
并实测失联看门狗前，只允许架空轮或有物理急停、人员全程监督的低速调试。
电脑端死手、TCP 断开或尽力发送停车帧不能替代固件看门狗。

## 13. 安全与保密

当前协议保证持有同一 PSK 的双方认证和帧完整性，但**不加密** header 或
payload。它只能部署在团队受控局域网或额外 VPN 内，不得直接暴露公网。

正式比赛：

- 两端必须配置 `observe_only`；
- 电脑只接收允许的图像、地图和状态；
- 不得通过手柄、键盘或其他方式遥控；
- GUI 是否隐藏按钮不能替代车端权限强制。

调试控制：

- 只用于赛外采集或明确允许的调试；
- 手柄必须使用持续按压的死手；
- 电脑、树莓派适配器和 STM32 各自独立限速；
- 任一层数据过期或故障都应保守停车；
- 急停恢复必须由车端/固件显式确认，远程重连不能自动解除。

## 14. 跨项目互操作验收

双方项目不共享 Python 类或测试代码，但应共享本协议文档和语言无关测试
向量。合入独立客户端前至少验证：

1. 固定 PSK、client nonce、server nonce 下，双方生成相同三个派生密钥；
2. 固定 header/payload 下，双方生成完全相同的 prefix 和 HMAC tag；
3. 客户端能处理一帧拆成任意 TCP 分片以及多帧粘在一次读取中；
4. 错误 magic、超限长度、错误 tag、缺失/额外 header 键和序号跳变均失败；
5. 两类 v1 control JSON 的合法样例互通，所有组合约束非法样例均拒绝；
6. `observe_only` 车端收到 control 后终止会话；
7. observation 突发不造成无界内存增长，control 不被观察流饿死；
8. 断线重连后 nonce、会话密钥和双向序号均更新；
9. 手柄松开、拔出、窗口失焦、网络断开和应用退出不会在重连后恢复旧速度；
10. 错误密钥、树莓派未启动、网络抖动和服务端重启均能安全清理。

当前仓库的：

```bash
python manual_tests/remote_link.py \
  --config configs/runtime.yaml \
  --timeout-seconds 10
```

只验证本仓库参考实现之间的一条认证 observation 往返，不能证明独立客户端
兼容。独立客户端项目应提供自己的协议实现和测试；最终必须以电脑与树莓派
两个独立进程、互不导入对方代码的双机测试作为交接完成证据。

## 15. v1 固定测试向量

本节十六进制均为连续 bytes，不包含空格或换行。它只验证握手、密钥派生和
帧封装；示例 payload `{}` 不是合法运动业务消息。

输入：

```text
PSK
000102030405060708090a0b0c0d0e0f101112131415161718191a1b1c1d1e1f

client_nonce
202122232425262728292a2b2c2d2e2f303132333435363738393a3b3c3d3e3f

server_nonce
404142434445464748494a4b4c4d4e4f505152535455565758595a5b5c5d5e5f
```

期望握手和派生结果：

```text
client_proof
c5884d8c70aa9d51afe0f3dec5bd7d36adb057dae198ee74bd0ac04c5868b0c4

server_proof
595efe40137798369f16579ea187b9cf8fb65b46717be2c111cdf444f04ba36d

session_material
c30dc36d1ec5df267b50a7b89f92d8548ec426aff455de78b056a0fc92fb6cdc

client_to_server_key
020f421748bae486f55d0ac0c48dd96858c5995d2d8ee16f081aa13e372c3380

server_to_client_key
f01218dea85a9b3726ddc285fd9a1011354a1792cd5da056ea1a9ae5b21742e3
```

使用 `client_to_server_key` 编码 sequence 0。原始 header 是下列单行 UTF-8，
长度 165 bytes：

```json
{"attributes":{},"content_type":"application/json","schema_version":1,"sender_timestamp_ns":123456789,"sequence":0,"stream":"control","topic":"control/debug/motion"}
```

payload 为 `{}` 加 LF：

```text
payload_hex = 7b7d0a
prefix_hex  = 52564d31000000a500000003
tag_hex     = 1e6c1a38607039449873e86c8c185ed57fd13fc081432985d3a2171893770a79
```

客户端应先让这些固定向量通过，再与真实树莓派做随机 nonce 和业务消息互操作。
