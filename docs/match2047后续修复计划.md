## 2. 已确认根因

1. **对准预算不匹配真实运动。** `GripperWidthPickupSequence._alignment_turn_complete()` 原先即使有 IMU，也把每次转动截断在 `min(alignment_continue_ns, 500 ms)`；正式配置为 400 ms。0.5 rad 左右的必要转角在 0.35 rad/s 下根本转不完，却会用掉两次机会。
2. **修正帧可能仍来自转动结束之前。** 原实现只比较帧是否不同，迟到图像可提前消耗第二次转动机会。
3. **失败重入条件过松。** `_target_attempt_blocked()` 原先允许仅旋转 0.20 rad 或机器人相对坐标变化就解除同区域失败；搜索与对准反向转动能互相解除约束。0:42–1:05 主要反复尝试黑块，不应把全部扭摆归因于安全区绿块。
4. **橙块行程使用投影包络最远端。** 原公式 `x0 + depth - orange_target_final_x_mm` 等于 `x1 - endpoint`；颜色上表面投影纵向拉长会被算作真实前进距离。可靠 K0 是底面中心，不应由顶部投影替代。
5. **夹爪扫掠检查偏短。** 原走廊只到 `corridor_start_x_mm + forward_distance`，没有包含实际夹爪末端前伸距离；且蓝块只按 K0 点检查，可能漏掉中心在线外但实体被碰到的情况。
6. **补夹并非完全未触发。** 2047 日志约 300.82 秒已进入补夹近场 session 52，约 301 秒因 `alignment_attempt_budget_exhausted` 返回运输。还存在固定 TRANSPORT 窄走廊提前排除宽度抓取候选的问题。
7. **解团入口会先转走再找回来。** 已确认抓取受阻后，部分路径返回普通 search_cluster 并立即输出搜索旋转；首次在约 7–10 秒进入停稳确认但未拿到可执行核心，随后转圈，到约 17 秒才执行。最后一团在约 350 秒受阻后转圈，到约 357 秒解团。
8. **后退抵消了整个接近空程。** 原实际后退为 `实际前进距离 + 净空 + 刹车余量`，没有区分接触前空程与穿入深度，容易退得过远。
9. **unknown 主要由 HSV 二次分类制造。** 模型只有四种任务目标，运行时因颜色证据不足/混杂产生第五类，并进一步造成候选失效。用户明确要求删除任务目标 unknown 类别及其定义和门禁。

## 3. 已写入工作区的改动（仍需完成审查和验证）

### 3.1 四类模型语义迁移

- `perception/types.py`：删除 `TargetClass.UNKNOWN` 和 `ClassProbabilities.unknown`；top-1 的条件类别分布为四类 one-hot，检测置信度仍独立保存。ROI 没有颜色证据时 `candidate_class=None`，不是新增任务类别。
- `perception/detector.py`：模型类别为权威；HSV 按模型类别提取掩码，不覆盖模型类别。删除 `unknown_override_confidence_threshold` 参数。
- `perception/color_segmentation.py`：增加按指定模型类别取掩码；无证据不输出任务 unknown。
- `tracking/tracker.py`、`world/model.py`、可视化、旧目标几何模块及 app 调用：迁移四类分布，删除任务 unknown 分支及 `unknown_suspect_threshold`。
- `GraspTargetTracker`：去掉 HSV 质量噪声造成的疑似/恢复计数；删除 `supply_recovery_frames` 配置和状态。明确蓝色仍不可作为物资。
- `measure_target_envelope()`：只要有对应模型类别的非空有效掩码，即可测量，不再因 HSV 分类状态非 ACCEPTED 拒绝。
- 配置与若干测试已同步；**专项文档、全部 schema/示例、其它测试尚未完成全面检查。**
- `TeamColor.UNKNOWN`、安全区身份不明、通信/设备状态的 UNKNOWN 不是任务目标类别，未删除。不要机械删除所有字符串 unknown。

### 3.2 对准与同目标重入

- `app/gripper_width_sequence.py`：有 IMU 时按实际转角完成转动，不受旧图续转 400 ms 截断；无运动历史仍执行有界短动作。
- 最多两次转动；按实际请求角度增加 `alignment_motion_allowance_ns`，并被 match 外层提交总预算消费。
- 转动完成记录 `_alignment_completed_ns`；下一次修正必须使用采集时间晚于它的图像。
- 未完成转动时不因延迟图像符号变化立即反向；实际可达零角度计划仍可进入制动复核。
- `_minimum_reachable_angle()` 不再停在可达域数值边界，若可行则进入边界内侧 2°。
- `_target_attempt_blocked()` 不再把单纯旋转或相对坐标变化作为重入条件，改看场地目标位置或机器人平移变化。
- **待审查：**失败记录中主 tracker ID 与近场局部 ID 仍可能混用；`_failure_region_points()` 已允许使用 preview_plan，但 `_remember_near_field_failure()` 仍优先 `_selected_target()`，应核对物理核心绑定是否完全正确。

### 3.3 橙块与真实扫掠

- 橙块前进改为 `K0 在计划方向的前向坐标 - orange_target_final_x_mm`；默认和仓库运行 YAML 的橙色底面中心终点改为 142 mm。
- **142 mm 是待真机校准的中心终点，不是已经验证的最优值。** 还需用两段录像对应计划确认左右开度、制动余量、橙块不同朝向的实际留存；不要声称已经解决误揽蓝块。
- `NearFieldGraspSelector` 新增必需参数 `target_geometry: TargetGroundGeometryConfig`，生产装配和已发现的直接测试构造点已更新。
- `_regions()` 用左右实际舵机开度反解夹爪末端 x，扫掠终点包含末端前伸距离。
- 蓝块用既有物理尺寸配置计算包围半径，检查实体与扫掠距离；不再仅看中心点。
- 绿黑的蓝色“仅仅是侧邻就否决”门禁已在近场和 match 入口移除，由实际扫掠检查替代；橙色单独转运/隔离仍保留。
- **待审查：**日志 CandidateGeometry 中 corridor_end 仍按旧公式计算，可能与实际 plan.regions 不一致，应统一诊断与执行几何。相关旧注释也尚未更新。

### 3.4 补夹、安全区与解团

- 补夹候选不再通过 `_transport_group_size()` 的固定窄走廊预筛，改交近场宽度规划。
- `MatchSequence._ground_in_safe_zone()` 和安全区 bbox 用于排除安全区内已交付物资候选；
  `grasp_excluded_observation_indices()` 在送入近场 worker 前标记排除项，完整 `targets` 仍保留，
  蓝色危险证据始终不删除。`GraspPreparationSession` 在同帧去重、锁定 ID 映射后重新绑定索引，
  `MatchSequence._near_field_plan_has_delivered_member()` 在消费层按当前位姿再次复核。
- 补夹扫描按 `target_final_x_mm + range_hysteresis_mm` 排除爪内物资，不把排除项计入新增容量；
  若该物资或蓝块实体仍落入真实扫掠，计划以 `blocked_target` 等明确原因拒绝，而不是删除障碍。
- 已知非静态边界的抓取受阻直接进入 `BREAKUP_SETTLE`，不先发搜索转速。
- 解团观察增加朝接触计划航向的 IMU 有界对准，再用真实停稳后的当前帧复核，不绕一周。
- 后退改为退出实际穿入深度加净空/刹车余量，不抵消全部接近空程；运行时按实际前进与计划空程差计算。
- 正式 `runtime.match.yaml` 解团前进速度 0.4→0.6 m/s、后退速度 0.3→0.45 m/s，穿入上限 240→360 mm。**局部团跨度和安全检查仍限制实际距离，不能声称实际行程已统一放大 1.5 倍。**
- 补夹候选重复选择/计数与障碍保留已由 worker 排除索引、消费层复核和容量条件共同处理；
  当前只承诺无硬件回归，带载转向、二次开爪留存和真实三块容量仍未验收。
