# 规则状态机设计

本文是规则状态机的权威对接设计，回答状态机消费什么、维护什么、输出什么，以及每条比赛规则如何转化为确定行为。官方规则到工程语义的摘要仍以[赛题约束与视觉需求](赛题约束与视觉需求.md)为准；本文不重新定义目标外观、场地尺寸或评分。

适用范围是 2027 智能救援初赛。决赛现场规则变化应通过配置和新的规则事件适配，不在检测器、跟踪器或规划器中散落条件分支。

## 1. 设计目标与边界

状态机负责：

- 维护本轮是否开始、首个有效普通物资是否完成、有效交付计数和终止原因；
- 在动作发出前检查转运组合、危险目标、目标数量和目的区域；
- 处理视觉过期、疑似危险、对方安全区、长时间停止、对手接触等降级；
- 只输出 `SEARCH`、`APPROACH`、`PUSH`、`AVOID`、`DELIVER`、`STOP` 六类抽象动作；
- 产生可记录、可回放的确定决策，不直接控制电机。

状态机不负责：

- 从图像推断目标、区域或接触关系；
- 根据像素距离判断目标是否已经进入安全区；
- 生成路径、速度或串口报文；
- 猜测裁判是否最终计分；
- 在信息缺失时把 `unknown` 当作普通物资。

上游必须先把连续感知转成带时间和不确定性的世界快照；机械接触、目标越界和完全进入区域等事实由世界模型、接触传感器或后续融合模块形成显式证据。状态机只消费这些证据。

## 2. 为什么使用复合状态

“首个只能是一个普通物资”是跨越搜索、接近、推动和交付全过程的任务阶段；`SEARCH`、`PUSH` 等是短时活动。把两者做成一个枚举会产生 `FIRST_SEARCH`、`FIRST_PUSH`、`GENERAL_SEARCH`、`GENERAL_PUSH` 等重复状态，并容易遗漏安全转移。

因此完整状态由三个正交部分组成：

| 维度 | 值 | 作用 |
| --- | --- | --- |
| `MissionPhase` | `WAIT_START`、`FIRST_NORMAL_REQUIRED`、`GENERAL_RESCUE`、`ENDED` | 保存不可逆的任务历史 |
| `ActivityState` | `IDLE`、`SEARCHING`、`APPROACHING`、`PUSHING`、`VERIFYING_DELIVERY`、`AVOIDING`、`SAFETY_HOLD`、`STOPPED` | 描述当前短时行为 |
| `TerminationReason` | 无或某个明确原因 | 记录本轮为何不可恢复地结束 |

例如“首个普通物资阶段正在避让疑似危险目标”表示为：

```text
phase=FIRST_NORMAL_REQUIRED
activity=AVOIDING
termination_reason=None
```

安全保持与终止必须区分：

- `SAFETY_HOLD` 是信息不足造成的可恢复停止，例如视觉暂时过期、正在推动的目标短时丢失；
- `ENDED + STOPPED` 是规则已经被违反或出现不可恢复风险，例如危险目标进入安全区、伤员混运、主动攻击。

恢复只允许由新的可信证据触发，不能靠超时自动假定风险消失。

## 3. 输入契约

一次 `step()` 使用同一 `timestamp_ns` 下的以下输入。时间均为应用单调时钟纳秒，不得混用系统墙上时间。

### 3.1 `WorldSnapshot`

世界模型提供：

| 字段 | 含义 |
| --- | --- |
| `timestamp_ns` | 快照生成时间 |
| `visual_timestamp_ns` | 最近一次视觉帧时间，包括“本帧无目标”的有效观测 |
| `targets` | 带稳定 `track_id`、类别概率、置信度、位置和跟踪状态的动态目标 |
| `regions` | 己方物资区、己方伤员区、对方安全区和场界等静态区域 |
| `opponent_occupancies` | 带置信度与更新时间的对手占据区域 |
| `robot_field_point` | 可选机器人场地坐标；定位未接入时为 `None` |
| `uncertainties` | 视觉过期、缺地面点、未知目标、对手信息过期等显式不确定性 |

状态机不得读取检测框或重新做类别阈值判断。危险语义由世界目标统一给出：

- `CONFIRMED`：跨帧证据支持危险类别；
- `SUSPECTED`：未知类别、低置信或历史危险证据尚未解除；
- `CLEAR`：当前证据足以按非危险目标处理。

### 3.2 `TransportStatus`

转运状态描述机器人此刻正在持续接触/推动的目标：

| 字段 | 含义 |
| --- | --- |
| `engaged_track_ids` | 去重后的稳定目标 ID；空元组表示未转运 |
| `contact_started_ns` | 本次接触开始时间；未接触时为 `None` |

只要目标仍被机器人共同推动，就必须包含在该集合中。短时遮挡时可由跟踪器保持 ID；若 ID 无法在世界快照中解析，状态机进入 `SAFETY_HOLD`，不得假定目标已经离开。

禁止用检测框数量直接替代正在转运的数量。接触集合最终应由视觉近场关系、机构状态或接触传感器融合产生。

### 3.3 `DeliveryEvidence`

交付证据是一次性事件，包含：

| 字段 | 含义 |
| --- | --- |
| `delivery_id` | 本轮唯一且单调不可复用的事件 ID |
| `track_ids` | 本次进入/越界的目标 ID |
| `destination` | `OWN_MATERIAL`、`OWN_INJURED`、`OPPONENT_SAFE` 或 `OUT_OF_FIELD` |
| `fully_entered` | 是否全部进入区域；己方得分只接受 `True` |

区域边界的“部分进入”和“全部进入”判断属于世界模型。重复提交同一个 `delivery_id` 必须幂等，不能重复增加计数或改变阶段。

### 3.4 `SafetySignals`

非视觉安全信号必须显式提供：

- `last_motion_timestamp_ns`：最近一次有效运动时间；
- `opponent_contact_since_ns`：与对手连续接触的开始时间，未接触为 `None`；
- `active_attack`：是否主动向对方发起攻击；
- `lost_control`：是否失控；
- `safety_accident`：起火、破坏场地等事故；
- `human_touched_after_start`：启动后人员再次接触机器人或电脑；
- `target_carried_on_robot`：是否抓取或把目标放在机器人上；
- `external_stop_requested`：裁判、急停或应用请求停止。

这些信号暂时可由合成事件或 mock 注入，机械、电控完成后替换提供者，不修改状态机规则。

## 4. 输出契约

每次 `step()` 返回一个不可变 `MissionDecision`：

| 字段 | 含义 |
| --- | --- |
| `timestamp_ns` | 决策时间 |
| `phase` / `activity` | 决策后的复合状态 |
| `action` | 六种抽象动作之一 |
| `target_track_id` | `APPROACH`、`PUSH`、`DELIVER` 的可选目标 |
| `reason` | 稳定、可记录的机器可读原因 |
| `terminal` | 本轮是否已不可恢复地结束 |
| `termination_reason` | 终止时的明确规则原因 |

动作语义：

| 动作 | 下游职责 |
| --- | --- |
| `SEARCH` | 规划搜索覆盖或原地观察，不假定存在目标 |
| `APPROACH` | 接近指定目标并保持危险/对手安全裕量 |
| `PUSH` | 继续推动已验证的目标组合 |
| `AVOID` | 离开对方安全区、对手占据或疑似危险区域 |
| `DELIVER` | 朝状态机允许的己方分区完成交付 |
| `STOP` | 输出零运动意图；终止态还必须等待人工复位 |

状态机不输出左右轮速度。规划器必须再次执行碰撞和场界约束，但不得推翻状态机的 `STOP` 或把被禁止的目标加入路径。

## 5. 决策优先级

每次 `step()` 必须按以下顺序短路，靠后的收益行为不能覆盖靠前的安全行为：

1. 已终止、外部停止、事故、失控、人员触碰、抓取/载运、主动攻击；
2. 危险目标已经进入安全区或离场；
3. 超量、伤员混运、危险转运等当前转运组合违规；
4. 运行满 180 秒或停止运动达到 15 秒；
5. 视觉过期、转运目标丢失等信息不足；
6. 机器人进入对方安全区、对手持续接触或路径附近存在危险/疑似危险；
7. 一次性交付事件验证；
8. 当前合法转运的继续推动或交付；
9. 合法候选目标的选择和接近；
10. 无候选时搜索。

这保证“看见高分伤员”永远不能覆盖“视觉已过期”或“正在误送危险目标”。

## 6. 规则矩阵

### 6.1 直接终止

| 条件 | `TerminationReason` | 依据与处理 |
| --- | --- | --- |
| 危险目标进入任一安全区 | `DANGER_IN_SAFE_ZONE` | 立即 `STOP` |
| 危险目标离开场地 | `DANGER_OUT_OF_FIELD` | 立即 `STOP` |
| 首次己方交付不是恰好 1 个普通物资进入物资区 | `INVALID_FIRST_DELIVERY` | 本次无效，立即 `STOP` |
| 一次转运数量超过 3 | `TOO_MANY_TARGETS` | 本次无效，立即 `STOP` |
| 转运伤员时总数不等于 1 | `INJURED_MIXED_TRANSPORT` | 本次无效，立即 `STOP` |
| 主动攻击 | `ACTIVE_ATTACK` | 立即 `STOP` |
| 抓取或把目标放在机器人上 | `ILLEGAL_CARRY` | 立即 `STOP` |
| 事故、失控、启动后再次接触 | 对应安全原因 | 立即 `STOP` |
| 15 秒无有效运动 | `NO_MOTION_TIMEOUT` | 立即 `STOP` |
| 180 秒到时 | `MATCH_TIMEOUT` | 立即 `STOP` |

“已确认危险目标正在被推动但尚未进区/出场”虽然官方终止条件尚未发生，软件仍采用保守 `DANGER_ENGAGED` 终止，防止下一控制周期造成不可逆后果。这是项目安全策略，不伪装成裁判已经判罚。

### 6.2 可恢复降级

| 条件 | 活动/动作 | 恢复条件 |
| --- | --- | --- |
| 视觉年龄超过配置上限 | `SAFETY_HOLD / STOP` | 新鲜世界快照到达 |
| 转运中的 track ID 丢失 | `SAFETY_HOLD / STOP` | 同一 ID 恢复，或上游明确结束接触 |
| 转运目标为疑似危险 | `SAFETY_HOLD / STOP` | 目标变为 `CLEAR`，或接触明确解除 |
| 未定位且需要判断对方区/交付区 | `SAFETY_HOLD / STOP` | 提供机器人/目标场地证据 |
| 对手连续接触满 10 秒 | `AVOIDING / STOP` | 机构先停止，由上游确认分开并清除接触计时 |
| 机器人进入对方安全区 | `AVOIDING / AVOID` | 离开该区域 |
| 路径邻域存在危险/疑似危险或对手占据 | `AVOIDING / AVOID` | 风险区域解除或规划出安全路线 |

对手接触满 10 秒时官方会强制分开并放回出发区，因此状态机不自行猜测已经被移动；在收到新的位置和接触解除证据前保持停止。

### 6.3 交付结果

| 目的地与组合 | 结果 |
| --- | --- |
| 首次：1 个普通物资，全部进入己方物资区 | 首次阶段完成，进入 `GENERAL_RESCUE` |
| 首次：其它己方交付 | `INVALID_FIRST_DELIVERY`，终止 |
| 后续：1–3 个普通/核心物资进入己方物资区 | 记录有效交付，继续一般救援 |
| 后续：1 个伤员进入己方伤员区 | 记录有效交付，继续一般救援 |
| 物资进入己方伤员区或伤员进入己方物资区 | 记录错区，目标按裁判流程回中心；不增加有效计数 |
| 非危险目标进入对方安全区 | 记录对方受益，清除本次转运并优先撤离 |
| 非危险目标离场 | 记录本方扣分风险，清除本次转运并停止/重新评估 |
| 仅部分进入己方区 | 不视为有效交付，保持 `VERIFYING_DELIVERY` |
| 重复 `delivery_id` | 返回与首次处理一致的当前状态，不重复计数 |

普通/核心物资可以混合，但总数不得超过 3；伤员不能与任何其它目标混合。危险目标不能成为合法候选。

## 7. 正常状态流

```text
WAIT_START / IDLE
        │ start
        ▼
FIRST_NORMAL_REQUIRED / SEARCHING
        │ 选择已确认普通物资
        ▼
FIRST_NORMAL_REQUIRED / APPROACHING
        │ 接触集合恰好为该目标
        ▼
FIRST_NORMAL_REQUIRED / PUSHING
        │ 到达己方物资区入口
        ▼
FIRST_NORMAL_REQUIRED / VERIFYING_DELIVERY
        │ 全部进入且 delivery_id 首次出现
        ▼
GENERAL_RESCUE / SEARCHING
        │
        ├─ 物资/核心 1–3 个 → APPROACHING → PUSHING → VERIFYING_DELIVERY
        ├─ 伤员恰好 1 个  → APPROACHING → PUSHING → VERIFYING_DELIVERY
        ├─ 风险出现       → AVOIDING 或 SAFETY_HOLD
        └─ 终止条件       → ENDED / STOPPED
```

状态机不要求按固定类别顺序完成后续任务。默认目标优先级和危险避让距离来自运行配置，决赛可替换。

## 8. 候选选择与不确定性

候选目标必须同时满足：

1. 跟踪状态已确认且未过期；
2. 世界目标危险状态为 `CLEAR`；
3. 有当前机器人地面系位置，能够交给接近/推动规划；
4. 首次阶段仅允许 `GREEN_SUPPLY`；
5. 一般阶段允许普通、核心或伤员；
6. 不位于对手占据、疑似危险膨胀区或已完成区域；
7. 类别、位置或接触数量存在冲突时不参与收益排序。

类别优先级只在所有安全条件满足后使用。默认建议一般阶段为伤员、核心、普通，但这不是规则事实，必须配置化。

`UNKNOWN` 不是第五种可转运目标。未知目标作为疑似危险障碍进入世界模型；只有新的跨帧证据解除疑似危险后才可选择。

## 9. 幂等、时间与复位

- `start_timestamp_ns` 只在 `start()` 首次成功时设置；重复 start 是错误，不重置计时。
- `step()` 时间戳必须单调不减；倒退立即报错。
- `delivery_id` 在单轮内唯一；重复事件不得重复更新计数。
- 终止态吸收所有后续事件，只返回 `STOP`，直到显式 `reset()`。
- `reset()` 只允许在未开始或已终止时调用，并清空本轮 ID、计数和计时。
- 状态机不使用 `time.time()`；测试和回放完全由事件时间驱动。

## 10. 模块对接顺序

```text
TargetObservation
      │ capture_timestamp_ns
      ▼
MultiTargetTracker ──> TrackedTarget
      │
      ▼
WorldModel + 静态区域 + 对手/机器人/接触输入
      │
      ▼
WorldSnapshot + TransportStatus + DeliveryEvidence + SafetySignals
      │
      ▼
MissionStateMachine
      │
      ▼
MissionDecision(action, target_track_id, reason)
      │
      ▼
后续规划器/电控适配（P4/P5）
```

跟踪器、世界模型和状态机都不能创建相机、Hailo、定位器或串口对象。实际应用入口负责按 `configs/runtime.yaml` 装配并把同一单调时间轴的数据串起来。

## 11. 必须自动回放的场景

规则状态机完成至少需要以下无硬件用例：

1. 启动后搜索，仅选择普通物资，单个普通物资正确交付后开放一般救援；
2. 首次交付核心、伤员、多个普通或错分区，确定终止；
3. 后续 1–3 个普通/核心物资合法交付；
4. 伤员单独合法交付，伤员与任意目标混运终止；
5. 四个目标同时转运终止；
6. 已确认危险目标被接触、进入安全区或离场，分别走保守停止；
7. 未知/疑似危险目标不被选择，并触发避让或保持；
8. 视觉过期停止，新鲜快照到达后恢复；
9. 转运目标短时丢失停止，同 ID 恢复后继续；
10. 机器人误入对方安全区输出 `AVOID`，离开后恢复；
11. 对手接触达到 10 秒停止，解除并重定位后恢复；
12. 15 秒无运动、180 秒到时、事故、失控、主动攻击和非法载运终止；
13. 错区、对方区、非危险目标出场等非终止事件不错误推进首次阶段；
14. 同一 `delivery_id` 重放不重复计数；
15. 终止态吸收后续收益事件，复位后才允许新一轮。

危险类、视觉过期和所有终止路径必须单独断言动作、阶段、活动状态和终止原因，不能只断言“抛出异常”或“结果为空”。

## 12. 当前已知限制

- 官方没有给出机器可直接观测的“转运开始/结束”定义；当前接口要求上游提供接触集合，机械完成后必须用实车验证。
- “第一次转运”按首次目标进入己方安全区处理；目标误入对方安全区按官方条款计入对方，不推进本方首次阶段。若现场裁判解释不同，应只修改本设计和状态机交付规则。
- 对手接触 10 秒后的强制分开由裁判执行，软件只能停止并等待新的位置证据。
- 尚无定位模块时，世界模型可以保存静态场地区域和机器人局部目标，但不能可靠判断机器人是否进入对方安全区；状态机不得用缺失坐标作否定结论。
- 策略输出仅是抽象动作，不证明路径可达、机械能够稳定推动或现场规则验收完成。
