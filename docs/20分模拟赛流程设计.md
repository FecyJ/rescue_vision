# 20 分模拟赛流程设计

本文定义“单车、固定出发姿态、中心目标团按命题示意图紧密摆放、模拟赛只豁免
总运行时长”的最小 20 分闭环。当前仓库已实现该闭环的受限软件初版和车端装配
入口，但没有把它声明为真车验收完成或正式比赛能力。规则事实仍以
[赛题约束与视觉需求](赛题约束与视觉需求.md)和官方资料为准，规则状态转移仍以
[规则状态机设计](规则状态机设计.md)为唯一权威；本文只规定模拟赛应用如何装配
现有模块并执行动作。

## 1. 目标与范围

得分策略固定为依次把 4 个绿色普通物资单独推入己方物资区：

```text
第 1 个绿色普通物资：5 分，满足首次必须单独转运 1 个普通物资
第 2 个绿色普通物资：5 分
第 3 个绿色普通物资：5 分
第 4 个绿色普通物资：5 分
合计：20 分
```

选择四次单独绿色交付，是为了只使用一种目标类别和一个目的区域，并持续保持
直接转运数量为 1。当前阶段不搬运核心物资或伤员，不做 2–3 个物资批量推送，
也不以更高分目标覆盖危险和未知目标的保守停止。

模拟赛假设：

- 单车运行，不存在对手机器人；对方安全区仍是静态禁入区；
- 出发区编号、机器人初始朝向、队伍颜色和中心目标团朝向在启动前写入配置；
- 目标团的位置允许有现场摆放误差，但整体位于场地中心附近；
- 只豁免官方 180 秒总运行时间。15 秒无有效运动、禁止启动后人工触碰、禁止
  遥控、禁止抓取/承载、危险目标、安全区、场界和事故规则继续生效；
- 电脑端只允许 `observe_only`，不能下发运动、夹爪或状态跳转命令；
- 目标模型直接使用当前 Hailo Pose 模型和 ROI HSV 分类链路，不在本流程中另建
  第二套检测器。

严格意义上，“无总时限”与官方每轮 3 分钟不同。模拟赛配置可以把
`mission.match_duration_s` 设置为主办方明确同意的较大有限值，例如 1200 秒；
不得静默把该配置当成正式初赛规则。当前
`configs/runtime.simulation-20min.yaml` 仍保留 180 秒，实际模拟赛运行前必须按
主办方约定显式修改并在记录中注明豁免来源；本次软件实现没有替现场确认这一规则
口径。

## 2. 当前实现基线与缺口

截至 2026-08-25，现有代码可以复用：

- 相机、去畸变、地面映射和单槽最新帧 Hailo 推理；
- `TargetObservation` 的检测框、K0、类别、置信度、地面点和质量标记；
- 编码器/IMU 融合、固定初始位姿和 `observe_only` perception/地图发布旁路；
- UART v2 树莓派端、轮速/夹爪控制、控制刷新门限和旁路故障停车；
- `MultiTargetTracker`、`WorldModel` 和 `MissionStateMachine` 的纯逻辑实现；
- `ClusterBreakupSequence` 从等待里程计到 `GREEN_FOUND` 的受监督试验流程；
- `app/simulation_20_point.py` 的顶层状态编排、受限预推导航、绿色目标筛选、几何
  单目标接触/交付证据、退离、四次进度和统一停车；
- `rescue-vision-simulation-20-point` 的严格配置装配和有界旁路车端入口。

当前不能据此宣称完整 20 分能力。尚缺：

- STM32 v2 真车闭环验收。最近一次实测仍报告
  `stop_reason=watchdog_timeout`、`motor_output=false`，这是所有运动的首要阻塞；
- STM32 v2 真车闭环、真实看门狗/急停状态和机械参数验收；
- 现有解团实现之外的真实危险/未知接触传感器和碰撞后现场证据；初版 wrapper 会在
  目标观测存在时做保守门禁，但不替代实体接触判断；
- 正式模型、约 1.5 m 范围真实定位/区域/对手感知和树莓派端到端性能；
- 真实 `TransportStatus`/`DeliveryEvidence` 适配。初版使用“近场几何 + 同一轨迹 +
  推送命令”和配置区域内缩的保守软件证据；
- 多轮真实初始阵列、现场规则口径和正式比赛扩展验收。

## 3. 运行架构

完整入口为 `rescue-vision-simulation-20-point`，实现位于 `app` 包内；该入口只
服务这一条受限流程，不新增通用 `planning` 顶层包。稳定的通用规划算法只有出现
第二个真实调用方后再提取。当前入口已实现，但它仍受真车门禁和现场证据限制。

```text
Camera source
    │ 独立有界旁路：取最新帧、去畸变
    ▼
TargetPoseDetector
    │ 独立单槽旁路
    ▼
TargetObservation ──> MultiTargetTracker ──> WorldModel
                                              │
OdometryImu ──> OdometryImuFusion ────────────┤
                                              ▼
                                  MissionStateMachine
                                              │ STOP 不可覆盖
                                              ▼
                                 20 分应用行为状态机
                                              │
                                   受限路径与视觉伺服
                                              │
                                              ▼
                                      MotionController
                                              │
                                              ▼
                                            STM32

Remote observe_only publisher <── perception / pose / state snapshots
```

主运动循环只允许：刷新轮速、非阻塞排空 UART、读取已完成的最新快照、运行轻量
状态转移并提交控制意图。相机等待、去畸变、推理、JPEG/JSON 编码、TCP、显示和
写盘全部使用有界旁路；任一旁路异常必须传播到统一停车路径，不能放宽 100 ms
运动刷新门限。

规则状态机和应用行为状态机职责不同：

- `MissionStateMachine` 判断动作是否合法、首次普通物资是否完成、何时必须停止；
- 应用行为状态机把允许的 `SEARCH/APPROACH/PUSH/DELIVER/AVOID` 细化为定距运动、
  预推位姿和视觉伺服；
- 应用不得在 `MissionDecision.action=STOP` 时继续运动，也不得自行解释首次、危险、
  容量或错区规则。

## 4. 顶层状态流

应用状态使用下列完整流程。状态名是 `Simulation20PointSequence` 的应用内部状态，
不替代 mission 包现有枚举；现有解团子状态由 `ClusterBreakupSequence` 原样驱动。

```text
BOOT
  ↓
PREFLIGHT
  ↓ 一键启动
LEAVE_START → SEARCH_CLUSTER → CENTER_CLUSTER → BREAKUP_SAFETY_CHECK
  → APPROACH_CLUSTER → BREAKUP_PUSH → BREAKUP_RELEASE
  → BREAKUP_OPEN_RETREAT → BREAKUP_CLOSE → RETREAT_FROM_CLUSTER
  → RESET_TARGET_TRACKS
  ↓
SCAN_GREEN → EVALUATE_EASY_GREEN
       ├─ 有易搬运绿色 → SELECT_GREEN → PLAN_PREPUSH → NAVIGATE_PREPUSH
       │                    → ALIGN_GREEN → APPROACH_GREEN → ENGAGE_GREEN
       └─ 无易搬运绿色 → PLAN_REBREAKUP → CENTER_REBREAKUP_CLUSTER
                            → BREAKUP_SAFETY_CHECK → APPROACH_CLUSTER
                            → BREAKUP_PUSH → BREAKUP_RELEASE
                            → BREAKUP_OPEN_RETREAT → BREAKUP_CLOSE
                            → RETREAT_FROM_CLUSTER
                            → RESET_TARGET_TRACKS → SCAN_GREEN

ENGAGE_GREEN
  → PUSH_TO_MATERIAL_ZONE → VERIFY_DELIVERY → DISENGAGE_AND_RETREAT
  → UPDATE_PROGRESS
       ├─ 有效绿色交付数 < 4：回到 SCAN_GREEN，重新判断是否需要解团
       └─ 有效绿色交付数 = 4：FINISH_STOP

任意状态 ── 可恢复信息不足 ──> SAFETY_HOLD
任意状态 ── 规则终止/电控故障/事故 ──> TERMINAL_STOP
```

`SAFETY_HOLD` 只允许零运动意图。恢复必须由新鲜、可信的明确证据触发；不得因
超时猜测风险消失。若安全保持导致 15 秒无有效运动，则按规则进入终止态，而不是
为了“保持运动”盲目移动。

## 5. 启动与电控门禁

### 5.1 `BOOT`

只创建尚未打开的配置对象，校验：

- 使用 `configs/runtime.simulation-20min.yaml`，且队伍颜色和固定初始位姿已设置；
- 相机、内参、地面映射、Hailo、UART、motion、odometry、gripper、fusion 和
  `cluster_breakup` 均启用；
- 远程关闭或为 `server + observe_only`；
- 所有速度不超过 motion 硬上限，夹爪端点来自本车机械标定；
- 地面映射元数据匹配当前相机、分辨率、焦点和安装位姿。

失败时不打开电机，退出并打印具体配置路径和值。

### 5.2 `PREFLIGHT`

打开资源后必须先保持软制动，并取得以下真实证据：

1. 连续且有效的双编码器/IMU 遥测；
2. STM32 `WATCHDOG_ARMED=true`、急停未锁存；
3. `QUERY_STATUS` 和零轮速命令得到 `COMMAND_REPLY=accepted`；
4. 新鲜状态中的运动命令年龄会随新命令刷新；
5. 相机和 Hailo 后台产生新鲜结构化观测；
6. 观察端即使未连接也不阻塞流程。

当前实测的 `watchdog_timeout + motor_output=false + 运动命令年龄不刷新` 必须先在
STM32 固件中修复。不得通过清零累计编码器、伪造路程、增大应用超时或跳过状态
检查继续比赛。编码器保持固件累计值，树莓派用首帧建立软件路程基线。

### 5.3 一键开始

开始时同时：

- 记录唯一 `start_timestamp_ns`；
- `MissionStateMachine.start()`；
- 清空上一轮 tracker、world、交付 ID、应用状态和完成目标集合；
- 固化本轮 `team_color`、出发区、初始位姿和配置快照；
- 之后拒绝人工触碰和远程控制。

## 6. 离开出发区与可控解团

### 6.1 `LEAVE_START`

按约定初始方位以配置速度直行，用左右编码器有效轮程完成固定距离越障。满足以下
任一条件立即停车：

- 左右轮前进符号不一致；
- 命令未被接受、看门狗不刷新、电机输出未使能；
- 遥测过期、`sample_overrun`、计数跳变或阶段超时；
- 实际中心路程长期无进展。

### 6.2 `SEARCH_CLUSTER` 与 `CENTER_CLUSTER`

越障完成后按 `search_direction` 原地低速扫描。目标团候选使用当前帧任务目标检测
框的联合包围框，但必须满足配置的最小检测数量、观测年龄和连续确认帧数。联合框
中心通过比例角速度控制锁定在画面中心；方向约定仍为左转角速度为正。

只看见单个远处目标、观测过期或模型输出相互冲突时继续扫描或停车，不把安全区
色块当成中心目标团。

### 6.3 `BREAKUP_SAFETY_CHECK`

这是当前解团试验尚缺的强制门禁。进入推进前必须：

- 从目标团观测中标出浅蓝危险和 `unknown`；
- 选择窄推头预计直接接触的前缘目标，直接接触集合不得超过 3 个；
- 项目保守策略禁止直接接触已确认危险目标；疑似危险或直接接触集合不确定时停车；
- 预测短行程冲散后的中央操作包络，确认任何危险/未知目标不会接近安全区或场界
  的配置安全裕量；
- 夹爪只允许张开形成推送面，不得闭合夹住、托起或承载目标；
- 模拟赛裁判需事先确认中心解团的间接位移不按“同时转运超过 3 个”判罚。若解释
  不同，本方案停止，不能靠软件隐藏接触数量。

该门禁不仅用于启动后的第一次解团。每次 `SCAN_GREEN` 完成规定范围的检查但没有
易搬运绿色时，必须基于最新世界快照重新执行同一门禁；不能认为第一次撞击已经
永久解除目标团风险。

### 6.4 `APPROACH_CLUSTER`、`BREAKUP_PUSH`、张爪退出和 `RETREAT_FROM_CLUSTER`

目标团保持居中并低速接近。最近有效 K0 地面点进入配置距离后张开夹爪，以配置的
较高但受 motion 上限约束的速度做短距离直线推进。推进只依赖编码器定距，不因
画面短时完全遮挡无限前进。

到达冲散距离后立即制动并切到张开端点，保持完整全行程时间。随后保持张爪，以
`retreat_speed_m_s` 倒退 `gripper_open_retreat_distance_m`；该阶段只允许张爪
退出，不允许提前合爪。退出距离达到后再次停车，切到闭合端点并保持完整全行程
时间，最后进入 `RETREAT`，以闭爪状态倒退 `retreat_distance_m`。冲击、倾斜、打滑、
目标钻车底、危险目标快速位移或任一电控故障均进入 `TERMINAL_STOP` 或保守安全保持。

### 6.5 `RESET_TARGET_TRACKS`

解团碰撞会造成检测框重叠、ID 交换和目标突然位移。车辆退离后：

- 保持低速扫描，不沿用碰撞前的目标 ID；
- 显式 `MultiTargetTracker.reset()` 并连续收集新鲜帧；
- 只有重新确认的目标进入新世界快照；
- 已确认危险和未知目标先建立膨胀禁入区，再开放绿色候选选择。

重复解团后的 tracker 重置不能清空 mission 已接受的交付历史和唯一
`delivery_id`。若当前 tracker 只能整轮重置，则应用保留交付记录，并在重建世界
后按静态安全区区域排除已经交付的目标；不得把安全区内重新分配的 track ID 当成
新候选再次搬运。

## 7. 绿色目标选择

### 7.1 `SCAN_GREEN`

按配置方向低速旋转，持续消费最新模型观测、跟踪和机器人连续位姿。扫描必须覆盖
配置的最小航向范围或完成一整轮目标可见区观察，不能因单帧没有绿色就开始撞击。
候选必须：

1. `target_class=green_supply`，且跨帧跟踪已确认；
2. 危险状态为 `CLEAR`，不是颜色不足、歧义或 Pose/HSV 冲突；
3. 有新鲜 `GroundPoint`，能够由当前 `FieldPose2D` 转为 `FieldPoint`；
4. 不在双方安全区、场界裕量、危险/未知膨胀区或已完成集合内；
5. 与其它目标分离到足以证明一次只会直接推动一个；
6. 存在到己方物资区入口的保守推送走廊。

满足全部条件的候选定义为“易搬运绿色”。其中“与其它目标分离”至少要求目标
足迹到最近其它目标足迹的净空大于推头半宽、目标半宽、横向控制误差和配置安全
余量之和；“走廊可用”还要求机器人能到达目标背后的预推位姿，而不穿过当前目标团。

只在所有安全条件满足后按代价选择目标。建议代价依次考虑：预推位姿可达、推送
走廊净空、到入口距离、目标地面几何质量；不按检测置信度单独追逐最近目标。

### 7.2 无易搬运目标时的重复解团

完整扫描后没有易搬运绿色，不直接进入 `SAFETY_HOLD`，而是执行：

```text
SCAN_GREEN
  → EVALUATE_EASY_GREEN（结果为空）
  → PLAN_REBREAKUP
  → CENTER_REBREAKUP_CLUSTER
  → BREAKUP_SAFETY_CHECK
  → APPROACH_CLUSTER
  → BREAKUP_PUSH
  → RETREAT_FROM_CLUSTER
  → RESET_TARGET_TRACKS
  → SCAN_GREEN
```

`PLAN_REBREAKUP` 不盲目复用首次固定冲击方向。它从未交付目标建立距离/足迹邻接
图，把相互接触或净空不足的连通分量视为剩余目标团，并优先选择满足以下条件的
冲击方案：

1. 预计能提高至少一个绿色目标的最小周边净空；
2. 直接接触集合明确且不含危险/疑似危险，数量不超过 3；
3. 冲击方向远离安全区、场界以及现有危险/未知目标；
4. 机器人存在无碰撞的接近和退离路径；
5. 使用已经真车验收的速度和行程，不因前一次无效而自动加速或加长行程。

每次重复解团都记录解团前后的可搬运性指标：易搬运绿色数量、各绿色最小净空、
目标团连通分量大小、危险目标到安全区/场界的最小距离。只有新快照证明分离度有
进展，才允许下一次重复解团。

正常流程可以多次循环直至发现易搬运绿色，但不能无限盲撞。配置必须给出：

- `max_breakup_attempts_per_delivery`：一次交付循环允许的最大重复解团次数；
- `max_breakup_attempts_total`：整轮总解团次数；
- `min_breakup_progress_mm`：继续尝试所需的最小净空改善；
- `scan_min_heading_span_rad`：判定“没有易搬运目标”前的最小扫描覆盖；
- `breakup_settle_confirm_frames`：碰撞后目标稳定并允许重建跟踪的连续帧数。

达到次数上限、连续无分离进展、没有合法冲击方案，或危险裕量下降时进入
`SAFETY_HOLD`/`TERMINAL_STOP`，不得为了凑够 20 分继续撞击。每完成一次有效绿色
交付后，重复解团计数按“本次交付循环”重新开始，但整轮总次数不清零。

### 7.3 `SELECT_GREEN`

锁定唯一稳定 `track_id` 和该时刻目标场地点，记录选择原因。其它绿色仍是动态
障碍，不允许在接近过程中自动并入本次转运。若目标丢失、类别变成未知/危险或
走廊被占用，取消选择并回到 `SCAN_GREEN`。

## 8. 最小导航与预推位姿

本模拟赛先实现受限的“旋转—直行—旋转 + 局部视觉伺服”，不实现通用 A*。

给定目标场地点 `T` 和己方物资区入口参考点 `D`：

```text
push_direction = normalize(D - T)
prepush_point = T - push_direction * prepush_offset_mm
```

`prepush_offset_mm` 必须包含轮轴原点到推头前缘距离、目标半尺寸和安全余量。生成
路径前用配置机器人足迹沿各段膨胀检查：

- 场界和对方安全区；
- 危险/未知目标禁入区；
- 其它已确认目标；
- 己方安全区非入口围栏；
- 定位不确定度形成的额外裕量。

若简单路径不安全，不尝试复杂绕行：取消当前候选并选择另一绿色。所有绿色均因
相互粘连、预推位姿被占用或走廊被目标团阻挡时，返回第 7.2 节的重复解团评估；
只有不存在合法重复解团方案或达到安全上限时才进入 `SAFETY_HOLD`。

### 8.1 `NAVIGATE_PREPUSH`

使用编码器/IMU 连续位姿执行分段导航；每段均有距离、航向误差、阶段时长和最小
运动进展门限。定位年龄或不确定度超过阈值立即停车。当前仅近场地面映射，不能把
中心至安全区全程精度写成已验收；实施前必须完成覆盖约 1.5 m 的真实标定或证明
导航只依赖已验收的融合范围。

### 8.2 `ALIGN_GREEN` 与 `APPROACH_GREEN`

进入目标附近后切换为目标局部视觉伺服：

- 用选中轨迹的 K0/中心保持目标位于推头中心线；
- 角速度采用有上限的比例控制，线速度随距离和横向误差降低；
- 目标短时遮挡立即把线速度降为零，恢复同一 ID 后才能继续；
- 近场发现第二个目标进入推头接触宽度时取消接近并后退。

## 9. 单目标推送和交付

### 9.1 `ENGAGE_GREEN`

只有近场几何证明推头即将接触选中绿色目标时，接触证据适配器才创建：

```text
TransportStatus.engaged_track_ids = (selected_track_id,)
contact_started_ns = 当前单调时间
```

首版可以融合“推头距离阈值 + 当前前进命令 + 同一轨迹持续存在”，但必须保守；
最终优先增加实体接触开关。无法确定接触数量时进入安全保持，禁止把检测框数量或
计划目标直接伪装成真实接触。

### 9.2 `PUSH_TO_MATERIAL_ZONE`

推送期间反复调用 `MissionStateMachine.step()`，只在它允许 `PUSH/DELIVER` 时继续。
控制目标是让绿色目标沿入口法向进入己方物资区：

- 始终保持一次一个稳定目标；
- 以目标横向误差修正小角速度，临近入口降低线速度；
- 机器人自身不得进入对方安全区；
- 目标、视觉或定位过期立即停车；
- 任何危险/未知目标进入推送走廊立即停止并撤回；
- 不允许夹爪闭合形成抓取。

### 9.3 `VERIFY_DELIVERY`

不能用“推了固定距离”直接记分。交付证据至少要求：

1. 目标类别仍为绿色普通物资；
2. 目标足迹全部位于己方物资区有效多边形内，不在围栏上；
3. 等价实现为目标中心进入按 40 mm 方块半尺寸和测量裕量内缩后的区域；
4. 连续多帧成立，且定位、区域和目标观测均新鲜；
5. 机器人退离后重新看到目标仍在区域内；
6. 使用单调唯一 `delivery_id`，重复观测不得重复计数。

证据成立后产生：

```text
DeliveryEvidence(
    track_ids=(selected_track_id,),
    destination=OWN_MATERIAL,
    fully_entered=True,
)
```

部分进入时保持验证，不记分；目标丢失时不能猜测已经进入。错误进入伤员区、对方
安全区或场外时按现有规则状态机处理，不由模拟赛应用私自修正计数。

### 9.4 `DISENGAGE_AND_RETREAT` 与 `UPDATE_PROGRESS`

交付确认后低速倒退，视觉和接触证据共同确认脱离，再清空 `TransportStatus`。
只有 `MissionStateMachine` 接受的有效绿色交付才加入完成集合。

完成条件不另建通用计分器，而是：

```text
本轮唯一有效绿色交付 track/delivery 数量 == 4
```

界面可以显示 `4 × 5 = 20`，但应用不能绕过 mission 的首次和交付验证直接增加
数量。少于 4 个则返回 `SCAN_GREEN`，同时排除已完成目标。

## 10. 完成和停止

`FINISH_STOP` 在第四个有效交付后：

- 立即输出零运动意图并执行软制动；
- 不要求返回出发区，不继续追求额外分数；
- 保持夹爪处于不会接触目标的安全姿态；
- 发布最终 `valid_green_deliveries=4`、目标/交付 ID、终止原因和 20 分展示值；
- 冲洗日志旁路并按相机、推理、远程、UART的生命周期顺序关闭资源。

程序退出或观察连接断开不能恢复旧运动。`SIGKILL` 和物理断链只能依赖已经真车
验收的 STM32 看门狗停车。

## 11. 安全短路优先级

应用每个控制周期按以下顺序短路，后面的收益动作不能覆盖前面的停车：

1. 急停、事故、失控、人员触碰、非法抓取/承载、外部停止；
2. 命令拒绝、看门狗异常、电机输出关闭、UART/控制刷新故障；
3. 危险目标进入安全区或场外、危险目标被直接接触；
4. 接触数量超过 3、伤员混运等规则终止；
5. 视觉、定位、接触或区域证据过期/缺失；
6. 场界、对方安全区、危险/未知膨胀区或路径占用；
7. 当前目标丢失、ID 冲突、第二目标进入推头宽度；
8. 合法的搜索、接近、推动、交付和收益选择。

电控故障使用固件状态和命令回复判定。树莓派已经请求非零轮速但
`last_motion_command_age_ms` 不刷新、`motor_output=false` 或
`stop_reason=watchdog_timeout` 时必须停车并修复固件，不能清零编码器或伪造运动。

## 12. 配置权威

所有可调量继续只来自运行配置。实施时应在现有配置结构中补充最小必要字段，
不在应用代码中硬编码：

| 概念 | 权威配置 |
| --- | --- |
| 相机、标定、模型、HSV | 现有 `camera/geometry/hailo/perception` |
| 轮距、轮径、速度、加速度、夹爪端点 | 现有 `motion` |
| 解团方向、速度、距离和门限 | 现有 `motion.cluster_breakup` |
| 初始位姿和融合噪声 | 现有 `localization.fusion` |
| 队伍颜色、场界和安全区 | 现有 `world` 静态地图 |
| 总时长、15 秒和规则阈值 | 现有 `mission` |
| 目标跟踪门限 | 现有 `tracking` |
| 预推偏移、足迹裕量、走廊宽度、交付内缩和确认帧数 | `simulation_20_point` |
| 扫描覆盖、易搬运净空、重复解团次数和最小分离进展 | `simulation_20_point` |

`simulation_20_point` 已实现为严格 dataclass，拒绝未知键、非有限值、负尺寸、
超过 motion 硬上限的速度，以及未完成解团/融合/Hailo/地面映射门禁却启用对应
能力。格式变化一次更新仓库内调用方和测试，不增加兼容层。

## 14. 测试与分级验收

### 14.1 无硬件 pytest

当前初版已在 `tests/test_simulation_20_point.py` 覆盖：配置严格装配、启动失败门禁、
现有解团后的轨迹重建和扫描、危险目标/旁路故障停车，以及四个绿色目标的合成
成功闭环和 20 分终止锁存。以下列表仍是后续补齐或加强的验收要求；合成回放不
能替代实拍、危险类指标或真车性能证据。

至少覆盖：

- 完整成功序列：解团后依次交付 4 个不同绿色目标；
- 第一次撞击不足时经过两次或多次“扫描—重复解团”后找到易搬运绿色；
- 每次交付后重新扫描，剩余绿色再次成团时允许新的受控解团循环；
- 单次/总解团次数上限、无净空改善和无合法冲击方向均停止继续撞击；
- 第一次交付非单个绿色时终止；
- 相同 `delivery_id` 重放不重复计数；
- 未知/危险目标不进入候选，危险直接接触或入区终止；
- 第二目标进入推头宽度、目标丢失、定位/视觉过期时停车；
- 简单路径被场界、对方安全区或危险膨胀区阻挡时更换候选；
- 交付部分进入不计数，退离后完全进入才计数；
- 第四次有效交付进入 `FINISH_STOP`，后续事件不能恢复运动；
- 慢取帧、慢去畸变、慢推理和慢发布不阻塞主运动循环；
- UART 回复拒绝、看门狗不刷新、状态过期和旁路异常均停车。

### 14.2 真车分级验收

必须逐级通过，不能直接跳到四目标：

1. 架空轮：协议、方向、轮速、编码器、IMU、看门狗和急停；
2. 空场：越减速带、固定转向、停车距离和定位误差；
3. 静态目标团：只观察和居中，不接触；
4. 低速短行程解团：检查危险最大位移、夹持、钻车底和场地损伤；
5. 单个已分离绿色：预推位姿、接近、推送和退离；
6. 单个绿色交付：完整进入判定和首次规则；
7. 连续两个、三个、四个绿色交付；
8. 加入浅蓝危险、未知目标、遮挡、视觉断流、UART 断开和急停故障注入；
9. 最终按模拟赛初始紧密阵列完整运行，多次重复报告成功率和失败原因。

### 14.3 完成标准

只有同时满足以下条件，才可称为“20 分模拟赛流程已实现”：

- STM32 看门狗、电机使能、急停和失联停车有真车证据；
- 解团不会直接接触危险目标，不造成危险入区/出场或一次直接转运超过 3 个；
- 四次交付均由唯一目标、真实接触和完全进入证据支持；
- 全程无人工触碰或远程控制，观察端断开不影响运行；
- 所有故障路径停车，主运动刷新没有被图像或网络任务阻塞；
- 至少完成多轮真实初始阵列重复测试，并记录成功/失败样例；
- README 仍明确它是受限模拟赛能力，不是完整正式比赛程序。

## 15. 尚需现场确认

- 模拟赛“无时间限制”具体只豁免哪一条，15 秒无运动是否仍执行；
- 中心解团造成多个目标间接位移是否计入一次转运数量；
- 张开夹爪作为推送面是否会被现场裁判认定为抓取机构；
- 目标团实际朝向、摆放公差、地面摩擦和安全区入口材料；
- “全部进入”在现场裁判口径下的边界和围栏判定。

任何一项解释变化，应先更新本设计和规则权威文档，再修改实现；不得只改参数或
在检测器、规划器中增加分散条件分支。
