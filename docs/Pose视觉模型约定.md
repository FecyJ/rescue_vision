# 工创赛视觉模型约定

## 1. 适用范围

本文档规定任务物体 YOLO Pose 模型的类别、检测框和关键点标注规则。

模型只负责可移动任务物体，不包含：

- 安全区
- 出发区
- 中心十字
- 场地线
- 对方机器人
- 本方机器人及其机构
- 其他固定场地结构

上述固定场地特征将由独立的场地特征模型推理后端处理；传统 OpenCV 检测已
删除，该模型后端和相应标注约定尚未实现。

---

## 2. 类别约定

类别编号和顺序固定如下，不得调整：

```yaml
names:
  0: green_supply
  1: black_core
  2: orange_injured
  3: blue_danger
```

类别语义：

| ID | 类别 | 含义 |
|---:|---|---|
| 0 | `green_supply` | 绿色普通物资 |
| 1 | `black_core` | 黑色核心物资 |
| 2 | `orange_injured` | 橙色伤员 |
| 3 | `blue_danger` | 浅蓝色危险物 |

运行代码中的 `TargetClass` 必须直接使用这四个标签名，不得另建
`normal`、`core`、`injured`、`hazard` 等别名。运行时另有 `unknown`
用于低置信度或无法可靠分类时的保守降级，但 `unknown` 不是第五个
YOLO 训练类别，不写入四类训练标签。

规则：

1. 类别按比赛任务语义确定，不按具体几何形状确定。
2. 同一任务类别即使由方块、球体、圆柱体等不同形状构成，仍使用同一类别。
3. 只有比赛规则新增独立任务语义时，才允许新增类别。
4. 无法可靠判断类别的目标不标注，不得凭颜色近似或主观猜测分类。

### 2.1 运行时类别判定

训练标签仍使用上述四类，Pose 后端仍输出原始模型类别；但部署时最终
`TargetObservation.target_class` 以检测框 ROI 内的 HSV 颜色证据为主：

1. Pose 模型负责目标存在性、水平检测框和 K0。
2. ROI HSV 负责四类主分类和局部颜色分割；范围、证据门槛和去噪参数全部来自
   运行配置。
3. HSV 证据充分时覆盖 Pose 类别；两者不同会记录
   `pose_color_conflict`，不把已知蓝绿混淆重新引入最终类别。
4. 颜色覆盖不足或多色歧义时输出运行时 `unknown`，不得用 Pose 类别静默兜底。
5. 命题文件仅给出颜色名称、示意图并明确现场存在色差，因此示例配置中的 HSV
   数值不是官方色卡，必须用固定相机参数和现场实物重新校准。

运行时 HSV 分类不改变人工标注类别：标注仍按物体的任务语义和已确认实物类别
进行，不允许用当前阈值输出自动替代真值。

---

## 3. Pose结构约定

每个实例只标注一个关键点：

```yaml
kpt_shape: [1, 3]
flip_idx: [0]
```

关键点名称固定为：

```text
K0：bottom_contact_anchor
中文：底部接触锚点
```

禁止新增 K1、K2，除非后续正式修改本约定并重新检查已有标签。

历史部署包的兼容由推理后端处理，不改变标注规范；新训练、导出和部署包必须使用 `[1, 3]`。

## 4. K0严格定义

K0 定义为：

> 经过统一图像校正后，目标与当前支撑面可见接触轮廓中的最下方唯一锚点；若最下方为一段单一连续线段，则取该线段的中点。

图像坐标规定：

- 原点位于图像左上角；
- `u` 向右增大；
- `v` 向下增大；
- “最下方”指 `v` 最大的位置。

K0 必须位于目标实体与支撑面的分界线上。

K0 不表示：

- 物体几何中心；
- 物体底面中心；
- 物体视觉中心；
- 检测框底边中心；
- 分割掩膜中的随机最低噪声点；
- 阴影最低点；
- 人工推测的隐藏中心；
- 任意两个辅助点的像素中点。

---

## 5. 各形状的K0规则

### 5.1 方块、长方体

- 两条可见底边形成向下尖角时：标最下方前角点。
- 一个正面完整朝向相机，最低处为连续底边时：标该最低底边中点。
- 底边倾斜且只有一个端点最低时：标最低端点。
- 不标隐藏底面的中心。

### 5.2 球体

- 标球体实体轮廓与支撑面的最低接触位置。
- 不标球心。
- 不直接使用检测框底边中心。

### 5.3 直立圆柱体

- 标底部可见接触轮廓的最低点。
- 最低处为连续短线段时，标该线段中点。
- 不标隐藏圆形底面的中心。

### 5.4 横放圆柱体

- 最低处为单一连续接触线段时，标该线段中点。
- 因透视或姿态导致只有一个端点最低时，标最低端点。

### 5.5 正四面体、圆锥及其他异形物体

- 最低处为唯一角点：标该角点。
- 最低处为单一连续边：标该边中点。
- 最低处存在多个分离且等价的接触点，无法得到唯一锚点：K0 标为不可用。
- 不能可靠确认实体与支撑面的边界：K0 标为不可用。

---

## 6. K0可见性

关键点格式为：

```text
K0_x K0_y K0_visibility
```

可见性定义：

```text
0：不存在、位于画面外，或无法可靠确定
1：被遮挡，但能从当前图像中的连续几何边界准确推断
2：直接可见
```

使用规则：

1. K0 清晰可见：标 `2`。
2. K0 被细小遮挡物局部挡住，但两侧边界可准确延长得到位置：标 `1`。
3. 只能大致猜测位置：必须标 `0`，不得标 `1`。
4. K0 被另一物体、围栏或机器人机构严重遮挡：标 `0`。
5. 目标底部超出画面：标 `0`。
6. 目标悬空、被托起或未接触所定义支撑面：标 `0`。
7. 物体堆叠在其他物体上，且不位于当前用于定位的支撑面：标 `0`。
8. 运动模糊后仍能唯一确定 K0：可标 `2`；无法可靠确定则标 `0`。

K0 不可用时统一写为：

```text
0 0 0
```

---

## 7. 多接触点规则

当目标存在多个最低接触位置时：

- 若这些位置连成一段单一连续区域：取该区域中点。
- 若这些位置相互分离，且不存在唯一合理锚点：K0 标 `0`。
- 不得固定选择左点、右点或距离图像中心最近的点。
- 不得在两个分离接触点之间的空白区域标点。

---

## 8. 支撑面规则

默认支撑面为比赛场地主地面。

目标位于以下位置时仍可标注 K0：

- 安全区坡道；
- 安全区内部平面；
- 其他清晰可辨的刚性支撑面。

但 K0 只表示该目标在当前支撑面上的接触锚点。

如果支撑面类型不明确，或目标同时跨越多个支撑面且无法确定主支撑面，K0 标 `0`。

---

## 9. 检测框规则

检测框采用水平矩形框。

检测框应：

1. 紧贴目标实体的可见轮廓。
2. 包含属于该目标的所有可见实体部分。
3. 不包含阴影、反光、光晕和背景。
4. 不包含相邻目标。
5. 不包含被目标推动但未与其固定连接的其他物体。
6. 目标轻微遮挡时，框住可见实体范围，不人为扩展到无法确认的隐藏范围。
7. 目标被严重遮挡且类别无法可靠判断时，不标注该实例。
8. 目标在图像边缘被截断但类别仍可确认时，可以标注检测框；K0 是否有效单独判断。

---

## 10. 遮挡与粘连规则

### 10.1 多个目标相互接触

- 每个物体单独标注一个实例。
- 每个实例使用自己的类别、检测框和 K0。
- 不得将多个相邻物体合并为一个检测框。
- 无法区分实例边界时，不得凭数量猜测拆分。

### 10.2 目标被其他物体遮挡

- 类别和实体边界仍可可靠判断：保留实例。
- K0 可准确推断：标 `1`。
- K0 无法准确推断：标 `0`。
- 类别也无法可靠判断：整个实例不标注。

### 10.3 围栏或车体遮挡

- 围栏和车体不属于任务目标检测框。
- 仅根据当前图像判断 K0，不得直接照抄上一帧的位置。
- 当前帧无法可靠确定 K0 时标 `0`。

---

## 11. 阴影、反光与模糊

1. 阴影永远不属于目标实体。
2. K0 应标在实体与支撑面的真实边界，不标在阴影边缘。
3. 反光区域仍属于目标实体，但不得把反光光晕扩入检测框。
4. 轻微模糊不改变类别、检测框和 K0 定义。
5. 模糊导致目标边界或 K0 无法可靠判断时，按不可用处理。
6. 颜色偏移不改变类别语义；类别无法确认时不标注。

---

## 12. 图像预处理一致性

任务目标的标注、训练、验证和部署统一使用当前 `CameraModel` 按固定 `new_K` 产生的全尺寸去畸变图，不使用原始畸变图。

固定内容包括 `calibration_id`、输出尺寸、图像方向、长宽比处理、缩放和填充
方式。去畸变的无效边缘统一填充为与 YOLO Letterbox 相同的 BGR
`(114, 114, 114)` 并保持在图中，不额外裁剪；不得在
`CameraModel.valid_mask == 0` 的区域标注目标。

禁止：

- 把原始畸变记录直接加入任务目标数据集；
- 混用不同 `calibration_id` 或 `new_K` 产生的去畸变图；
- 标注后再进行改变关键点几何位置的裁剪或透视变换；
- 不同步变换检测框和关键点。

---

## 13. 水平翻转规则

单关键点 K0 在水平翻转后语义不变：

```yaml
flip_idx: [0]
```

水平翻转时必须同步变换：

- 检测框；
- K0 横坐标；
- 图像内容。

不得只翻转图像而保留原标签坐标。

---

## 14. 标签格式

每个实例一行：

```text
class_id cx cy w h k0_x k0_y k0_visibility
```

所有坐标归一化到 `[0, 1]`。

示例：

```text
0 0.500000 0.600000 0.200000 0.260000 0.470000 0.742000 2
```

K0 不可用：

```text
0 0.500000 0.600000 0.200000 0.260000 0 0 0
```

---

## 15. 数据集质量约定

1. 同一物体、同一视角条件下必须采用一致的 K0 判定。
2. 标注员不得自行修改类别名称、编号或关键点定义。
3. 有争议的样本进入复审，不得以平均位置代替统一判定。
4. 连续视频帧中的 K0 应随目标和相机运动连续变化，不得无原因在角点与边中点之间跳变。
5. 所有标签必须经过可视化检查。
6. 类别正确但 K0 无法确定时，保留检测框并将 K0 标为 `0`。
7. 类别无法确定时，整个实例不标注。
8. 禁止为增加样本数量而猜测关键点。
9. 数据集投入训练后，本规则中的类别顺序和 K0 语义不得静默修改。

## 16. 当前输出边界

Pose 模型训练与部署输出仍是水平检测框加单个 K0，不训练或声称具备实例分割
能力，也不从 K0 推导物体朝向。运行时会在每个 Pose 检测框中以 HSV 阈值派生
一个 ROI 局部颜色掩码；该掩码属于后处理观测契约，不是 Pose 标签或模型输出，
因此本次不改变 YOLO Pose 标签格式和已有标签。

遮挡、接触、形状和困难程度继续作为数据集分层标签保留。若未来改为训练分割
模型、把掩码加入人工真值，或改变 K0/类别标注语义，必须修改本约定、同步
部署契约并重新检查已有标签。

规则或类别发生变化时，必须隔离新旧数据批次并重新检查旧标签。
