# 项目结构

本页只回答两个问题：一个功能现在在哪里，以及新代码应该放在哪里。实现状态以 [README](../README.md) 为准，任务顺序以 [后续优先级](后续优先级.md) 为准。

## 当前目录

```text
rescue_vision/
├── configs/runtime.example.yaml       # 可移植运行配置模板
├── configs/runtime.yaml               # 本机实际配置，不提交
├── docs/                              # 规则、路线图和专项操作文档
├── examples/                          # 明确标为合成的 schema 夹具
├── manual_tests/                      # 真机和 GUI 人工验收
├── src/rescue_vision/
│   ├── calibration/                  # 标定采集与求解命令
│   ├── camera/                       # 帧、真机源、回放、记录
│   ├── communication/                # UART 与认证远程消息通信
│   ├── config/                       # 运行配置加载与装配
│   ├── data/                         # 数据清单和划分命令
│   ├── evaluation/                   # 离线指标与报告命令
│   ├── geometry/                     # 坐标、去畸变、地面投影
│   ├── mission/                      # 规则状态机、事件回放与抽象动作
│   ├── perception/                   # 任务目标 Pose 契约与推理后端
│   ├── tracking/                     # 目标时间关联、遮挡与轨迹生命周期
│   ├── world/                        # 静态区域、动态目标和不确定性快照
│   └── versioning.py                 # 记录 Git 版本与 dirty 状态
└── tests/                            # 无硬件 pytest
```

没有 `localization/`、`planning/`、小车协议控制模块或 `app.py`，因为这些能力尚未实现。`communication/` 提供 UART 与认证远程消息通道，但没有远程意图到底盘、图传编码或地图渲染应用；真实接触/交付证据适配也尚未落地。每个已实现包的常用入口和实际对接示例见 [`src/rescue_vision/README.md`](../src/rescue_vision/README.md)。

## 模块边界

```text
Camera Frame
    │
    └── CameraModel ──> 去畸变帧 ──┬─> Recorder（采集）──> RecordingSource
                                   └─> TargetPoseDetector ──> K0
                                              │                │
                                              └─ GroundProjector
                                                       │
                                                       └─> TargetObservation
                                                                  │
                                                                  ▼
                                                         MultiTargetTracker
                                                                  │
                                                                  ▼
                                                            WorldModel
                                                                  │
                                                                  ▼
                                                      MissionStateMachine
```

- `camera` 负责帧的产生、生命周期、回放和记录；录制 CLI 在装配层调用 `CameraModel`，记录器本身不复制几何实现。
- `communication` 维护 UART 和认证远程消息的可靠交付，并在 `observe_only` 拒绝远程控制；它不把调试运动意图解释成轮速，也不实现图传或地图。
- `geometry` 不创建相机，也不解释比赛类别。
- 任务目标检测器消费去畸变帧和显式配置，只输出带帧号、时间、坐标系、置信度和质量标记的观测。
- 跟踪器消费同帧观测；世界模型消费轨迹和外部区域/对手证据；规则状态机只消费世界快照和显式接触/交付/安全事件。
- 定位尚未实现；缺少 `FieldPoint` 时世界模型保留不确定性，不伪造区域结论。
- 小车协议层后续消费 `communication` 原始行并统一解复用命令回复、轮速和 IMU；算法模块不得直接创建或读取 PySerial 对象。

坐标调用链固定为 `RawPixel → UndistortedPixel → GroundPoint ↔ BevPixel`，完整定义见 [`geometry` README](../src/rescue_vision/geometry/README.md)。

## 新代码放置规则

新增目录前同时满足：

1. 有可运行实现，而不是只有接口占位或未来计划。
2. 责任无法自然归入现有目录。
3. 有无硬件测试，或明确列入人工验收。
4. README 状态和本页定位表同步更新。

一个具体职责优先使用一个模块；不要为单个小文件建立新的顶层包。CLI 只解析参数和调用领域函数，业务校验留在可测试模块。未来模块的落地顺序见[后续优先级](后续优先级.md)，不提前创建空目录。

## 实时与测试边界

- 采集线程持续排空输入，只保存最新帧。
- 去畸变每帧最多一次；完整 BEV 仅按需生成并在同帧复用。
- 录像、可视化、日志和通信不得用无界队列阻塞实时路径。
- `tests/` 只能包含开发机可执行的自动测试。
- `manual_tests/` 承载相机、Hailo、GUI、固定安装和整车验收；脚本必须自行释放资源。
