# 项目结构

本页只回答两个问题：一个功能现在在哪里，以及新代码应该放在哪里。实现状态以 [README](../README.md) 为准，任务顺序以 [后续优先级](后续优先级.md) 为准。

## 当前目录

```text
rescue_vision/
├── configs/runtime.example.yaml       # 可移植运行配置模板
├── configs/runtime.yaml               # 本机实际配置，不提交
├── configs/runtime.simulation-20min.yaml # 20 分模拟赛临时配置（编码器+IMU、无视觉定位）
├── docs/                              # 规则、路线图和专项操作文档
├── examples/                          # 明确标为合成的 schema 夹具
├── manual_tests/                      # 真机和 GUI 人工验收
├── src/rescue_vision/
│   ├── app/                          # 手动采集、解团试验和受限模拟赛入口
│   ├── calibration/                  # 标定采集与求解命令
│   ├── camera/                       # 帧、真机源、回放、记录
│   ├── communication/                # UART 与运动/夹爪/采集远程消息通信
│   ├── config/                       # 运行配置加载与装配
│   ├── data/                         # 数据清单和划分命令
│   ├── evaluation/                   # 离线指标与报告命令
│   ├── geometry/                     # 坐标、去畸变、地面投影
│   ├── localization/                 # 中心十字绝对观测与编码器/IMU 连续融合
│   ├── mission/                      # 规则状态机、事件回放与抽象动作
│   ├── motion/                       # 差速运动、电控协议与远程调试执行
│   ├── perception/                   # 任务目标 Pose 与场地特征观测契约
│   ├── tracking/                     # 目标时间关联、遮挡与轨迹生命周期
│   ├── world/                        # 静态区域、动态目标和不确定性快照
│   ├── exception_notes.py            # Python 3.10+ 异常清理备注兼容
└── tests/                            # 无硬件 pytest
```

没有通用 `planning/` 或正式比赛 `app.py`。`localization/` 已实现 v3 中心十字/
安全区定位、单帧去重和编码器/IMU 连续融合；传统全图 OpenCV 场地检测已删除，
同一六类 Hailo 模型统一生产目标和地标，正式模型资产与实测地标仍待验收；
真车参数和性能仍未验收。`app/manual_capture.py` 负责赛外受监督手动驾驶、图传和
相机采集；`app/cluster_breakup.py` 是解团权威实现；`app/simulation_20_point.py`
编排四个绿色普通物资的受限模拟赛初版，并把控制意图交给 `MotionController`，
但真实接触传感器、现场区域证据、固件看门狗和正式比赛扩展仍未完成。每个已
实现包的常用入口和实际对接示例见
[`src/rescue_vision/README.md`](../src/rescue_vision/README.md)。

## 模块边界

```text
Camera Frame
    │
    └── CameraModel ──> 去畸变帧 ──┬─> Recorder（采集）──> RecordingSource
                                   ├─> TargetPoseDetector
                                   │          └─> TargetObservation
                                   │                     │
                                   │                     ▼
                                   │            MultiTargetTracker
                                   │                     │
                                   │                     ▼
                                   │                 WorldModel
                                   └─> 同一 YOLO Pose v3 场地类别分流
                                              │
                                              └─> FieldFeatureDetectionResult
                                                         │
                                                         ▼
                                                CenterCrossLocalizer
                                                         │
                                                         ▼
                                           CenterCrossPoseObservation
                                                         │
                                                         ▼
                                           OdometryImuFusion
                                                    ▲
                                                    │
                                      UART 单消费者分发 OdometryImu

GroundProjector ──> TargetPoseDetector / v3 中心十字与安全区地面投影
WorldModel ──> MissionStateMachine
```

- `camera` 负责帧的产生、生命周期、回放和记录；录制 CLI 在装配层调用 `CameraModel`，记录器本身不复制几何实现。
- `communication` 维护 UART 和直接 TCP 远程消息的可靠交付，并在 `observe_only` 拒绝运动/夹爪/采集控制、允许不执行动作的图像模式请求；它不把调试运动意图解释成轮速，也不把夹爪扳机状态解释成舵机角度，不生成图像内容或地图。
- `motion` 消费调用方注入的 UART COBS 帧通道和远程控制消息，负责 v3 固定二进制协议、统一命令序号、柔和停车安全同步、差速换算、夹爪机械端点/速度标定、双舵机渐进编码、限值、有效期、死手和停车；它不创建串口/TCP，不解释比赛任务，也不提供定位依赖的目标朝向控制。树莓派端已按[树莓派与单片机通信协议 v3](树莓派与单片机通信协议v3.md)删除旧文本格式兼容层，真车联调和标定仍待验收。
- `geometry` 不创建相机，也不解释比赛类别。
- 任务目标检测器消费去畸变帧和显式配置：Pose 后端提供框与 K0，ROI HSV 提供主类别和局部分割掩码；输出仍带帧号、时间、坐标系、置信度和质量标记。
- 目标地面几何估计器消费 `TargetObservation` 的 ROI 掩码、K0 和配置化三维形状，通过 `GroundProjector` 的完整外参投影输出机器人系中心、足迹、朝向和不确定度；不覆盖 K0，也不产生 `FieldPoint`。
- 传统全图 OpenCV 场地特征检测器与局部场界估计器已删除；同一 v3 六类模型
  一次推理分流四类目标、中心十字和安全区。出发区与场界不在 v3 感知结果中；
  中心十字只允许在模型 bbox 内做局部轴线精修。
- 中心十字定位器只消费同一帧且带机器人地面坐标的场地特征；输出四向位姿候选，并用红/蓝安全区或时间对齐的先验保守选择唯一解。静态地标追踪器另外缓存有界身份/搜索证据，连续三帧漏检后恢复全场搜索；旧观测不会重复融合。安全区角点定位器用新鲜入口角点对或三/四角产生独立绝对位姿。
- 固定场界、红蓝安全分区、出发区和中心十字终端只由 `world.static_map` 配置；`team_color` 把物理区域派生为任务状态机使用的己方/对方语义。感知颜色阈值仍属于 `perception`，定位关联门限仍属于 `localization`。
- 跟踪器消费同帧观测；世界模型消费轨迹和外部区域/对手证据；规则状态机只消费世界快照和显式接触/交付/安全事件。
- 完整车辆手动入口把唯一 UART 消费回调中的 `OdometryImu` 分发给融合器；三轴 IMU 字段保留传感器坐标系，由 `localization.fusion.imu_calibration` 在输入边界依次执行温度零偏、交叉轴/比例和安装旋转校正。当前不再运行中心十字视觉旁路，地图发布的是编码器+IMU 连续推算位姿；遥测过期或连续性丢失时清除机器人标记。仅相机模式不创建融合器。
- `motion` 统一校验 CRC、固定长度、方向、枚举和值域并解析二进制命令回复、系统状态和编码器/IMU 遥测；损坏帧丢弃后继续同步。算法模块不得直接创建或读取 PySerial 对象。

地面坐标调用链固定为
`RawPixel → UndistortedPixel → GroundPoint ↔ BevPixel`；离地目标点使用
`UndistortedPixel ↔ RobotPoint3D` 的完整外参投影。完整定义见
[`geometry` README](../src/rescue_vision/geometry/README.md)。
机器人地面系原点是两驱动轮接地点中点；`FieldPoint` 原点是场地中心十字点划线
交点，`+x` 向右、`+y` 指向红色安全区。`FieldPoint` 只在中心十字定位器输出
唯一 `FieldPose2D` 或连续融合具有有效绝对锚点时产生，不得由局部 `GroundPoint` 直接替代。

## 新代码放置规则

新增目录前同时满足：

1. 有可运行实现，而不是只有接口占位或未来计划。
2. 责任无法自然归入现有目录。
3. 有无硬件测试，或明确列入人工验收。
4. README 状态和本页定位表同步更新。

一个具体职责优先使用一个模块；不要为单个小文件建立新的顶层包。CLI 只解析参数和调用领域函数，业务校验留在可测试模块。未来模块的落地顺序见[后续优先级](后续优先级.md)，不提前创建空目录。

## 实时与测试边界

- 采集线程持续排空输入，只保存最新帧。
- 去畸变每帧最多一次；完整 BEV 仅按需生成并在同帧复用。
- 录像、可视化、日志和通信不得用无界队列阻塞实时路径。
- `tests/` 只能包含开发机可执行的自动测试。
- `manual_tests/` 承载相机、Hailo、GUI、固定安装和整车验收；脚本必须自行释放资源。
