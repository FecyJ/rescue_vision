# 项目结构

本页只回答两个问题：一个功能现在在哪里，以及新代码应该放在哪里。实现状态以 [README](../README.md) 为准，任务顺序以 [后续优先级](后续优先级.md) 为准。

## 当前目录

```text
rescue_vision/
├── configs/runtime.example.yaml       # 可移植运行配置模板
├── configs/runtime.yaml               # 本机实际配置，不提交
├── docs/                              # 规则、路线图和专项操作文档
├── examples/                          # 明确标为合成的 schema 夹具
├── manual_tests/                      # 真机和 GUI 人工验收
├── src/rescue_vision/
│   ├── app/                          # 跨模块入口；当前仅手动驾驶采集
│   ├── calibration/                  # 标定采集与求解命令
│   ├── camera/                       # 帧、真机源、回放、记录
│   ├── communication/                # UART 与运动/夹爪/采集远程消息通信
│   ├── config/                       # 运行配置加载与装配
│   ├── data/                         # 数据清单和划分命令
│   ├── evaluation/                   # 离线指标与报告命令
│   ├── geometry/                     # 坐标、去畸变、地面投影
│   ├── mission/                      # 规则状态机、事件回放与抽象动作
│   ├── motion/                       # 差速运动、电控协议与远程调试执行
│   ├── perception/                   # 任务目标 Pose 与传统视觉场地特征
│   ├── tracking/                     # 目标时间关联、遮挡与轨迹生命周期
│   ├── world/                        # 静态区域、动态目标和不确定性快照
│   ├── exception_notes.py            # Python 3.10+ 异常清理备注兼容
└── tests/                            # 无硬件 pytest
```

没有 `localization/`、`planning/` 或比赛 `app.py`，因为这些能力尚未实现。`app/manual_capture.py` 只装配赛外受监督手动驾驶、图传和相机采集，不解释任务规则，也不等于比赛应用。`motion/` 尚未把规则状态机抽象动作接到规划和底盘；真实接触/交付证据适配也尚未落地。每个已实现包的常用入口和实际对接示例见 [`src/rescue_vision/README.md`](../src/rescue_vision/README.md)。

## 模块边界

```text
Camera Frame
    │
    └── CameraModel ──> 去畸变帧 ──┬─> Recorder（采集）──> RecordingSource
                                   ├─> TargetPoseDetector
                                   │          └─> TargetObservation
                                   │                     ├─> TargetGroundGeometryEstimator
                                   │                     │          └─> TargetGroundGeometry
                                   │                     │
                                   │                     ▼
                                   │            MultiTargetTracker
                                   │                     │
                                   │                     ▼
                                   │                 WorldModel
                                   └─> FieldFeatureDetector
                                              │
                                              └─> FieldFeatureDetectionResult
                                                         │
                                                         ▼
                                                定位（P4，未实现）

GroundProjector ──> TargetPoseDetector / TargetGroundGeometryEstimator / FieldFeatureDetector
WorldModel ──> MissionStateMachine
```

- `camera` 负责帧的产生、生命周期、回放和记录；录制 CLI 在装配层调用 `CameraModel`，记录器本身不复制几何实现。
- `communication` 维护 UART 和直接 TCP 远程消息的可靠交付，并在 `observe_only` 拒绝远程控制；它不把调试运动意图解释成轮速，也不把夹爪扳机状态解释成舵机角度，不实现图传或地图。
- `motion` 消费调用方注入的 UART 行通道和远程控制消息，负责差速换算、夹爪机械端点/速度标定、双舵机渐进编码、限值、有效期、死手和停车；它不创建串口/TCP，不解释比赛任务，也不提供定位依赖的目标朝向控制。
- `geometry` 不创建相机，也不解释比赛类别。
- 任务目标检测器消费去畸变帧和显式配置：Pose 后端提供框与 K0，ROI HSV 提供主类别和局部分割掩码；输出仍带帧号、时间、坐标系、置信度和质量标记。
- 目标地面几何估计器消费 `TargetObservation` 的 ROI 掩码、K0 和配置化三维形状，通过 `GroundProjector` 的完整外参投影输出机器人系中心、足迹、朝向和不确定度；不覆盖 K0，也不产生 `FieldPoint`。
- 场地特征检测器与任务目标检测器并行消费同一去畸变帧；按需生成并复用一次 BEV，输出安全区、无编号出发区、中心十字和低精度边界候选，不直接更新世界模型。
- 跟踪器消费同帧观测；世界模型消费轨迹和外部区域/对手证据；规则状态机只消费世界快照和显式接触/交付/安全事件。
- 定位尚未实现；缺少 `FieldPoint` 时世界模型保留不确定性，不伪造区域结论。
- `motion` 已统一解析命令回复、轮速遥测和未知前缀；未来 IMU 复用同一解析入口或新增显式消息类型。算法模块不得直接创建或读取 PySerial 对象。

地面坐标调用链固定为
`RawPixel → UndistortedPixel → GroundPoint ↔ BevPixel`；离地目标点使用
`UndistortedPixel ↔ RobotPoint3D` 的完整外参投影。完整定义见
[`geometry` README](../src/rescue_vision/geometry/README.md)。

## 新代码放置规则

新增目录前同时满足：

1. 有可运行实现，而不是只有接口占位或未来计划。
2. 责任无法自然归入现有目录。
3. 有无硬件测试，或明确列入人工验收。
4. README 状态和本页定位表同步更新。

一个具体职责优先使用一个模块；不要为单个小文件建立新的顶层包。CLI 只解析参数和调用领域函数，业务校验留在可测试模块。未来模块的落地顺序见[后续优先级](后续优先级.md)，不提前创建空目录。

## 实时与测试边界

- 采集线程持续排空输入，只保存最新帧。
- 去畸变每帧最多一次；完整 BEV 仅按需生成并在同帧复用。
- 录像、可视化、日志和通信不得用无界队列阻塞实时路径。
- `tests/` 只能包含开发机可执行的自动测试。
- `manual_tests/` 承载相机、Hailo、GUI、固定安装和整车验收；脚本必须自行释放资源。
