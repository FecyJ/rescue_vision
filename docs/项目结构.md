# 项目结构

仓库以坐标、感知、定位、运动和任务规则为边界。正式流程只有一个权威实现
（`app/match.py`），其余入口是职责明确的变体；CLI 只负责
参数解析和对象装配，规则和动作放在可测试领域模块。

```text
configs/
  runtime.example.yaml       # 新配置模板
  runtime.match.yaml         # 正式流程配置
  runtime.cc.yaml            # CC 独立流程配置
  runtime.match_nb.yaml      # 当前 match 的简化开场变体配置
  runtime.strategy.yaml      # 蓝色优先策略变体配置
docs/                         # 规则、流程、验收和路线图
manual_tests/                 # 真机、相机、GUI 和通信验收
src/rescue_vision/
  app/                        # 正式流程、联调、解团、采集和独立测试入口
    breakup_planner.py        # 基于实际 K0 的纯逻辑局部解团规划
    match_strategy.py         # 蓝色优先策略变体（match 的子类，两阶段）
    teach_replay.py           # 手推编码器/IMU 示教日志与受监督轮轨迹回放
  calibration/                # 相机内参和地面外参
  camera/                     # 帧源、回放和记录
  communication/              # UART/TCP 与观察消息
  config/                     # 严格 YAML 配置和装配
  geometry/                   # 坐标、去畸变和地面投影
  localization/               # 视觉锚点和编码器/IMU 融合
  mission/                    # 比赛规则状态机
  motion/                     # 底盘、夹爪和 STM32 协议
  perception/                 # Pose、颜色和场地特征
  tracking/                   # 轨迹生命周期
  world/                      # 静态地图、动态目标和不确定性
tests/                        # 无硬件 pytest
```

## 应用职责

| 责任 | 权威实现 |
| --- | --- |
| 正式比赛动作流程和 d1 视觉纠偏 | `app/match.py` |
| CC 独立解团、单块搜索与抓取编排 | `app/match_cc.py`（安全区运输复用 `app/match.py`） |
| 正式流程硬件生命周期、预览和观察发布 | `app/match_runtime.py`、`app/match_observers.py` |
| 末端张爪推送—运输联调（不解团） | `app/grab_transport.py` |
| match 开场变体（两次转向、两段前进、一次倒车） | `app/match_nb.py`（复用 `app/match.py` 与 `app/match_runtime.py`） |
| 蓝色优先策略变体（开场两段冲刺 → 只搜蓝色危险物块 → 两趟 D2 投放 → 翻转入正式流程） | `app/match_strategy.py`（`app/match.py` 的子类；正式阶段显式委托回基类） |
| 固定解团试验 | `app/cluster_breakup.py` |
| 正式流程动态局部解团规划 | `app/breakup_planner.py`（`match` 使用；CC 保持固定动作） |
| 近场抓取与解团共用的连续静止证据 | `motion/stationary.py`（由实际编码器/IMU更新，跨应用会话保留） |
| 正式流程与独立入口共用的近场收拢几何/状态机 | `app/match.py`、`app/match_runtime.py`、`app/gripper_width.py`、`app/near_field_grasp.py`、`app/gripper_width_sequence.py`、`perception/gripper_width.py`、`motion/gripper_kinematics.py` |
| 目标短时记忆（可复用，尚未接入正式流程） | `app/scan_target_memory.py` |
| 带身份的场地目标聚类（可复用，尚未接入正式流程） | `app/field_target_cluster.py` |
| 终端日志 | `app/session_log.py` |
| D2→安全区末段逐帧遥测 | `motion/d2_safe_zone_telemetry.py` |
| 正式流程设计 | `docs/正式流程设计.md` |
| 固定加速度动作 TUI | `app/motion_sequence.py` |

`scan_target_memory.py` 只提供场地点记忆、老化和重投影的纯逻辑；正式流程当前不调用
它，也不复制采集时刻位姿对齐或记忆目标接管逻辑。`field_target_cluster.py` 只提供
确定性的 `FieldPoint` 连通聚类，同样不改变正式流程的实时轨迹选择。

## 坐标和实时约束

跨模块点必须使用 `RawPixel`、`UndistortedPixel`、`GroundPoint`、`FieldPoint` 等
带语义类型。机器人坐标为 `x` 向前、`y` 向左、`z` 向上，单位 mm；场地坐标原点为
中心十字点划线交点。`CameraModel` 是唯一去畸变实现，`GroundProjector` 是唯一地面
投影实现。

运动循环只消费最新观测；相机、推理、录像、预览、日志和网络发布通过有界旁路运行。
旁路故障不能自行升级为停车，只有运动或任务层的明确风险才能触发停车。
