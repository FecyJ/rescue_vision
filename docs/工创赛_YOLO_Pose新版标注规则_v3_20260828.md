# 工创赛智能救援 · YOLO Pose 新版标注规则

> 版本：v3
> 日期：2026-08-28
> 适用：任务物体识别、地面坐标定位、中心十字与安全区视觉定位
> 标注工具：X-AnyLabeling
> 模型：YOLO Pose

---

## 1. 总体设计

统一采用 3 个关键点槽位：

```yaml
kpt_shape: [3, 3]

kpt_names:
  - ground_anchor
  - image_left_landmark
  - image_right_landmark

flip_idx: [0, 2, 1]
```

统一语义：

- **K0 / ground_anchor**：该实例最重要的地面定位锚点。
- **K1 / image_left_landmark**：仅安全区使用，当前去畸变图像中靠主场地侧两个角点里水平坐标 `u` 更小的点。
- **K2 / image_right_landmark**：仅安全区使用，当前去畸变图像中靠主场地侧两个角点里水平坐标 `u` 更大的点。
- 当前类别不使用的关键点统一记为 `0 0 0`。

设计原则：

1. 关键点必须有唯一、明确、可重复的物理定义。
2. 不使用 bbox 中心、视觉质心等随视角变化明显的弱定义。
3. 关键点直接服务于像素坐标到地面/场地坐标的转换。
4. 安全区局部几何检测与“红区/蓝区身份判定”解耦。
5. 宁可将不确定关键点置为不可用，也不加入伪精确标签。

---

## 2. 类别定义

统一采用 6 类：

```yaml
names:
  0: green_supply
  1: black_core
  2: orange_injured
  3: blue_danger
  4: center_cross
  5: safe_zone
```

其中红色安全区与蓝色安全区合并为同一类 `safe_zone`。

模型只负责回答“这里是否有安全区，以及它的关键几何点在哪里”；安全区到底对应红区还是蓝区，由后续定位模块结合颜色、机器人粗位姿、IMU、里程计、上一帧结果和地图几何进行数据关联。

---

## 3. 场地坐标系约定

统一使用固定场地坐标系：

- `+Y`：指向红色安全区，即场地上侧。
- `+X`：指向场地右侧。
- 场地中心十字几何中心为世界坐标原点 `(0, 0)`。

所有世界坐标、地图 landmark、Homography/PnP 和后续视觉定位均必须遵守该定义。

---

## 4. 关键点可见性

每个关键点格式为 `(x, y, v)`。

### v = 2：可见

满足以下之一：

- 关键点对应的真实视觉结构直接可见；
- 对任务物体底面中心，虽然中心本身被物体遮挡，但物体姿态和底面几何结构完整，可稳定、唯一地确定中心。

### v = 1：遮挡但可可靠推断

关键点本身被局部遮挡，但当前图像中的相关几何结构足够，能唯一、稳定地推断其位置。

例如：

- 安全区 K0 的物理交点被围栏遮挡，但中心点划线中心轴和围栏基准线均清晰；
- 安全区角点被局部遮挡，但形成该角的两条边均可稳定拟合。

### v = 0：不可用

以下情况统一记为：

```text
0 0 0
```

包括：

- 关键点在图像外；
- 严重遮挡；
- 相关结构不足；
- 只能大致猜测；
- 多种位置都合理；
- 图像过于模糊或分辨率过低；
- 当前类别根本不使用该关键点。

# 5. 四类任务物体

适用：

```text
green_supply
black_core
orange_injured
blue_danger
```

## 5.1 Bounding Box

- bbox 紧密覆盖该实例的可见外轮廓。
- 不包含明显多余背景。
- 不把相邻物体框进同一个实例。
- 阴影、地面反光不属于物体。
- 单个真实物体对应一个实例。

## 5.2 K0：底面几何中心

统一定义：

> **K0 = 物体与地面接触底面的真实几何中心在当前图像中的投影。**

不是：

- bbox 底边中心；
- bbox 几何中心；
- 可见轮廓最低点；
- 可见底边中点；
- 视觉质心；
- 阴影中心。

### 正方体 / 长方体

K0 为真实接触底面的几何中心投影。

若中心本身不可见，但根据完整可见结构能稳定确定，标 `v=1`；若无法唯一确定，则 `0 0 0`。

### 正四面体

若以完整三角形面平放，K0 为该接触三角形面的几何中心投影。

## 5.3 K1 / K2

四类任务物体均不使用：

```text
K1 = 0 0 0
K2 = 0 0 0
```

---

# 6. 中心十字

类别：

```text
center_cross
```

## 6.1 Bounding Box

bbox 应紧密覆盖能明确表达“中心十字”结构的主要区域，并保留足够上下文，使模型可以区分普通场地线与真正的中心交叉结构。

不需要把整条中心线都框入 bbox。

## 6.2 K0：中心十字交点

定义：

> **K0 = 两条场地中心线几何中心轴的交点。**

它对应固定世界坐标：

```text
(0, 0)
```

标注时：

- 使用线带中心轴，而不是某一侧边缘；
- 点划线存在间断时，根据多个线段拟合中心轴；
- 不使用 bbox 中心代替；
- 不使用某一个黑色像素块的质心代替。

## 6.3 K1 / K2

中心十字不使用：

```text
K1 = 0 0 0
K2 = 0 0 0
```

场地方向建议在推理后通过局部直线拟合获得，而不是人为设置缺乏唯一视觉结构的 Pose 辅助点。

---

# 7. 安全区

类别统一为：

```text
safe_zone
```

红色与蓝色安全区使用同一类别。

## 7.1 Bounding Box

bbox 应覆盖能够稳定识别安全区的主体结构，建议包含：

- 安全区围栏；
- 内部可见区域；
- 靠主场地侧的围栏边；
- 必要的少量周围场地结构。

注意：

- bbox 仅用于实例识别，本身不承担精确世界坐标含义。
- 内部任务物体遮挡时，安全区仍是一个实例。
- 红区与蓝区标注风格保持一致。

---

# 8. 安全区 K0

定义：

> **K0 = 场地中心点划线的几何中心轴，与安全区靠主场地侧围栏“地面基准线”的交点。**

即：

```text
centerline_axis ∩ near_field_fence_ground_reference
```

该点是固定地面 landmark。

## 8.1 围栏地面基准线必须统一

紫色围栏本身有明显宽度，因此团队必须一次性确定到底采用哪一条物理边界：

优先级：

1. 官方场地图明确规定的安全区边界线；
2. 若官方未明确，则统一选取一条最稳定、可实测世界坐标的围栏地面边界；
3. 一旦确定，所有图片严格使用同一基准。

禁止：

- 有时取内沿、有时取外沿；
- 用围栏顶部可见边代替地面边界；
- 直接取视觉上最显眼的紫色边。

## 8.2 K0 可见性

`v=2`：
- 中心点划线中心轴和围栏地面基准线都清楚，交点可直接确定。

`v=1`：
- 交点本身被围栏遮挡，但两条线均可稳定延长求交。

`v=0`：
- 点划线可见长度不足；
- 围栏基准边无法确定；
- 交点出画面；
- 只能根据整个安全区大概位置猜。

---

# 9. 安全区 K1 / K2

K1、K2 为安全区**靠主场地侧边界的两个地面角点**。

关键定义：

> **K1 / K2 按当前去畸变图像中的左右关系定义，而不是按世界坐标 ±X 定义。**

设两个近场角点水平像素坐标分别为 `u_a`、`u_b`：

```text
K1 = u 更小的角点
K2 = u 更大的角点
```

标注导出必须始终满足：

```text
u(K1) < u(K2)
```

运行时模型输出允许 K1/K2 偶发互换。后处理在两个点同时有效时按当前去畸变
图像的 `u` 坐标交换整组关键点和置信度，恢复为 K1=图像左点、K2=图像右点；
只有一个点有效时不猜测另一个点，也不强制交换。

因此：

```text
K1 = image_left_landmark
K2 = image_right_landmark
```

## 9.1 为什么使用图像左右

这样可以：

- 不要求标注员先知道机器人朝向；
- 不要求先判断红区还是蓝区；
- 避免让模型隐式学习场地全局 ±X；
- 即使红/蓝底色被内部物体完全遮挡，仍然可以标注；
- 让 Pose 前端只承担“关键点在哪里”的感知任务；
- 把红/蓝身份和世界角点关联交给后端定位模块。

同一个真实物理角点，在不同视角下可以有时是 K1、有时是 K2，这是允许且正确的。

K1/K2 是**单帧图像语义**，不是跨帧保持不变的物理身份。

## 9.2 K1 / K2 的物理位置

K1、K2 均定义为：

> **安全区靠主场地侧围栏地面基准线，与对应侧围栏地面基准线的交点。**

因此不得标为：

- 围栏顶部角；
- 紫色框外轮廓顶部角；
- bbox 角；
- 红/蓝底板纹理角；
- 围栏装饰、拼接缝或铰接结构。

K0、K1、K2 必须使用同一套“地面基准线”定义。

## 9.3 K1 / K2 可见性

`v=2`：
- 构成角点的两条地面边界清楚可见。

`v=1`：
- 角点本身被局部遮挡，但两条边均可稳定拟合并延长求交。

`v=0`：
- 角点出画面；
- 两条组成边缺失过多；
- 严重遮挡；
- 图像过于模糊，无法稳定确定角点。

当两个角点水平位置几乎重合时，仍严格按当前 `u` 排序；推理后端不依赖 K1/K2 的跨帧物理身份。

# 10. 红/蓝安全区身份判定

模型统一输出：

```text
safe_zone
```

推理后再判定：

```text
red
blue
unknown
```

推荐证据：

1. 安全区底色明显可见时，使用颜色；
2. 当前机器人粗位姿；
3. IMU yaw；
4. 编码器 / 里程计；
5. 上一帧稳定结果；
6. center_cross 等其它固定 landmark；
7. 分别假设为红区 / 蓝区后比较定位一致性和重投影误差。

颜色完全被遮挡时，不强制依赖颜色分类。

---

# 11. K1 / K2 与世界角点的数据关联

由于 K1/K2 是当前图像左右语义，推理时不能写死：

```text
K1 -> 世界 -X
K2 -> 世界 +X
```

当安全区身份已知时，测试两种角点对应：

```text
假设 A：
K1_image -> world_corner_A
K2_image -> world_corner_B

假设 B：
K1_image -> world_corner_B
K2_image -> world_corner_A
```

当安全区身份也未知时，枚举：

```text
red × 2 种角点排列
blue × 2 种角点排列
```

共 4 个假设。

再根据以下信息选取最合理的一组：

- 重投影误差；
- 当前粗位姿；
- IMU；
- 里程计；
- center_cross；
- 上一帧定位结果。

---

# 12. 安全区三点几何关系

安全区通常满足：

```text
K1 ----- K0 ----- K2
```

三点位于同一条靠主场地侧围栏地面基准线上。

若 K0 对应 K1/K2 世界线段的几何中点，则应在**地面世界坐标中**满足：

```text
P0 ≈ (P1 + P2) / 2
```

不要在图像像素坐标中强制：

```text
K0 = (K1 + K2) / 2
```

因为透视投影一般不保持欧氏中点。

---

# 13. 图像坐标体系

训练、标注、推理和定位必须使用同一坐标体系。

推荐固定流程：

```text
原始相机图像
→ 固定去畸变
→ 保留完整去畸变画布
→ 无效区域固定填充
→ 标注
→ 训练
→ 推理
→ 还原关键点到统一去畸变画布坐标
→ Homography / 几何定位
```

禁止：

- 标注后再改变裁剪区域；
- 混用原图坐标与去畸变图坐标；
- 直接把 YOLO Letterbox 坐标送入地面 Homography。


# 17. 实例关联规则

一个 Pose 实例中的：

```text
bbox
K0
K1
K2
```

必须属于同一个真实实例。

在 X-AnyLabeling 中：

- Rectangle 与 Point 使用相同 `group_id`；
- 不同实例不能串组；
- safe_zone 的 K0/K1/K2 均与该安全区 bbox 同组；
- 多个任务物体相互遮挡时，各自保持独立实例。

# 18. 常见错误

## 四类任务物体

错误：

```text
K0 = bbox 底边中心
K0 = 可见轮廓最低点
K0 = 可见底边中点
K0 = 视觉中心
```

正确：

```text
K0 = 真实底面几何中心投影
```

## 中心十字

错误：

```text
K0 = bbox 中心
K0 = 某一段点划线中点
K0 = 某个黑色块中心
```

正确：

```text
K0 = 两条中心线几何中心轴交点
```

## 安全区 K0

错误：

```text
K0 = 安全区整体中心
K0 = 红/蓝区域质心
K0 = 围栏视觉中心
```

正确：

```text
K0 = 中心点划线中心轴 × 近场围栏地面基准线
```

## 安全区 K1/K2

本版禁止使用：

```text
K1 = 世界 -X 角
K2 = 世界 +X 角
```

正确：

```text
K1 = 当前去畸变图像中 u 较小的近场角
K2 = 当前去畸变图像中 u 较大的近场角
```

# 20. 推理输出建议

统一输出：

```python
{
    "class": "...",
    "bbox": [x1, y1, x2, y2],
    "keypoints": {
        "k0": [u0, v0, conf0],
        "k1": [u1, v1, conf1],
        "k2": [u2, v2, conf2],
    }
}
```

四类物体和中心十字：

```text
K1/K2 = invalid
```

安全区：

```text
K0/K1/K2 均可参与定位
```

安全区身份由后端维护：

```python
{
    "safe_zone_identity": "red" | "blue" | "unknown"
}
```

# 21. 后续定位使用

## 四类任务物体

```text
物体 K0
→ 统一去畸变画布坐标
→ 地面 Homography / 射线与地面求交
→ 物体底面中心世界坐标
```

## 中心十字

```text
center_cross.K0
↔
世界坐标 (0, 0)
```

作为固定 landmark。

## 安全区

```text
safe_zone.K0/K1/K2
→ 局部 Pose 观测
→ 枚举 red / blue 身份
→ 枚举 K1/K2 世界角点对应
→ 与粗位姿、IMU、里程计、center_cross 联合验证
→ 确定地图关联
→ 参与机器人 (x, y, yaw) 定位
```

建议后续增加局部传统视觉精修：

```text
Pose 关键点
→ 小 ROI
→ 颜色 / Canny / LSD / fitLine
→ 围栏地面边线拟合
→ 交点精修
→ refined K0/K1/K2
```

Pose 负责鲁棒找到 landmark，传统视觉负责在结构清晰时进一步提高几何定位精度。
