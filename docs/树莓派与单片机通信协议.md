# 树莓派与单片机通信协议

本文是树莓派视觉计算端与 STM32 底盘控制端之间通信接口的唯一权威。它面向
长期运行、运动安全和编码器/IMU 定位，替代现有 Rescue Car 文本行协议。

当前仓库和 STM32 固件尚未实现本文协议；两端应在同一次联调中直接切换，
不保留 `m...`、`g...`、`t...`、`s1...`、`OK` 或 `ERR` 的兼容解析。

本文不规定 IMU 模块自身的 UART/I²C 协议。STM32 负责读取、校验和时间戳 IMU
数据，再按本文统一发送；不得把 IMU 厂商的二进制帧透明转发到树莓派。

## 1. 设计边界

- 物理链路固定为 UART 115200、8N1、无硬件流控。
- 线路只有一种二进制分帧，不混用调试文本、日志或 IMU 原始协议。
- 每种消息有固定布局。修改字段时同时修改两端和本文，不维护 schema 版本、
  兼容别名或能力协商。
- CRC16 只负责发现传输损坏，不提供认证或保密；协议不使用 SHA、签名、密钥、
  JSON、时间字符串或文件校验和。
- STM32 负责电机闭环、夹爪输出、失联停车、急停锁存、编码器采样和 IMU 采样。
- 树莓派负责机械标定参数、里程计/IMU/视觉融合和场地坐标，不向 STM32 下发
  全局位置，也不把 STM32 积分位置作为定位权威。

## 2. 帧格式

一帧在线路上的格式为：

```text
COBS(message_type | payload | crc16_le) | 0x00
```

- COBS 使用标准 Consistent Overhead Byte Stuffing；`0x00` 只作为帧结束符。
- 解码后的首字节是 `message_type`，末两字节是 CRC16，二者之间是固定长度
  payload；没有 magic、长度字段或结束字符串。
- 多字节整数统一为小端。协议不传输浮点数。
- CRC 使用 CRC-16/CCITT-FALSE：`poly=0x1021`、`init=0xFFFF`、
  `refin=false`、`refout=false`、`xorout=0x0000`。
- CRC 覆盖 `message_type | payload`，结果以小端 `uint16` 附在末尾。
  标准检查输入 ASCII `123456789` 的结果为 `0x29B1`。
- 解码后帧长度上限为 64 bytes。空帧、COBS 错误、超长、长度不符、未知类型或
  CRC 错误的帧直接丢弃，不刷新运动看门狗，也不回复错误帧。

接收端必须持续消费字节流。遇到损坏帧后丢弃到下一个 `0x00`，下一帧仍可正常
解析。发送端不得在同一 UART 输出 `printf` 调试文字。

## 3. 公共类型和时间

| 名称 | 宽度 | 说明 |
| --- | ---: | --- |
| `u8` / `i8` | 1 byte | 无符号/有符号整数 |
| `u16` / `i16` | 2 bytes | 小端整数 |
| `u32` / `i32` | 4 bytes | 小端整数 |
| `u64` / `i64` | 8 bytes | 小端整数 |

命令序号和周期遥测序号均为 `u16`，到 `65535` 后回到 `0`。树莓派发出的所有
命令共用一个命令序号；每种周期遥测各自维护序号。序号只用于关联回复和检测
丢帧，不用于持久身份或去重。连续性判断必须按模 `65536` 计算，`65535 → 0`
是正常连续帧。

`sample_timestamp_us` 和 `controller_timestamp_us` 是 STM32 从本次启动开始的
单调微秒计时，类型为 `u64`。定位帧必须填写传感器实际采样时刻，而不是 UART
开始发送的时刻。树莓派收到完整帧时另外记录本机 `monotonic_ns`；两台设备的
时间值不能直接相减。STM32 重启表现为控制器时间倒退，树莓派必须清除连续
积分状态，等待新的绝对视觉观测或重新初始化。

## 4. 树莓派到 STM32 的命令

### 4.1 设置轮速 `SET_WHEEL_SPEED`（`0x10`）

| 偏移 | 类型 | 字段 | 说明 |
| ---: | --- | --- | --- |
| 0 | `u8` | `message_type` | 固定 `0x10` |
| 1 | `u16` | `command_sequence` | 命令序号 |
| 3 | `i16` | `left_target_mm_s` | 左轮目标速度，正值向前 |
| 5 | `i16` | `right_target_mm_s` | 右轮目标速度，正值向前 |
| 7 | `u16` | `crc16` | 帧 CRC |

STM32 只接受固件安全限值内的速度。有效命令更新左右目标并刷新运动看门狗；
越界命令拒绝执行且不刷新看门狗。树莓派在运动使能期间必须周期重发当前目标，
建议 20–50 Hz，不能只在目标改变时发送。

### 4.2 柔和停车 `SOFT_BRAKE`（`0x11`）

| 偏移 | 类型 | 字段 | 说明 |
| ---: | --- | --- | --- |
| 0 | `u8` | `message_type` | 固定 `0x11` |
| 1 | `u16` | `command_sequence` | 命令序号 |
| 3 | `u16` | `crc16` | 帧 CRC |

有效命令把双轮目标设为零，按 STM32 已标定的制动斜率减速，并刷新看门狗。
制动斜率不逐条下发，避免两端维护两套运动约束。

### 4.3 紧急停止 `EMERGENCY_STOP`（`0x12`）

| 偏移 | 类型 | 字段 | 说明 |
| ---: | --- | --- | --- |
| 0 | `u8` | `message_type` | 固定 `0x12` |
| 1 | `u16` | `command_sequence` | 命令序号 |
| 3 | `u16` | `crc16` | 帧 CRC |

STM32 收到有效帧后立即关闭运动输出并锁存急停。本文不定义远程解除急停命令；
只能在目标为零时通过后续真机安全评审确认的现场动作解除。任何轮速命令和
树莓派重连都不得自动解除。

### 4.4 设置夹爪目标 `SET_GRIPPER`（`0x13`）

| 偏移 | 类型 | 字段 | 说明 |
| ---: | --- | --- | --- |
| 0 | `u8` | `message_type` | 固定 `0x13` |
| 1 | `u16` | `command_sequence` | 命令序号 |
| 3 | `u16` | `left_target_cdeg` | 左舵机目标，百分之一度 |
| 5 | `u16` | `right_target_cdeg` | 右舵机目标，百分之一度 |
| 7 | `u16` | `crc16` | 帧 CRC |

角度范围固定为 `0..18000`。夹爪机械开闭端点仍由树莓派运行配置保存；STM32
只执行显式双舵机目标和自身电气安全限制。夹爪命令不刷新运动看门狗；停车或
失联时保持最近夹爪目标，不自动释放物品。

### 4.5 查询状态 `QUERY_STATUS`（`0x14`）

| 偏移 | 类型 | 字段 | 说明 |
| ---: | --- | --- | --- |
| 0 | `u8` | `message_type` | 固定 `0x14` |
| 1 | `u16` | `command_sequence` | 命令序号 |
| 3 | `u16` | `crc16` | 帧 CRC |

有效命令立即触发一帧 `SYSTEM_STATUS`，但不刷新运动看门狗。

## 5. STM32 到树莓派的消息

### 5.1 命令回复 `COMMAND_REPLY`（`0x80`）

| 偏移 | 类型 | 字段 | 说明 |
| ---: | --- | --- | --- |
| 0 | `u8` | `message_type` | 固定 `0x80` |
| 1 | `u16` | `command_sequence` | 原命令序号 |
| 3 | `u8` | `command_type` | 原命令类型 |
| 4 | `u8` | `result` | 结果枚举 |
| 5 | `u16` | `crc16` | 帧 CRC |

`result` 固定为：

| 值 | 名称 | 含义 |
| ---: | --- | --- |
| 0 | `accepted` | 命令已通过校验并更新控制状态 |
| 1 | `out_of_range` | 数值超出固件安全范围 |
| 2 | `emergency_stop_latched` | 急停锁存，拒绝运动命令 |
| 3 | `device_unavailable` | 对应执行器当前不可用 |

每条长度和 CRC 正确的已知命令都返回一帧回复。`accepted` 只表示 STM32 接受了
目标，不表示电机或舵机已经物理到位。树莓派不得等待回复后才发送下一周期
轮速命令。

### 5.2 里程计与 IMU `ODOMETRY_IMU`（`0x81`）

该帧固定以 100 Hz 发送。编码器和 IMU 必须来自同一个采样周期；推荐在 IMU
data-ready 中断时锁存左右编码器累计计数并记录时间。不得用 UART 发送时刻
替代采样时刻。

| 偏移 | 类型 | 字段 | 单位/说明 |
| ---: | --- | --- | --- |
| 0 | `u8` | `message_type` | 固定 `0x81` |
| 1 | `u16` | `telemetry_sequence` | 本消息独立序号 |
| 3 | `u64` | `sample_timestamp_us` | STM32 单调采样时间 |
| 11 | `i64` | `left_encoder_count` | 左轮累计计数，正值向前 |
| 19 | `i64` | `right_encoder_count` | 右轮累计计数，正值向前 |
| 27 | `i32` | `gyro_x_urad_s` | 绕机器人 `+x` 角速度，µrad/s |
| 31 | `i32` | `gyro_y_urad_s` | 绕机器人 `+y` 角速度，µrad/s |
| 35 | `i32` | `gyro_z_urad_s` | 绕机器人 `+z` 角速度，µrad/s |
| 39 | `i32` | `accel_x_mm_s2` | 机器人 `+x` 加速度计读数，mm/s² |
| 43 | `i32` | `accel_y_mm_s2` | 机器人 `+y` 加速度计读数，mm/s² |
| 47 | `i32` | `accel_z_mm_s2` | 机器人 `+z` 加速度计读数，mm/s² |
| 51 | `i16` | `imu_temperature_cdeg` | IMU 温度，百分之一摄氏度 |
| 53 | `u16` | `sensor_flags` | 传感器状态位 |
| 55 | `u16` | `crc16` | 帧 CRC |

机器人坐标原点是两驱动轮接地点连线中点，`x` 向前、`y` 向左、`z` 向上，
角速度按右手系为正。车辆水平静止时，加速度计应近似
`(0, 0, +9807) mm/s²`。STM32 必须完成 IMU 安装轴到机器人轴的固定变换；
树莓派不再解释厂商坐标轴、四元数或欧拉角。

编码器累计值从 STM32 启动时的零点开始，运行中不得清零。两轮正值都表示
前进；必须包含实际采用的正交解码倍频和减速后的全部计数。每圈计数、有效
轮径和有效轮距属于树莓派机械标定，不放进每帧通信。

`sensor_flags` 位定义如下；未定义位必须为零：

| bit | 名称 | 为 1 的含义 |
| ---: | --- | --- |
| 0 | `imu_valid` | 本帧 IMU 数值可用 |
| 1 | `imu_calibrated` | 陀螺仪/加速度计校准可用 |
| 2 | `left_encoder_valid` | 左编码器可用 |
| 3 | `right_encoder_valid` | 右编码器可用 |
| 4 | `gyro_saturated` | 本周期陀螺仪饱和 |
| 5 | `accel_saturated` | 本周期加速度计饱和 |
| 6 | `sample_overrun` | 自上一帧后发生采样超期或漏采 |

树莓派只有在相应 `valid` 位有效时才能消费数据。饱和或超期帧可以记录，但
必须由融合层拒绝或显著降权。协议不发送磁力计、四元数、欧拉角或 STM32
积分位姿；这些数据对当前二维视觉融合不是必要输入，且磁力计容易受到电机和
车体材料干扰。

### 5.3 系统状态 `SYSTEM_STATUS`（`0x82`）

STM32 固定以 10 Hz 发送，并在收到 `QUERY_STATUS` 后额外立即发送一帧。

| 偏移 | 类型 | 字段 | 说明 |
| ---: | --- | --- | --- |
| 0 | `u8` | `message_type` | 固定 `0x82` |
| 1 | `u16` | `status_sequence` | 本消息独立序号 |
| 3 | `u64` | `controller_timestamp_us` | STM32 单调时间 |
| 11 | `u16` | `watchdog_timeout_ms` | 固件运动失联超时 |
| 13 | `u32` | `last_motion_command_age_ms` | 尚未收到时为 `0xFFFFFFFF` |
| 17 | `u16` | `system_flags` | 系统状态位 |
| 19 | `u8` | `stop_reason` | 当前运动状态枚举 |
| 20 | `u16` | `servo_left_target_cdeg` | 左舵机当前目标 |
| 22 | `u16` | `servo_right_target_cdeg` | 右舵机当前目标 |
| 24 | `u16` | `crc16` | 帧 CRC |

`system_flags` 位定义如下；未定义位必须为零：

| bit | 名称 | 为 1 的含义 |
| ---: | --- | --- |
| 0 | `watchdog_armed` | 运动失联看门狗已启用 |
| 1 | `emergency_stop_latched` | 急停已经锁存 |
| 2 | `motor_output_enabled` | 电机驱动输出当前允许 |
| 3 | `gripper_output_available` | 双舵机输出可用 |

`stop_reason` 固定为：

| 值 | 名称 | 含义 |
| ---: | --- | --- |
| 0 | `startup` | 启动后尚未接受运动命令 |
| 1 | `running` | 正常执行轮速目标，包括零目标 |
| 2 | `soft_brake` | 正在或已经柔和停车 |
| 3 | `watchdog_timeout` | 失联看门狗触发停车 |
| 4 | `emergency_stop` | 急停锁存停车 |

## 6. 安全行为

1. STM32 上电后轮速目标和电机输出为零，运动看门狗自动布防。
2. `watchdog_timeout_ms` 必须是固件固定安全参数，首版建议 300 ms；不得由
   树莓派逐条修改。
3. 只有通过 COBS、固定长度、CRC、类型和值域校验的 `SET_WHEEL_SPEED` 和
   `SOFT_BRAKE` 刷新运动看门狗。
4. `SET_GRIPPER`、`QUERY_STATUS`、损坏帧、未知帧和越界命令不得刷新看门狗。
5. 看门狗超时后，STM32 必须独立于树莓派进程把双轮目标和输出降为零，并持续
   报告 `watchdog_timeout`；UART 恢复后不得自动恢复旧目标。
6. 急停优先级高于全部运动命令并保持锁存。本文不允许通过通信解除急停。
7. 树莓派退出时应先发送 `SOFT_BRAKE`，但这不能替代 STM32 看门狗。

必须在架空轮和具备物理急停的条件下分别验证：停止树莓派发送、杀死进程、
拔出 UART、发送损坏帧、接收洪泛、STM32 重启和树莓派重启。只有实测在规定
时间内停车后，软件才可宣称固件看门狗可用。

## 7. 实时调度和队列

- STM32 必须优先处理 UART 接收和电机安全，不得因发送遥测阻塞控制循环。
- `ODOMETRY_IMU` 固定 100 Hz，`SYSTEM_STATUS` 固定 10 Hz；命令回复随命令产生。
- 发送拥塞时允许丢弃尚未发送的旧 `ODOMETRY_IMU`，保留最新样本；不得积累
  无界队列。`SYSTEM_STATUS` 和 `COMMAND_REPLY` 不得被普通遥测覆盖。
- 树莓派持续排空 UART。接收缓冲区溢出、连续定位遥测超期或系统状态过期均
  视为链路故障，并进入停车/定位降级路径。
- 115200 8N1 下，本协议 57-byte 解码定位帧经 COBS 后不超过 59 wire bytes；
  100 Hz 定位遥测约占 5.9 kB/s，给命令、状态和回复保留足够余量。

## 8. 定位消费约定

树莓派按相邻有效帧计算编码器增量和时间差：

```text
delta_left_count  = left_count[n]  - left_count[n-1]
delta_right_count = right_count[n] - right_count[n-1]
dt                = (timestamp_us[n] - timestamp_us[n-1]) / 1_000_000
```

每圈计数、左右轮有效半径、有效轮距、IMU 零偏和噪声全部来自树莓派运行配置。
融合层用编码器推算平移、用 `gyro_z_urad_s` 推算短时航向，并用中心十字视觉
位姿进行低频绝对纠偏。完整三轴陀螺仪和加速度计用于静止、倾斜、碰撞、饱和
和异常运动判断，不直接对平面位置做长期二次积分。

以下任一情况必须中断连续积分，而不是跨越异常拼接轨迹：

- STM32 时间倒退或相邻时间不递增；
- 遥测序号不满足模 `65536` 的前进关系，或丢帧导致时间间隔超过融合配置上限；
- 任一编码器 `valid` 位清零；
- 左右累计计数出现不符合机械上限的跳变；
- UART 接收溢出或定位遥测过期。

IMU 无效时可按配置短时退化为纯轮式里程计；编码器无效时不得用加速度计二次
积分伪造平面位置。磁力计、四元数或欧拉角若以后经整车验证确有必要，应新增
独立消息类型，而不是改变 `ODOMETRY_IMU` 的固定布局。

## 9. 两端实施顺序

1. STM32 实现 COBS、CRC、命令、安全状态和失联看门狗，先架空轮验证。
2. STM32 接入编码器与 IMU，同周期输出 `ODOMETRY_IMU` 并验证轴向、单位、
   采样周期、温度和状态位。
3. 树莓派以本文替换现有文本协议编码、解析和日志，不保留旧格式兼容层。
4. 完成无硬件协议测试、录制回放及损坏帧/丢帧/重启测试。
5. 真机标定每圈计数、轮径、轮距和 IMU 零偏，再实现连续融合与视觉纠偏。
