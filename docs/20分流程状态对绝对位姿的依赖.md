# 20 分流程状态对绝对位姿的依赖

本文回答一个问题：20 分模拟赛流程中，每个应用状态和跨状态机制对**机器人绝对
位姿**（`FusedPoseEstimate` 及其场系派生量）依赖到什么程度、具体逻辑是什么。

依据与边界：

- 状态定义与行为语义以 [20分模拟赛流程设计](20分模拟赛流程设计.md) 为准，
  规则事实以 [规则状态机设计](规则状态机设计.md) 为准；本文不改变任何设计权威；
- 代码位置以当前 `app/simulation_20_point.py`、`mission/state_machine.py`、
  `world/model.py` 实现为准，行号可能随改动漂移；
- "绝对位姿"指场地系 `FieldPoint` 位姿；当前配置
  `localization.enabled=false` 时它是"配置初始位姿 + 编码器/IMU 航迹推算"
  （流程设计 §5.4）。传统 OpenCV 场地特征检测已删除，场地特征模型推理后端
  尚未实现，因此 `localization.fusion.enabled=true` 也不会加入视觉纠偏。

## 1. 位姿如何进入系统

每控制周期 `step()` 只在一个位置把位姿注入世界快照
（`simulation_20_point.py:813-831`）：

```text
robot_field_point            = pose.pose.position
target.field_point           = _field_from_robot(pose.pose, track.ground_point)
                               即 场系目标点 = 位姿 ⊕ 机器人系视觉地面点
```

之后所有状态与规则都不再直接读 pose，而是消费 `WorldSnapshot` 里的这两份
场系数据。关键性质：

- `ground_point` 由视觉在机器人系给出，**精度与位姿无关**；
- 位姿误差只通过这一次 ⊕ 变换进入全场，误差既影响"机器人在哪"，也影响
  "目标在场系哪"；
- pose 缺失时 `target_field_points` 为空 → 各目标的 `field_point=None` →
  下游所有场系判定降级为保持或"无候选"。

## 2. 依赖分级

| 级别 | 含义 |
| --- | --- |
| 无 | 运动与判定只读机器人系视觉量（`ground_point`、图像居中）或编码器路程，不读 pose 及其场系派生量 |
| 存在性 | 只要求 pose 存在（非 `None`），数值不参与任何判定 |
| 低 | 判定/运动本体在机器人系闭环，但 pose 经场系派生量间接参与，或只影响精度 |
| 强 | 判定或运动控制直接使用场系坐标或位姿门限，位姿误差 1:1 进入结果 |

## 3. 各状态依赖总表

| 状态 | 依赖 | 位姿用途 | 位姿误差的直接后果 |
| --- | --- | --- | --- |
| `BOOT` | 无 | 只创建未打开资源 | — |
| `PREFLIGHT` | 存在性 | 融合首个有效位姿是启动证据之一（§5.2） | 无，只拖延启动 |
| `LEAVE_START` | 无 | 编码器定距直行（§6.1） | — |
| `SEARCH_CLUSTER` | 无 | 检测框水平间隙分组 + 最大团联合框（§6.2） | — |
| `CENTER_CLUSTER` | 无 | 联合框中心比例角速度锁定画面中心（§6.2） | — |
| `APPROACH_CLUSTER` | 无 | 最近 K0 地面点（机器人系）进入配置距离（§6.4） | — |
| `BREAKUP_PUSH` / `RELEASE` / `OPEN_RETREAT` / `CLOSE` | 无 | 编码器定距、定行程，`motion.cluster_breakup` 为权威（§6.4） | — |
| `RETREAT_FROM_CLUSTER` | 无 | 编码器定距倒退 | — |
| `RESET_TARGET_TRACKS` | 存在性 | 稳定帧数满足后、进入 `SCAN_GREEN` 的边界检查 pose 是否存在 | 只拖延扫描开始，不产生错误数值 |
| `SCAN_GREEN` | 存在性 + 低 | pose 存在才累计扫描跨度；用 `heading_rad` 逐周期积分到 `scan_min_heading_span_rad`（§7.1） | 跨度积分只受航向**漂移率**影响，量级小；缺失时零速等待 |
| `EVALUATE_EASY_GREEN` | 强 | `_pose_usable` σ 门限；候选代价用 `pose.position` 到预推点距离排序；σ 不合格按"无易搬运绿色"进 `PLAN_REBREAKUP`（§7.1） | 门限永久失败 → 永远走再解团（当前实测死路）；排序失真 → 选错目标 |
| `SELECT_GREEN` | 强 | `_pose_usable` 门限 + `_find_plan`（预推几何 + 走廊安全） | 方案误拒（卡流程）/ 误放行（物理不安全） |
| `PLAN_PREPUSH` | 强 | 同上 | 同上 |
| `NAVIGATE_PREPUSH` | 强 | 每周期用位姿对 `prepush_field` 做"先转向、再直行"闭环，40 mm 容差；每周期 `_find_plan` 重查走廊（§8.1） | 物理停错位置；走廊判定失真；到位判定偏移 |
| `ALIGN_GREEN` | 无 | `atan2(ground_point)` 比例转向（§8.2） | — |
| `APPROACH_GREEN` | 无 | `ground_point` 视觉伺服到接触距离，实现中显式 `del pose`（§8.2） | — |
| `ENGAGE_GREEN` | 低 | 接触几何用 `ground_point`（机器人系）；同周期 mission 重判中机器人区域守则用场系 | 接触判定本身可靠；区域守则随位姿失真 |
| `PUSH_TO_MATERIAL_ZONE` | 强（终点）/ 低（闭环） | 横向修正为视觉伺服；**终点**用 `_target_fully_entered`（`field_point` 在己方物资区内缩）判定入区（§9.2/9.3）；plan 失败回退用 pose 查走廊 | 交付终点判定偏移：提前宣布或永不完成 |
| `VERIFY_DELIVERY` | 强 | `field_point` 入区连续确认帧 + pose 存在性；生成 `DeliveryEvidence(fully_entered=True)`（§9.3 证据条件 3/4） | 伪交付或永不交付 |
| `DISENGAGE_AND_RETREAT` | 低 | 编码器退离距离 + `ground_point.x` 重新确认脱离（§9.4） | 判定本体可靠；mission 区域守则失真 |
| `UPDATE_PROGRESS` | 存在性 | 4 次有效交付 → `FINISH_STOP`；复位计数器后、下一轮扫描前查 pose | 只拖延 |
| `PLAN_REBREAKUP` | 中 | 无 pose 入参，但邻接判定用 `field_point`（§7.2） | 误判"是否需要解团" |
| `CENTER_REBREAKUP_CLUSTER` / 再解团 `APPROACH_CLUSTER` | 无 | 复用 `ClusterBreakupSequence` 视觉居中/接近（§7.2） | — |
| `TERMINAL_STOP` / `FINISH_STOP` | 无 | 零速制动与资源收尾 | — |

跨状态机制：

| 机制 | 依赖 | 位姿用途 | 位姿误差的直接后果 |
| --- | --- | --- | --- |
| `MissionStateMachine`（每周期） | 强 | 见第 4 节 | 规则判定与物理现实脱节 |
| `WorldModel` | —（注入点） | 接收 `robot_field_point`/`target_field_points`，计算 `robot_regions`、`target_region_kinds` | 一切场系派生的源头 |
| `RemoteLocalizationPublisher` / `map/state` | 无（纯输出） | pose 按 200 ms 节流发布（§3） | 不影响流程 |

## 4. 各状态具体逻辑

### 4.1 `PREFLIGHT`（存在性）

打开资源后必须同时取得：连续有效编码器/IMU 遥测、看门狗与急停证据、零速命令
接受、相机/Hailo 新鲜观测、**融合首个有效位姿**（§5.2）。位姿只作为六项启动
证据之一参与门禁，不进入任何数值计算；缺失时在约 5 秒有界窗口内重试。

### 4.2 出发与首次解团（无）

`LEAVE_START` 按初始方位直行，仅编码器路程定距（§6.1）。
`SEARCH_CLUSTER`/`CENTER_CLUSTER` 是图像空间闭环：水平间隙分组、最大团联合框
中心比例角速度居中（§6.2）。`APPROACH_CLUSTER` 用最近 K0 地面点（机器人系）
判接近距离。`BREAKUP_PUSH` 至 `RETREAT_FROM_CLUSTER` 全部是编码器定距/定行程
动作，`motion.cluster_breakup` 为权威（§6.4）。这些状态不读 pose，也不因
定位过期停在途中（§6.4："推进只依赖编码器定距"）。

### 4.3 `RESET_TARGET_TRACKS` → `SCAN_GREEN`（存在性 + 低）

`RESET_TARGET_TRACKS`（`simulation_20_point.py:958`）：碰撞后停车等待
`breakup_settle_confirm_frames` 个不重复 `frame_sequence` 的新鲜帧并显式重置
tracker；满足后状态切到 `SCAN_GREEN`，此时检查 pose：缺失则输出零速
`scan_waiting_for_field_pose`，恢复后自动开始扫描。

`SCAN_GREEN`（`:1013`）：先查 `WorldUncertainty.STALE_VISION`，再查 pose
存在，然后 `_scan_span_reached`（`:991`）用 `pose.heading_rad` 逐周期累加
`|normalize(heading − last)|`，累计达到 `scan_min_heading_span_rad`（默认 2π）
才进入 `EVALUATE_EASY_GREEN`。跨度是逐周期差分的积分，只受航向漂移率影响，
不积累绝对值误差。

### 4.4 `EVALUATE_EASY_GREEN`（强）

`_step_evaluate`（`:1057`）：

1. pose 缺失 → 保持 `candidate_selection_pose_uncertain`（零速等待恢复）；
2. `_pose_usable`（`:1957`）失败——quality 含 `STALE`、σ 缺失、或位置 σ 超过
   `max_position_uncertainty_mm`（120）、航向 σ 超过 `max_heading_uncertainty_rad`
   （0.20）——直接转 `PLAN_REBREAKUP`（`no_easy_green_pose_uncertain`）。这是
   设计文档 §7.1 明确定义的语义："若位姿存在但不确定度不合格，任何易搬运绿色
   都无法被验证，按'无易搬运绿色'直接进入 PLAN_REBREAKUP 评估"；
3. σ 合格才调 `_candidate_plans`（`:1741`）：给每个绿色目标生成搬运方案，按
   `(distance(pose.position → prepush_field), −clearance, track_id)` 排序取最近者。

后果：纯航迹推算下 σ 单调增长，evaluate 永远落在分支 2——这不是死锁，但会让
流程恒走再解团，直到次数上限后保持，最终由 15 秒无动作规则终止（2026-08-27
真车日志实测：三次 evaluate 时 σ 分别为 323/440/564 mm、0.31/0.42/0.47 rad）。

### 4.5 `SELECT_GREEN` / `PLAN_PREPUSH`（强）

两者都要求 `_pose_usable` 且每周期用 pose 重算 `_find_plan`（`:1762`）：

```text
push_direction = normalize(D − T)           # D=己方物资区入口参考点，T=目标场地点
prepush_point  = T − push_direction × prepush_offset_mm
```

随后两段走廊安全检查 `_segment_safe`（`:1863`）：按 `corridor_sample_step_mm`
步进采样，每点要求在场界内、不在对方安全区、与每个非本目标保持
`robot_footprint_radius + target_half_extent + safety_margin` 净空；任一段不安全
则方案作废。`SELECT_GREEN` 中门限失败退回 `EVALUATE_EASY_GREEN` 重选；
`PLAN_PREPUSH` 中失败零速保持 `prepush_pose_uncertain`。

推送方向完全由场系坐标决定，是位姿误差变成**物理推送方向误差**的位置。

### 4.6 `NAVIGATE_PREPUSH`（强）

`_step_navigate`（`:1166`）：每周期 `_pose_usable` + `_find_plan` 重查后：

- heading 段：`heading_error = normalize(desired_heading − pose.heading_rad)`，
  超过 `navigation_heading_tolerance_rad`（0.10）时原地转向（比例角速度，上限
  `navigation_max_angular_velocity_rad_s`）；
- straight 段：以 `navigation_speed_m_s` 前进并持续航向修正，直到
  `distance(pose.position, prepush_field) ≤ navigation_position_tolerance_mm`
  （40）→ 转 `ALIGN_GREEN`。

到达判定、航向误差和走廊安全全部由位姿驱动；位姿错 0.3 m/0.3 rad 时机器人
物理停错位置，只能靠后续视觉伺服补救（且目标必须在视野内）。§8.1 明确
"定位年龄或不确定度超过阈值立即停车"。

### 4.7 `ALIGN_GREEN` / `APPROACH_GREEN`（无）

进入目标附近后切换为纯视觉伺服（§8.2）：`_step_align`（`:1240`）用
`atan2(ground_point.y, ground_point.x)` 比例转向，容差
`navigation_heading_tolerance_rad`；`_step_approach`（`:1300`）显式 `del pose`，
以 `approach_speed_m_s` 前进并做横向角速度修正，直到
`ground_point.x ≤ engage_distance_mm`。目标新鲜度用 `target_max_age_ms` 判断，
与位姿无关。这是"绕过门限后仍能物理自愈"的核心环节。

### 4.8 `ENGAGE_GREEN`（低）

`_step_engage`（`:1374`）的接触几何 `_geometric_contact_is_valid`（`:1988`）
全部基于 `ground_point`（机器人系）：类别绿色、`CLEAR`、前方
`engage_distance_mm` 内、横向 `engage_lateral_tolerance_mm` 内、接触走廊无第二
目标。成立后创建 `TransportStatus` 并在**同一周期**让 mission 重判；mission
接受 `PUSH/DELIVER` 才输出 `GripperPosture.CLOSED` 进入推送。位姿只在 mission
重判的机器人区域守则中间接参与（见 4.12）。

### 4.9 `PUSH_TO_MATERIAL_ZONE` / `VERIFY_DELIVERY`（强于终点判定）

`_step_push`（`:1465`）的运动闭环是视觉伺服：以 `push_speed_m_s` 前进，
角速度 = `push_angular_kp × atan2(ground_point)` 限幅修正；只有
`_find_plan` 失败的回退路径才用 pose 重查走廊。但**终点判定**
`_target_fully_entered`（`:1924`）是场系判断：`target.field_point` 在己方物资
区域内缩 `delivery_inset_mm + target_half_extent_mm`（35+25）内才算完全进入。

`VERIFY_DELIVERY`（`:1533`）对 `_target_fully_entered` 连续确认
`delivery_confirm_frames` 帧，未进入则继续低速前推；确认达标且 pose 存在
（否则 `delivery_pose_missing` 保持）后生成
`DeliveryEvidence(track_ids, OWN_MATERIAL, fully_entered=True)` 提交 mission，
被接受才转 `DISENGAGE_AND_RETREAT`（§9.3 证据条件 1–6 中的定位/区域/观测新鲜
要求即落在此处）。位姿误差在这里直接变成**交付判定偏移**。

### 4.10 `DISENGAGE_AND_RETREAT` / `UPDATE_PROGRESS`（低 / 存在性）

`_step_disengage`（`:1608`）以编码器路程定退离距离，并用目标
`ground_point.x` 与 `retreat_clear_distance_mm` 的机器人系几何连续确认脱离
（§9.4："最低退离距离未达到前，动作只依赖编码器定距"）。`UPDATE_PROGRESS`
（`:1649`）在有效交付数 = 4 时进 `FINISH_STOP`，否则复位解团计数与选中目标、
重建跟踪，并在开始下一轮扫描前检查 pose 存在（`next_scan_requires_field_pose`）。

### 4.11 `PLAN_REBREAKUP` 与再解团（中 / 无）

`_step_plan_rebreakup`（`:1673`）本身无 pose 入参，但邻接判定读
`snapshot` 的场系派生量：`_rebreakup_plan_is_safe`（`:1703`）要求至少两个
具备 `field_point` 的目标、且存在一对距离 ≤
`2×target_half_extent + min_green_clearance_mm` —— 判定
"目标团仍存在可解团几何邻接"（§7.2 条件 1/2）。重复解团不检查分离进展，只受
次数上限约束（§7.2）。

随后 `CENTER_REBREAKUP_CLUSTER` → `APPROACH_CLUSTER` → 固定解团序列，全部复用
`ClusterBreakupSequence` 的视觉居中/接近与编码器定距动作，不再读位姿。位姿
误差会误判"是否需要解团"，进而影响次数上限内尝试是否被允许。

### 4.12 `MissionStateMachine`（强，跨状态）

规则机每周期消费世界快照中的场系数据，与位姿相关的主要判定：

- 机器人位置缺失：`robot_field_point is None` 或
  `WorldUncertainty.MISSING_ROBOT_FIELD_POSITION` → 保持
  `robot_field_position_missing`（`state_machine.py:441-446`）；
- 机器人在对方安全区 → `AVOIDING` 避让（`:459`）；
- 机器人在对手占用区内 → `AVOIDING`（`:461-468`）；
- 运送中机器人在己方物资/伤员区 → 转 `VERIFYING_DELIVERY` 并允许 `DELIVER`
  （`:506-519`）；
- 候选排除 `_target_is_in_excluded_area`（`:792`）：已在自己物资/伤员区或对方
  安全区的目标不参与候选——区域成员判断用 `field_point`；
- `_process_delivery`（`:643`）：首交付必须是单个绿且 `fully_entered`（否则
  终止 `INVALID_FIRST_DELIVERY`）、交付计数、错区/越界计数；`fully_entered`
  由应用侧场系判定产生；
- 危险目标 + 交付证据 destination 为越界/进安全区 → 终止
  `DANGER_OUT_OF_FIELD` / `DANGER_IN_SAFE_ZONE`（`:380-403`）。

即规则机用位姿同时守"机器人在哪"与"目标在哪"两类区域守则；位姿失真时规则
判定与物理现实脱节（可能物理已违规而系统未察觉，或系统误停）。

### 4.13 对外输出（无）

`RemoteLocalizationPublisher`（`cluster_breakup.py:672`）与
`_publish_remote_simulation_state` 把位姿按 200 ms 节流发布到 `map/state`，
位姿不可用时发布 `robot_localized=false`（§3、§5.4）。纯输出，不参与任何
运动或规则判定。

## 5. 结论

- **完全不受位姿误差影响的环节**：出发/首次解团/再解团的定距动作、
  `SEARCH/CENTER/APPROACH_CLUSTER`、`ALIGN_GREEN`、`APPROACH_GREEN`、
  `ENGAGE_GREEN` 的接触几何、`PUSH` 的横向修正、`DISENGAGE` 的退离判定。
  这些环节占搬运近场闭环的大部分，也是纯航迹推算下流程仍能物理自愈的基础。
- **位姿误差 1:1 进入结果的环节**：`EVALUATE` 的 σ 门限与候选排序、
  `SELECT/PLAN_PREPUSH/NAVIGATE` 的预推几何与走廊安全、`PUSH/VERIFY` 的交付
  终点判定、mission 的机器人/目标区域守则。
- **位姿经相对几何间接参与的环节**：`PLAN_REBREAKUP` 的邻接判定（目标间相对
  距离，平移误差抵消、短距离下航向误差影响小）。
- **只受存在性与精度影响的环节**：`PREFLIGHT`、`RESET_TARGET_TRACKS`、
  `SCAN_GREEN`（跨度积分）、`UPDATE_PROGRESS`。
- 设计文档 §7.1 明确要求"候选选择和导航仍必须有新鲜且不确定度合格的全局位姿，
  不得从编码器路程或旧画面伪造"，§8.1 要求"定位年龄或不确定度超过阈值立即
  停车"。**绕过或放宽 `max_position_uncertainty_mm`/`max_heading_uncertainty_rad`
  是对这两条设计定义的偏离**，按设计文档 §15 的口径应先更新设计文档再修改
  实现，且只能作为低速、有人值守的流程联调手段，不作为比赛配置。
